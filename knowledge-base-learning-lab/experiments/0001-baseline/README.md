# Experiment 0001：透明关键词检索基线

## 目的

在加入 SQLite、Embedding 或向量数据库之前，理解一次检索为什么命中、排序或漏召回。

## 测试材料

| 资源 | 主题 | 关键事实 | 与其他资源容易混淆的点 |
| --- | --- | --- | --- |
| 资源 A：差旅报销规则 | 差旅费用与提交期限 | 高铁二等座、经济舱机票可报销；住宿超标需部门负责人审批；十个工作日内交材料 | “申请”“报销”会与远程办公补贴产生词面重叠 |
| 资源 B：远程办公支持 | 网络补贴与设备借用 | 每月一次、一百元网络补贴；需运营商账单和直属经理确认；显示器不可报销 | “申请”“确认”会与差旅审批产生词面重叠 |
| 资源 C：知识库访问规范 | 权限过滤、证据与长期记忆 | 先按用户和项目过滤；证据应可定位；未审核会话观察不可写入长期记忆 | “知识库”“证据”与内置种子材料产生词面重叠 |

## 问题与预期证据

| 问题 | 预期资源 | 预期事实/段落 | 关键词问法还是语义改写 |
| --- | --- | --- | --- |
| Q1：住宿超标时谁需要审批？ | 资源 A | 部门负责人审批 | 改写 |
| Q2：怎样申请网络费用补助？ | 资源 B | 每月一次、一百元；账单与直属经理确认 | 改写 |
| Q3：没有审核的聊天内容能直接变成长期记忆吗？ | 资源 C | 不能；会话观察须经审核 | 改写 |
| Q4：飞机票和高铁票哪些可以报销？ | 资源 A | 经济舱机票与高铁二等座 | 近似关键词 |
| Q5：差旅结束后多久交材料？ | 资源 A | 十个工作日内 | 改写 |

## 实际结果

| 问题 | Top 1 | 正确证据是否进入 Top 5 | 命中层级 | 观察到的原因 |
| --- | --- | --- | --- | --- |
| Q1 | 资源 A / L1 / 4.50 | 是 | L1（L2 排第 2） | “住宿”“审批”等二元词命中；L1 对 L2 有目录分数加成 |
| Q2 | 资源 B / L0 与 L1 / 3.00（并列） | 是 | L0/L1 | “申请”“网络”命中；L0 只含首句，不能独自支持完整流程回答 |
| Q3 | 资源 C / L1 / 10.50 | 是 | L1（L2 排第 2） | “审核”“长期记忆”等原词高度重叠，是词面强命中 |
| Q4 | 资源 A / L1 / 9.00 | 是 | L1（L2 排第 2） | “机票”“高铁”“报销”近似原文，词面强命中 |
| Q5 | 资源 A / L1 / 4.50 | 是 | L1（L2 排第 2） | “差旅”“结束”有重叠，但“多久”不是原文“十个工作日”，存在改写脆弱性 |

## 复盘问题

1. 哪个问题因为包含原文关键词而命中？
2. 哪个问题表达了相同语义，却因措辞不同而漏召回？
3. L1 概览是否帮助系统选对资源？
4. Top 1 错误是召回失败、排序失败，还是内容切分失败？
5. 下一次实验只改变哪个变量？为什么？

## 本轮执行记录（Stage 0）

- 执行方式：本地内存服务；未使用真实公司代码、用户数据、外部模型或密钥。服务已在实验后关闭，因此这些资源和任务不会保留。
- 观察到的状态流：`POST /api/resources` 返回 `queued`；后台任务依次经历 `parse → summarize → index → done`；约 0.7 秒后资源为 `ready`、任务为 `completed`。
- 透明评分：先用 L1 概览计算资源分数；资源内节点的分数为词面命中数，加上目录分数（L2 加 25%，L0/L1 加 50%）。所以 L1 容易排在 L2 前，即使真正可引用的原文在 L2。
- 结论：本轮五题的正确资源均进入 Top 5，但这只是中文短语与二元词重叠的结果，不能说明系统具备语义检索能力。下一轮若继续基线实验，应只替换问题措辞，不改变切分或评分算法，以量化漏召回。

## 本实验禁止改变的变量

- 不加入 Embedding。
- 不同时改变切分和评分算法。
- 不用模型生成答案掩盖检索错误。
- 不根据单个问题宣布算法更好。
