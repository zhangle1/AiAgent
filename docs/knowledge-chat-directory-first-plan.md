# 聊天知识库轻量方案：服务器目录直读与 KnowAgent 模式切换

日期：2026-11-05。状态：方案建议，尚未实现。

本方案按最新需求收敛聊天链路，取代[上一版协同设计](knowledge-agent-codex-workspace-design.md)中聊天端较重的映射展示、多入口操作和发布流程建议。知识中心自身的 Agent、解析与语义能力继续独立完善。

## 1. 核心决定

**把知识中心的知识文件视为可用 Git 管理的文件工作区。聊天默认不选知识；需要时在左下角「知识库」弹窗中勾选目录，发送问题后，Codex 结合当前代码仓库自行检索这些目录。**

先交付目录直读。后续在同一个弹窗增加「Codex 直接读取 / KnowAgent 接口」切换，目录选择和普通聊天操作保持一致。

这里有三个独立概念：

| 概念 | 职责 |
| --- | --- |
| 知识文件工作区 | 存放当前可读的原件、Markdown 和已有派生知识 |
| Git | 保存版本、比较变化、拉取和推送；同步状态决定是否跟上远端 |
| 读取模式 | 决定 Codex 直接查文件，还是通过 KnowAgent 的受控接口获取知识 |

Git 仓库可以先在服务器本地建立，远端同步后接；目录直读本身不必等待远端仓库配置完成。Git 也不会自动保证“最新”，仍需要明确的更新动作和同步结果。

## 2. 用户实际怎么用

1. 打开项目聊天，左下角显示「知识库」，默认没有选择。
2. 点击后打开树状弹窗：知识中心 → 已授权知识目录 → 子目录／文件。
3. 勾选需要的范围并确认；父目录代表其可访问子树，父子重复选择去重。
4. 入口变为「知识库 · 2 项」。正常输入并发送问题。
5. Codex 在当前项目代码与所选知识目录中按问题查找，再回答并标注来源。

点击箭头展开，点击复选框选择；弹窗支持搜索、清空、取消和确认。取消保留原选择。首版不增加独立启用开关、关联按钮或“交给 Codex”步骤。

切换项目或会话清空当前输入框选择，取消旧请求，防止旧响应带回旧目录。历史消息保留当轮选择记录；继续聊天要重新确认范围。

后续模式入口放在这个弹窗内：

```text
知识库
读取方式： (●) Codex 直接读取  (○) KnowAgent 接口

搜索目录……
☑ 产品资料
  ☑ 订单系统
  ☐ 财务系统
☐ 公共规范

已选 1 个目录                     清空  取消  确认
```

首版只展示目录选择即可，待接口模式可用后再显示切换项。上图为后续布局示意，父子勾选按实际包含关系展示。

## 3. 首版读取链路

```text
左下角知识库树勾选
        ↓
聊天请求携带目录标识
        ↓
后端按当前身份解析并校验实际目录
        ↓
将目录接入 Codex 运行环境，并提供简短范围说明
        ↓
Codex 按需列目录、搜索、读取文件
        ↓
结合当前项目代码回答，引用知识文件和代码位置
```

**当前项目仍是 Codex 的工作目录，知识目录作为附加查阅范围。** 不因勾选知识而切换代码项目，也不把所有知识正文预先拼进提示词。

例如用户问：“结合订单资料，检查现在的退款实现有哪些遗漏。”Codex 可以先搜索知识目录中的退款规则，再阅读项目退款代码，对照后给出文件位置和差异。无需先调用知识编译、生成 L0/L1 或建设向量索引。

后端提供的简短说明包括：知识范围名称、运行环境中的可读位置、直接读取模式、可用版本信息，以及优先查阅相关文件、引用实际读取内容的要求。目录名和文件内容作为参考数据处理。

## 4. 如何把整个知识中心看成文件仓库

“整个知识中心”是统一的文件管理视角，不代表所有用户共享一个包含全部个人数据的物理 Git 仓库。

先建立一个受控的知识文件工作区，将允许导出的知识内容完整落地。管理员可以管理公共知识仓库；个人资料、个人 Wiki 和摘要按归属分开存放并授权。聊天树只展示当前用户可访问且已映射的范围。

示意布局如下，并非现有磁盘布局：

```text
knowledge-workspace/
  sources/       原始文件与可直接阅读的 Markdown
  readable/      已有解析正文，保留与原件的映射
  wiki/          已有 Wiki 内容
  summaries/     已有摘要
  manifests/     来源标识、相对路径、内容哈希、派生版本
```

原件完整保存；已有解析正文可以一起导出，缺少解析不阻断其他文件的直读。派生文件记录来源哈希，过期时明确标记，避免旧摘要被当成当前原文。

现有知识树由数据库与文件共同投影，所以第一次导出需要按资源可见性和存储契约整理，不能把整个运行数据目录直接加入 Git。具体导出范围沿用[Git 工作区优先方案](knowledge-git-workspace-first-proposal.md)。

首版明确采用“导出／刷新形成的查阅工作区”：现有知识中心继续保存上传与解析结果，刷新工作区后供 Codex 阅读。Git 保存这个工作区的版本。Codex 不在聊天查阅时直接改动这些镜像文件，避免与知识中心刷新互相覆盖。

将来需要让 Git 原文正式接管上传和编辑时，再单独迁移写入入口；这不是本轮目录查阅的前置条件。

## 5. “最新”以什么为准

首版读取服务器工作区当前内容，可以包含尚未提交的更新，因此界面和回答不能只用 HEAD 声称内容版本。

| 状态 | 表达 |
| --- | --- |
| 工作区完成刷新 | 可读取本次刷新后的知识文件，显示刷新时间或版本 |
| 存在未提交改动 | 当前读取包含本地更新，HEAD 仅作为基线 |
| 与远端完成同步 | 记录同步成功时间和当时的远端提交 |
| 远端检查失败或未检查 | 远端是否更新未知，不能标成“已是最新” |
| 知识中心有新上传但未刷新 | 提示查阅副本待刷新，不能声称已经读到新上传 |

聊天发送不自动执行 pull、merge 或 push。知识工作区提供手动刷新／同步即可；冲突保留并明确报错。Git 维护可后续复用已有权限和变更集交付流程，查询本身不触发提交。

首版无需为每轮复制整仓快照，但应记录所读文件的相对路径与内容哈希；文件读取中变化时重新读取或提示变化。这样接受实时工作区的轻量实现，也不把一轮问答描述为严格固定快照。

## 6. 后续两种模式如何切换

| 项目 | Codex 直接读取 | KnowAgent 接口 |
| --- | --- | --- |
| 适用场景 | 先跑通文件检索、结合代码调试、探索知识内容 | 利用目录语义、解析正文、证据和知识状态 |
| 读取入口 | 运行端可访问的知识文件目录 | 经授权的知识工具／接口适配层 |
| 查阅策略 | Codex 自主决定搜索和阅读步骤 | Codex 调用接口获取目录、正文、搜索与状态 |
| 解析方式 | 使用运行环境已有能力，必要时由 Codex 组织解析 | 复用知识中心既有解析与 KnowAgent 能力 |
| 知识选择 | 同一组逻辑目录标识 | 同一组逻辑目录标识 |
| 项目代码 | Codex 继续读取当前代码工作区 | Codex 继续读取当前代码工作区 |

“Codex 自己解析”不意味着所有 PDF、Office、扫描件都天然可读。首版优先 Markdown／文本和已有解析正文；缺少工具或正文时明确说明无法读取哪些文件，不以文件名推测内容，也不自动创建后台编译任务。

接口模式优先让 Codex 使用 `ls/read/search/status` 一类确定性工具。KnowAgent 自身的规划、摘要导航、证据核验可以继续优化；需要其完整问答能力时，另加显式查询工具，返回答案同时保留原始证据入口，控制额外模型调用。

该模式需要实际接通 Codex 工具桥接，例如受控 MCP 或现有工具适配机制，实施时验证支持情况。仅把 HTTP 地址写进提示词不算完成接口接入；不把用户令牌、平台密钥交给模型。

模式按每条消息保存。从下一轮起生效，已发消息不改变。切换读取方式或取消目录后，旧会话上下文中可能仍有此前读到的内容；若要求严格隔离，必须开启新的底层执行会话或重建干净上下文，不能只更新提示词。

接口失败要明确报错，由用户选择是否改用直读；不静默切换模式。两种模式共享来源标识、相对路径和版本信息，方便比较检索效果。

## 7. 最小技术改动

以下字段和服务名称均为建议，尚未存在于当前请求契约。

前端仅增加可选知识选择字段：

```json
{
  "knowledge_context": {
    "mode": "filesystem",
    "scope_ids": ["scope-order-docs"]
  }
}
```

后续 `mode` 增加 `knowagent`。`scope_ids` 代表已登记的目录或文件节点，浏览器不提交任意服务器绝对路径。旧客户端不传此字段，维持原聊天行为。

后端新增轻量目录解析服务，负责按用户身份将节点映射到实际路径、去重、检查目录存在和运行端可读，并构建当轮知识上下文。HTTP 与 WebSocket 共用解析逻辑，客户端 API 和类型同步更新。

当轮消息元数据保存模式、目录标识、显示名称、工作区版本／刷新状态和实际引用。服务器真实路径只用于内部运行配置，历史展示与导出使用逻辑标识和相对路径。

当前代码中可复用的位置：

| 已核对入口 | 接入方向 |
| --- | --- |
| `backed/Services/Chat/Codex/CodexChatService.cs` | 已有工作区配置和服务端引用上下文拼装；新增知识范围及实际运行端访问配置 |
| `backed/Services/Chat/ProjectReferenceContextService.cs` | 参考其服务端身份校验与引用解析方式 |
| `backed/Services/Knowledge/KnowAgent/KnowledgeAgentTools.cs` | 已有选定范围内 `ls/read/search/status`，后续用于接口适配 |

这些已有入口不代表“目录选择 → Codex 文件访问”已经接通。

## 8. 轻量实现仍要落实的目录边界

服务器上存在目录，不代表 Codex 所在容器、远程 Worker 或运行账号能读取。接入时必须验证运行端可见性，必要时提供受控挂载或只读投影；不可达时明确提示。

首版知识范围只读，项目代码保持既有权限。路径规范化并验证授权根目录，拒绝符号链接／Windows junction 逃逸；Git 凭据、配置密钥和无关个人目录不进入可读范围。

只在提示词中写“请仅访问这些目录”不能形成权限隔离。多用户部署必须由运行隔离、文件系统权限或受控只读投影落实范围；若当前运行通道只有宽泛的全盘访问，不能宣称树勾选限制了实际权限。

每轮重新校验权限。撤权、缩小范围或切换身份后，旧执行会话不得继续持有原范围访问能力；已进入历史的文字不会因撤权自动消失，历史展示遵循既有会话权限。

## 9. 实施顺序与验收

**第一步：整理可读文件工作区。** 完整导出授权知识，保留原件和已有正文，建立来源映射；确认上传后的刷新路径。准备本地 Git，远端同步可独立配置。

**第二步：完成聊天目录直读。** 复用左下角入口、默认不选、树勾选、后端解析、运行端只读接入、结合代码回答并引用。到这里就是首版交付范围。

**第三步：增加模式切换。** 同一选择器接入 KnowAgent 工具桥接，继续完善知识 Agent 的检索、语义和证据能力。

**第四步：按需求扩展维护。** 再考虑 Git 写入接管、增量同步、知识整理与审核发布，不阻塞首版问答。

使用合成知识文件与临时项目验证：

1. 不选知识时维持现有聊天；选目录后，Codex 能实际读取其中内容并对照项目代码。
2. 父子范围去重，跨用户目录、路径穿越及链接逃逸被实际访问边界阻断。
3. 更新文件并刷新后，下一轮读到新正文；未刷新、未同步和远端未知状态正确展示。
4. 不支持的二进制文件、无权限和目录不可达明确报告，不伪造检索结果。
5. 项目／会话切换、取消、权限变化和自动重试不混入另一轮选择；重试复用原请求范围与模式，并重新校验权限。
6. 后续切换模式时，所选逻辑范围一致，调用链与引用可核对；接口失败不自动改走目录。

本次仅形成方案文档，不修改业务代码，不操作真实知识文件或远端 Git。
