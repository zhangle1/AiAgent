# 可信工作区与 SSH 无感使用方案

日期：2026-09-17。本文为实现方案；下文规划能力尚未接入当前 client。

## 1. 用户最终看到什么

左侧选择项目工作区，右侧聊天内容流式输出，底部输入任务。工作区可以是本地文件夹，也可以是管理员配置的远程环境。

```text
项目工作区                  当前项目 / 只读分析
  本机 · 订单系统           你：检查登录失败的原因
  远程 · 测试环境           AI：正在查找登录入口…
                           已读取 src/auth.ts
                           发现问题与修改建议…
                           [输入任务]       [发送 / 停止]
```

用户授权项目后，可以要求 AI 自己查找相关文件，不必逐个选择文件。AI 应按需读取，并显示访问了哪些文件；授权不代表将整个目录上传。进入修改阶段后，聊天中展示具体 diff 和执行结果。

SSH 的主机、端口、账号、指纹与认证配置放在工作区管理中。普通使用者只选择有权限的环境，无需每次填写 SSH 表单；界面仍显示正在操作本机还是远程环境。

当前检查的是 `D:/AiAgent/Project/AIAGENT/ai-agents`，用户提及的 E 盘旧目录状态不能据此推断。

## 3. 可信目录如何驱动 AI

将本机浏览授权与 AI 使用授权分开：选择文件夹后，明确启用“允许 AI 按需读取并向平台发送项目文本”。读取范围为该工作区，排除敏感文件，并提供随时撤销入口。

流程：

1. 用户选择目录并授予当前工作区的 AI 只读权限。
2. 客户端绑定不透明 workspaceId、授权版本和当前任务。
3. 模型产生结构化的 list/read/search 请求，参数仅含根内相对路径。
4. 桌面主进程验证工具、参数、授权版本、路径和预算，执行本地读取。
5. 仅把有限结果送回平台，同时在聊天中展示文件访问记录。
6. 模型根据结果继续分析，直到完成、取消或达到预算。

每次调用都重新检查授权。切换项目、撤销授权、退出登录应取消当前任务，并丢弃旧任务迟到的结果；界面禁用按钮不能代替主进程检查。

首版工具限定为 list/read/search，限制文件数量、单文件大小、总返回字节、轮次与耗时。不要把模型回复中的代码块当作可执行工具请求。

对于当前模型入口，有两个独立实施路径：

- **平台模型工具循环**：使用支持工具调用的模型，通过已有插件 chat/completions 流式接口返回工具请求，在 client 主进程编排和执行。需要补齐工具参数拼接、schema 校验、结果回传和取消测试。
- **继续使用远程 Codex**：需要先新增真实的客户端工具请求与结果桥接，再绑定到 Codex 运行。现有 delegate 的文本增量协议本身不提供这个能力，不能把“流式聊天已通”等同于“本地 Agent 已通”。

仅桌面发起的本地工具循环不一定需要先建设设备配对与 WSS；如果要从浏览器遥控本机，才需要设备身份、出站连接、权限映射与断线恢复。

## 4. 从分析扩展到修改

| 权限 | 允许行为 |
| --- | --- |
| 只读分析 | 在授权根内列目录、搜索、读取有限文本 |
| 审阅后修改 | 生成具体补丁，用户确认后写入对应文件 |
| 受控执行 | 额外授权指定的构建、测试等命令 |

补丁批准应绑定任务、工作区、授权版本、文件原始哈希和补丁哈希。执行前重新核对，文件已改变则重新生成并审阅；写入用临时文件和原子替换。

文件目录授权无法单独限制任意程序：把进程 cwd 设为项目目录，不代表程序不能访问其他目录。命令执行需要独立的操作系统隔离或受限执行器，不能直接把现有人工 PTY 交给 AI。人工终端输出继续仅在用户明确分享时进入模型。

## 5. SSH 如何变成工作区能力

| 网络情况 | 连接执行位置 | 普通用户体验 |
| --- | --- | --- |
| 平台能访问目标服务器 | 平台侧连接服务或受控执行节点 | 选择“测试环境”后直接工作 |
| 只有用户电脑能访问目标 | 本机客户端 | 相同的工作区体验，客户端需在线 |
| 需要无人值守，用户电脑可能离线 | 目标网络内常驻执行节点 | 由在线节点处理任务 |

平台管理工作区名称、访问成员、执行位置、远程允许目录和权限。连接参数与主机指纹由管理员维护；凭据进入执行侧的安全存储，平台业务数据库只保存引用。平台执行模式需要专门的服务端凭据方案，不能沿用“所有 SSH 凭据始终只在客户端”的旧假设。

隐藏 SSH 表单不会消除首次配置：仍须有人核实目标主机身份并配置认证。指纹变更时连接失败并交由管理员处理，不能为无感体验自动接受新指纹。凭据无需交给模型或普通用户界面。

本地文件和远程文件使用统一的工具接口，但各自实现路径校验。远程文件工具可走受限 SFTP；远程命令需要受控执行器，不能认为 SSH exec 天然提供安全的参数数组或目录沙箱。

## 6. 建议实施顺序与验收

1. **完成当前聊天界面与流式链路验收**：后端编译、真实聊天取消和错误处理，以及 Electron 中滚动、输入、项目切换测试。
2. **可信目录只读 Agent**：增加授权提示、list/read/search 工具循环和访问记录。验收无需手选文件即可分析项目，越界和撤销后访问均被拒绝。
3. **文件修改**：接入 diff、一次性批准、哈希冲突检测和原子写入。验收未经批准不落盘，过期补丁不能覆盖用户修改。
4. **托管远程工作区**：按实际网络选择平台执行或客户端执行，配置权限、凭据与指纹。验收普通用户只选择环境，模型无法取得凭据，其他用户不能借用目标。
5. **浏览器调度与无人值守**：补齐配对、WSS、幂等和审计。验收断线不重复写入，设备撤销立即阻止新任务。

本方案补充 [终端与远程主机访问架构](agent-terminal-and-remote-host-access-plan.md)。其中平台执行模式是新增设计方向，不代表原架构中的客户端 SSH 已迁移到服务端。
