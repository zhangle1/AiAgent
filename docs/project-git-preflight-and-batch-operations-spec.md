# 项目 Git 状态前置检查与批量操作规格

## 目标与范围

聊天中选中代码项目后，`项目程序运行`成为该项目 Git 健康状态的总入口。项目范围仅包含数据库已登记且归属该项目的代码库；不接受浏览器路径，也不扫描未登记目录。每次项目检查在计算 ahead/behind 前都执行 `git fetch --quiet --prune`，避免用本地远端引用做出“已同步”判断。

本期保留单仓库的运行、打包、差异、重置更新、提交推送能力；面板移除“启动全部已配置程序”，新增项目级批量重置更新与批量提交推送。

## 状态模型

项目级 API 返回每个已登记代码库的 Git 检查结果及汇总状态：

| 汇总状态 | 条件 | 顶部入口 |
| --- | --- | --- |
| `checking` | 前端请求尚未完成 | 中性外观、按钮内旋转图标与“正在检查”提示 |
| `synced` | 至少一个 Git 仓库，全部刷新成功、均有上游且 `behind=0` | 绿色，提示“所有代码库已同步” |
| `attention` | 任一刷新/检查失败、未设置远端或上游、或 `behind>0` | 黄色，列出需处理数量与原因 |
| `neutral` | 未选项目、项目没有已登记代码库，或没有 Git 仓库 | 中性，说明没有可检查的 Git 仓库 |

仓库行状态可为 `synced`、`behind`、`no-upstream`、`not-repository`、`failed`。远端刷新失败即为 `failed`，即使本地缓存可计算出数字也不能标为已同步。

## API

所有接口沿用 `/api/v1/code-repositories` 认证和项目访问控制：

- `GET projects/{projectId}/git/status`：刷新项目内每个 Git 仓库远端引用后返回项目汇总及逐仓库状态。
- `POST projects/{projectId}/git/discard-and-pull`：对请求指定的仓库（缺省为全部 Git 仓库）依次执行既有“重置更新”。返回逐仓库结果；单个失败不回滚已完成仓库。
- `POST projects/{projectId}/git/commit-and-push`：先刷新并重新判断每个目标仓库；`behind>0`、无上游、刷新失败或非 Git 仓库均明确跳过。其余仓库使用同一提交信息执行既有提交推送，并返回逐仓库结果。

批量响应不包含访问令牌。Git 子进程输出会清理当前凭据和 URL 中的嵌入式密码后才返回客户端。

## 幂等、并发与失败语义

每个代码库继续使用既有 Git 操作通道串行化；同一项目的批量操作另有项目级通道，重复点击会按顺序执行，不会并发丢弃或提交同一工作区。前端在检查或批量操作期间禁用相应操作、关闭弹窗的提交按钮，并保留取消（取消仅在操作开始前有效）。

批量重置更新是破坏性操作：确认弹窗必须列出目标仓库、未提交变更数、远端领先数及风险；确认前不调用写接口。执行 `reset --hard HEAD` 后仅使用 `pull --ff-only`，不会删除未跟踪文件，无法快进或认证失败按仓库报告失败。

批量提交推送不尝试合并或自动拉取。其确认弹窗复用现有 Conventional Commit 输入形式，统一提交信息。操作时再次检查远端，落后仓库一律跳过并提示先执行“一键重置更新”。部分成功是预期结果，逐仓库显示成功、跳过或失败，并在结束后重新检查。

## UI 与移动端

顶部按钮在项目改变后和打开面板时自动检查，也可以手动刷新。按钮用颜色之外的文字提示表达状态，并携带无障碍标签。面板顶部显示项目级摘要和批量操作；窄屏仍以底部 sheet 展示，批量按钮纵向全宽，确认对话框使用底部可滚动布局，长仓库名与错误可换行。

无项目、无仓库、无 Git 仓库、无远端/无上游、检查失败、操作中、取消和部分失败均有可理解的文案；单仓库动作维持原行为。

## 验收案例

1. 选中有两个 Git 仓库的项目，服务端每次检查均先 fetch；任一仓库远端新增提交后，顶部转黄并显示待更新数量。
2. 所有仓库 fetch 成功、有上游且 `behind=0`，顶部为绿色；无项目或没有 Git 仓库时为中性。
3. 任一 fetch、路径或 Git 检查失败，顶部为黄色且仓库行给出失败原因；响应和日志不出现 token。
4. 点击一键重置更新先出现风险与仓库列表；取消不触发请求；确认后逐仓库显示结果，未跟踪文件不在操作承诺范围内，结束自动重新检查。
5. 批量提交推送使用一个提交信息；落后仓库被跳过并提示先重置更新，其他仓库继续执行并逐项报告。
6. 重复点击、网络慢和移动端窄屏时不会重复并行发起批量操作，按钮和对话框状态仍可理解。
