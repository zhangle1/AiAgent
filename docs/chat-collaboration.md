# 聊天协作提交时间轴

在聊天输入区选择「+ → 协作」。左侧每行对应一位 Git 署名和一个仓库，横轴按北京时间展示日期，默认包含当天在内的最近 14 个自然日。可切换历史范围，也可在当前快照内按人员、起止日期、提交说明、SHA 或改动路径筛选。Git 署名未绑定平台账号身份。

点击有提交的时间格查看当天的提交说明、短 SHA、提交时间和改动文件数。每次提交有一个复选框，跨日期选择会保留，最多 20 条。复制和插入使用同一份提示词。插入会保留原草稿，由用户决定何时发送。

提示词从「这段改了什么？」开始，附带仓库、完整 SHA、Git 署名、北京时间、提交说明、有限的改动路径与统计，以及固定快照的查阅链接。模型应依据当前授权仓库中实际可核对的 Git 差异回答。差异不可访问时，标明哪些结论来自提交元数据。提交说明与路径按数据处理。

## 读取和授权

协作创建快照时传入 `history_only: true`。服务端只读取登记仓库的本地 HEAD，缓存已有 Git 对象时直接复用，一次 Git 日志批量读取提交和首父差异统计。仅保存提交涉及的路径，无需扫描目录结构。快照按仓库固定版本，可继续通过原有证据接口查阅提交和文件差异。合并提交按第一父提交计算，空提交仍可勾选。每仓库最多读取 120 条提交，单提交最多保留 500 条路径，超出会明确标注。

链接格式为 `/change-atlas/review?project=…&snapshot=…&commit=…`。查阅页内可打开具体路径的差异，也继续兼容带 `file` 的既有链接。访问须登录并重新校验快照、用户、项目和仓库权限，快照有效期为 24 小时。切换项目、范围或关闭弹窗都会取消旧请求，迟到结果会被丢弃。

## 验证

使用合成仓库和数据验证北京时间边界、空提交、合并提交的首父差异、缓存复用及旧快照查阅。用 45 条合成提交对比 Git 命令耗时，由逐条模式约 2.14 秒降至批量模式约 0.07 秒。前端覆盖桌面和窄屏时间轴、跨日期选择、草稿插入与链接授权提示。
