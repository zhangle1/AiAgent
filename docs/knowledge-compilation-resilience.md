# 知识提炼两阶段与队列故障隔离

2026-09-18

## 问题与修复

2026-09-24 现场再次出现 SQL Server `ExecuteReader 要求打开可用的 Connection`。本次根因是后台提炼在 `await` 模型调用期间仍持有 SqlSugar 客户端：提炼服务、队列进度回调和 Wiki 目录读取都可能让一个连接跨越长耗时异步边界。现在改为“数据库操作即开即关”：每次状态更新、校验、进度写回和 Wiki 目录读取使用独立 `CopyNew()` 客户端，模型调用期间不再持有数据库连接。这样页面切换、模型重试或并发状态查询不会复用处于错误状态的连接。

截图中的错误出现在提炼阶段的数据库读取路径；旧实现让多个查询和长耗时任务共享同一个 SqlSugar 客户端，具体堆栈可能落在状态更新、Wiki 上下文读取或进度回写。原实现将部分数据库更新放在任务异常捕获边界之外；失败回写也没有二次隔离。后台服务异常退出可能触发宿主停止，造成其他接口一起不可用。临时 SQLite 数据库的故障触发器已复现“首任务开始失败，后续任务不再执行”；这不是对现场 SQL Server 连接异常原因的完整复现。

队列各操作、提炼处理、内容读取和设置读写使用独立 SqlSugar 客户端，避免异步后台路径复用请求连接。每个任务的初始化、进度、模型调用和终态更新均被隔离。终态写库失败时保留内存终态，查询、列队和重新提交时尝试补写；成功产物不会因队列状态更新失败而被改报失败。进程重启仍将数据库中的未完成任务标记为中断，不自动重跑模型。

原文保持不变，草稿和文档成功状态在同一短事务内提交。失败重提炼不覆盖前次草稿，也不改变 RAG 活动版本。数据库整体不可用时，依赖数据库的接口仍可能报错；本次保证的是任务异常不会退出整个宿主，并隔离任务与请求的连接生命周期。

## 两阶段策略

参考本地 `llm_wiki/src/lib/ingest.ts` 的 Analysis / Generation 调用顺序，不移植其桌面文件写入模型。

1. **Analysis**：按最多 16000 字符分段，读取完整原文及本库已有知识页标题、审核状态，分析实体、概念、关系、矛盾和不确定性。所有段先完成分析。
2. **Generation**：将当前段完整原文、该段分析、其他段分析预览与已有标题交给模型，输出结构化知识页。分析不是事实证据；每页必须引用当前段原文并通过逐字匹配。全部段通过后，宿主才保存草稿。

单段正常两次调用，不再花费模型调用来请求读取原文或宣布结束。最多 256000 字符，不截断原文；调用预算不足以覆盖全部两阶段时，在模型调用前拒绝。每段生成最多三次，修正仍保留原文和分析，且为后续分段预留调用预算。空分析、超长输出、虚构引用和重复标题均拒绝。真实进度分别来自分析完成段数和生成证据覆盖段数。

本轮接入现有 Wiki 标题目录，并非完整移植 llm_wiki 的 purpose/schema 配置、长文检查点、缓存与自动合并；跨文档关系仍是待审核的模型建议。

## 模型链路检测说明

模型服务页的基础诊断使用 `stream=false` 普通 JSON 响应，而知识提炼的 `CompleteAsync` 也必须走同一条非流式协议。此前该方法误复用了 SSE 流式实现，部分兼容接口虽然普通请求成功，但不会返回可解析的 `data:` 事件，因而被链路检测误判为空响应。现已将非流式调用改为直接解析 `choices[0].message.content`（兼容 `reasoning_content`），流式聊天仍保留原有 SSE 路径。

聊天框与知识提炼是两种不同智能体：聊天框走 `ChatOrchestrator → AgentLoop`，需要流式输出、思考标签和工具调用；知识提炼走 `KnowledgeChainDiagnosticsService → KnowledgeCompiler`，需要多轮非流式调用、严格 JSON 页面和原文证据校验。两者共享模型配置和底层 HTTP 客户端，但不共享输出协议。链路检测现在会把“模型可连接但输出不符合知识编译契约”作为结构化失败结果返回，不再直接抛出 500。

运行 `dotnet test backed.tests --no-restore --filter "FullyQualifiedName~Knowledge" --verbosity quiet`。

覆盖任务开始写库失败、错误终态写库失败、成功终态补写、后续任务可执行、知识库读操作、取消与成功竞态、两阶段调用顺序、完整分段证据、有限修正、预算预检、保存失败回滚及保留旧草稿。

测试使用临时数据库和伪模型，不连接用户数据库或消耗真实模型额度。部署后仍需用现场 SQL Server 和实际 Codex/API 模型执行一次提炼验收。
