# 聊天知识目录 Scope

## 目的

把知识库中的一个或多个资源文件夹或具体原始文件作为聊天本轮的可选检索范围，支持书籍、规范、Wiki、示例资料等增量补充。Scope 是目录／文件范围，书籍只是其中一类资源，也不替代现有知识库名称。

## 兼容边界

- `knowledge_scope_uris` 为空：沿用原有知识库全范围检索。
- `agent=codex`：聊天编排器仍优先进入现有 Codex CLI 分支，Scope 不参与 CLI 参数、工作区或工具权限决策。
- 非 Codex 知识检索按所选范围过滤 Wiki 页的来源文档或 RAG chunk 的 `document_id`。
- Scope 解析失败或目录无权访问时，本轮返回明确错误，不扩大到全库检索。
- 代码修改、补丁应用、测试运行、提交和推送继续使用原有显式流程。

## Codex 聊天如何使用勾选的书

选择「解析正文 → 书名」可让本轮 Codex 翻阅整本书。选择其中的子目录时，只提供该子目录下的 Markdown 正文和目录索引。选择原始 PDF 等文件时，宿主按文件的来源 URI 找到最新发布的解析章节。支持多选与同名书。每个显式选项都须可访问且包含可读章节。

普通发送和原生追加共用服务端身份校验。后端在本机临时目录按书籍保留章节层级，校验内容哈希后把目录的绝对路径交给 CLI。提示词要求 Codex 自行翻阅，并在给建议时列出实际阅读的书章相对路径与对应代码位置。此过程无需 Wiki、向量索引或额外模型调用。提供目录表示章节可供阅读，实际引用取决于本轮模型打开的文件。

临时目录由当前轮次持有，追加收到 RPC 确认后仍然可读，结束时清理。原生追加沿用当前活动轮次的同一引用范围。更换勾选后可用「排队继续」，下一轮按新选择重新校验。排队快照保存资源 URI，服务器物理路径只在执行时生成。

临时目录根部的 `aiagent-chapter-links.json` 将本轮已选章节的相对路径映射到带解析版本的资料库链接。回复用这些链接引用章节，用户可在聊天中预览或下载 Markdown。接口按当前账号校验资源可见性、解析版本和清单哈希。旧消息中的临时路径按来源文档 ID 和完整章节路径查找当前版本。只有书内相对路径的旧引用，须在会话选中的知识范围内唯一匹配完整目录和文件名。个人电脑其他目录里的文件可通过聊天附件或资料库上传使用。直接读取资料库需要后端服务账户能访问配置的存储目录。

回归测试 `CodexReadsOnlySelectedBookChaptersFromTurnInput` 使用合成书籍、项目和 app-server 协议替身。将 `AIAGENT_BOOK_TEST_CODEX` 设为本机 Codex 可执行文件绝对路径，可通过其 `sandbox -P :read-only` 从两种协议输入读取章节与仓库文件。随机校验标记只存在于文件正文中。

点击章节名称在聊天右侧打开排版预览，正文和解析图片由资料库按权限提供。点击「保存到知识库」可选择本人、项目或共享资料目录，将 Markdown 和同一解析版本中正文实际引用的 PNG 另存为一个文件。保存遇到图片读取失败时显示错误，全部图片就绪后才上传。副本使用内嵌图片，可独立预览。超过 JSON 原文上限的 Markdown 由知识工作区通过原文件接口加载。保存副本沿用资料库 25 MB 单文件上限。

## 请求字段

```json
{
  "knowledge_base_names": ["shared-books"],
  "knowledge_scope_uris": [
    "viking://resources/books/refactoring/",
    "viking://resources/checklists/",
    "viking://resources/Manufacturing%20Systems.pdf"
  ],
  "code_project_id": 12,
  "agent": "codex"
}
```

前端展示可见目录与原始文件，目录可折叠，包含直接上传在资料根目录下的 PDF；只发送服务端返回的 URI。解析章节和编译输出不作为单独原文件选项。后端再次规范化 URI 并检查可见树：目录取后代文档 ID，文件按完整 URI 精确匹配，不能用文件名前缀覆盖其他文件。目录与文件混选仍取文档 ID 并集，继续按知识库筛选；不存在／不可见项拒绝整次检索。旧目录 URI 缺少末尾斜杠仍兼容。浏览器或模型提供的本机绝对路径不具有授权意义。

## 会话持久化

Scope URI 列表与知识库选择一起写入会话 preferences，重新打开会话时恢复选择。资源树刷新后如果某个 URI 已不可见，前端清除该项，后端仍会拒绝无权或不存在的 URI。

## 目录选择交互

树形选择器独立判断触发按钮和弹窗的点击范围，父级项目菜单不得处理知识目录的外部点击。勾选、展开和搜索仅修改本地草稿，不关闭弹窗；确定才更新会话选择，取消、Esc 和点击外部均丢弃草稿。桌面与移动端遵守相同规则。搜索覆盖折叠目录的后代，搜索框回车不提交聊天。

勾选父目录会联动选中全部可见资源树中的后代目录和原始文件，包括折叠或被搜索过滤的项；取消父目录会取消整棵子树。取消某个子目录或文件时，覆盖它的祖先取消全选并显示半选，提交范围改为其余已选目录和文件，避免取消的项仍被父目录包含。单独选择子目录不会自动扩大到父目录的直属资料。已确认的父目录再次打开时恢复全部后代勾选。

提交与计数仅保留最上层已选目录或文件，去除已由父目录覆盖的重复项；半选节点不作为整个目录提交。接口字段不变；服务端新增文件的精确匹配。

浏览器回归：`front/tests/knowledge-scope-picker.browser.mjs`，使用合成 API 和 WebSocket 驱动真实聊天页面，覆盖根目录与目录内文件勾选、父子联动、半选与取消子项后的实际提交范围、连续多选、目录展开、草稿保留、取消及桌面/移动端；不调用真实模型或读取知识资料。

## PDF 上传与可见性

Next.js 的 `/api` rewrite 使用请求正文克隆，当前安装版本默认最多保留 10 MB。16.1 MB 合成书籍在旧配置下只剩 10,485,760 字节，后端无法获得完整 multipart。`front/next.config.js` 将 `experimental.proxyClientMaxBodySize` 对齐后端默认 200 MB 请求上限；知识导入的单文件 25 MB、数量、格式和路径校验保持。修改配置后需要重启前端服务／重新构建生产包，后端文件 Scope 改动需编译并重启后端。

上传界面在弹窗内显示 HTTP 和文件级错误，保留文件供重试。零个文件导入不报告成功；部分成功显示实际保存数、解析任务数和逐项失败／跳过原因。原始文件保存后立即刷新目录，解析未入队的警告与原文保存状态分别展示，不等待 PDF 转换或模型调用成功才显示资源。

验证入口：`front/tests/knowledge-upload-proxy.mjs` 使用已安装 Next.js 的相同正文克隆函数对比完整字节数与 SHA-256；`knowledge-resource-upload.browser.mjs` 驱动真实页面的合成 HTTP／文件级失败及重试。`KnowledgeBookUploadTests` 对真实 Dynamic API 发送同名 16.1 MB 合成 multipart PDF，确认原文逐字节保留、根目录文件可见且任务入队。`KnowledgeFileScopeTests` 验证单文件、目录／文件混选、同名前缀不串入及不可见资源拒绝。

这些验证不读取真实书籍，不表示已经验证该书的 PDF 转换或 OCR；转换能力及扫描件限制继续见 [文档转换与结构解析](knowledge-document-parsing.md)。

## 后续扩展

- 增加多个目录的 Scope 保存和 Playbook 默认范围。
- 在 `KnowledgeContext` 内统一加入关键词、向量、图谱和结构过滤。
- 为 Scope 保存代码仓库、目录和 commit 快照，形成知识到代码的可复现审查。
- 接入本地 Knowledge Agent 或自定义 API 时只替换 Provider，保留 Scope、权限和现有 Codex 改码链路。
