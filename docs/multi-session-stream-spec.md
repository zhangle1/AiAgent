# 多会话并行流式规格

## 目标

保持现有 `/api/v1/chat/ws`（失败时 SSE）原始流式协议，不引入任务表、队列、Worker 或服务端控制通道。一个浏览器可同时维护多个会话的流式请求；用户切换会话只切换页面渲染，不中止其他会话。

## 应用层运行时

根布局提供 `ChatStreamProvider`，只保存浏览器内存中的运行记录：

```text
stream_id -> { session_id, status, events, started_at, error_message }
```

- `session_id` 是流归属键；Provider 根据它把事件交给对应会话页面。
- `stream_id` 是客户端生成的唯一键；每条请求各自使用原有 WS/SSE 连接和 AbortController。
- 事件定义：`label`、`loop`、`thinking`、`content`、`tool`、`tool_request`、`tool_result`、`sources`、`done`、`completed`、`error`。
- `done` 仅表示 Agent 已生成回答；后端完成会话与使用量落盘后才发送 `completed`。浏览器只以 `completed` 作为一轮流的成功终态，不以 WebSocket 的 `close` 事件作为完成条件。
- 进入中的会话在收到自身的 `completed` 后，延迟读取一次已落盘历史作为最终一致性校准；该刷新只作用于当前会话，不刷新浏览器页面，也不影响其他会话流。
- 兼容仍运行旧协议后端的浏览器：收到 `done` 后等待 800ms；期间若未收到 `completed`，才按旧协议结束该会话并执行同样的会话级历史校准。新协议始终以 `completed` 优先。
- 同一会话保持一条活动流；不同会话可并行。
- 页面卸载不 abort；仅明确点击停止或整个应用关闭时 abort。
- 运行记录在本次浏览器应用生命期内保留，用于切回会话时立即接续显示；已完成内容仍由原有会话接口持久化。
- 历史接口返回的数据只作为页面基线。页面显示消息必须始终由“历史基线 + Provider 当前流记录”同步派生，不把流事件复制回页面本地状态；已落盘的完成回复按内容去重。

## 侧栏状态

| 状态 | 样式 | 位置 |
| --- | --- | --- |
| `streaming` | 8px 蓝色旋转环 | 会话标题末尾、菜单按钮之前 |
| 后台 `done` 未查看 | 6px 琥珀提示点 | 同一位置 |
| 当前选中或已查看 | 不显示完成提示 | — |
| `error` | 6px 红色提示点 | 同一位置 |

进入会话即标记其完成/失败提示为已查看；运行中的蓝环持续保留。状态点不改变项目分组、标题截断或菜单宽度。

## 取舍

浏览器刷新仍会丢失进行中的内存流；这是保持原始流式执行语义和简洁性的取舍。刷新后已完成结果通过原有会话历史读取。
