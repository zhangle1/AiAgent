# 模型发现与坤伴订阅

## 服务端模型发现

管理员在设置 → 模型 → LLM 或 Embedding 输入服务地址与 API Key 后，界面等待输入稳定，再读取供应商模型列表并保存模型配置。也可以点击“检测并保存”刷新已保存的密钥。已有模型不因供应商暂时不返回而自动删除；已有手动上下文容量保留。修改地址后需要重新输入密钥，已保存密钥不能用于另一个地址。

模型检测返回 401、其他错误或空列表时，仍通过相同的串行保存队列保存当前连接配置，保留已有模型，并明确显示检测结果。此前失败／空列表提前返回，导致刚输入的 Key 未落库，刷新后回到旧空值；该缺口已修复。保存失败保留页面中的输入并提示重试。过期或已取消的检测不能写入配置。密钥回填为掩码时保留本次检测错误，不能把“配置已保存”当作供应商鉴权通过。

模型列表支持 OpenAI 兼容、Anthropic、Google 和 Ollama 的列表形状。检测只调用模型列表，不发送生成请求、不用失败提示猜上下文上限。服务返回的容量优先，其次从本地公开目录匹配；不能确认的值留空。公开能力不会自动启用服务端 Native V2，原有显式验证开关保留。

本地目录是服务端 ContentRoot 下的 `data/models/model.json`，首次使用从程序集中的 `Resources/Models/models.dev.json` 原子写入，格式沿用客户端 models.dev 快照。它只含公开元数据，不保存 API Key、用户密码或会话令牌。目录可由运维维护，当前进程加载后使用内存快照，修改后重启生效。数据库的 `ai_model_profile` / `ai_model` 仍是运行配置来源；输出容量、图片能力和来源信息使用已有 `ExtraOptionsJson`，无需新增非空列。

新增接口：

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/settings/model-discovery` | 管理员检测指定配置或草稿的模型列表 |
| `GET /api/v1/settings/model-discovery/status` | 返回本地目录相对位置 |

界面自动保存通过既有 catalog API，与手动保存、应用、诊断和重新读取共用顺序队列，忽略输入变化后的过期发现结果。写库期间暂时禁用编辑，后续操作使用服务器回传的配置 ID。手动上下文及输出容量单独标记来源；未标注来源的旧容量跟随本次检测更新，避免旧种子中的小窗口一直保留。没有检测到新值时保留现值。供应商失败只显示状态分类，不将响应正文、密钥或模型生成内容写入错误提示。

## 坤伴订阅账号模式

客户端默认先经过 [登录首页](kunbuddy-account-home.md)。未登录或检测到登录过期时填写 URL、用户名和密码，成功后自动更新下述订阅配置；设置中的登录入口仍可使用，二者共用同一服务。

在桌面端 设置 → 模型 → 添加 AI 服务 → 使用订阅登录 中选择“坤伴订阅”，填写 AiAgent 地址、账号和密码。地址可以是后端根地址，也可以是配置了 `/api` 反向代理的网页根地址，支持部署前缀。无协议的内网地址按 HTTP 处理；公网使用 HTTPS。URL 不能包含凭据、查询或片段。

登录后自动同步服务端配置的 LLM 档案和模型。每种服务协议保持独立本地供应商行，使用服务端配置模型的稳定 ID；聊天、工具定义、工具结果、图片内容和流式响应按原协议转发，平台模型密钥始终由服务端补充。支持 Chat Completions、Responses、Anthropic Messages 和 Google Generative AI；服务端高级选项可显式设置订阅请求协议，默认按供应商选择。服务器只能访问管理员配置的服务地址和模型，客户端不能传入任意上游 URL 或绕过模型目录。

密码只用于登录请求，不写入本地文件或日志。桌面主进程交换得到 8 小时的 `kunbuddy-client` 会话令牌，通过 Rust host 原有加密凭据存储保存，渲染层只收到公开供应商信息。该令牌与网页会话、DeepSeek 插件会话隔离，不能调用管理接口。登录／退出 IPC 只接受主窗口发送者，按顺序执行。重新登录更新同账号档案，停用并清除已撤下档案的本地凭证；部分保存失败恢复旧配置和旧凭证，并撤销新令牌。退出账号会撤销此服务、此账号在本机保存的会话并删除关联档案，其他账号保留。密码重置、用户禁用或到期后需要重新登录。

服务器展示名称转换为本地别名时遵循 Rust host 的 60 字符限制，稳定模型 ID 不变。空白占位模型不会发布到订阅目录。首次生成本地元数据目录若写盘失败，不发布仅存在于内存的成功状态，下次可重试落盘。

这次“订阅”是账号连接渠道，沿用现有 AiAgent 账号可用的全局 LLM 目录，不包含支付、套餐购买、计费或新增逐模型授权表。原 API Key 模式、浏览器聊天和本地文件工具继续沿用既有行为。未知模型容量由客户端原有运行时默认值处理，不称为实测容量。

| 接口 | 行为 |
| --- | --- |
| `POST /api/v1/auth/kunbuddy-login` | 验证现有账号，返回短期 Bearer 令牌 |
| `GET /api/v1/kunbuddy/models` | 读取该渠道可用的配置档及模型元数据 |
| `POST /api/v1/kunbuddy/logout` | 撤销当前会话 |
| `/api/v1/kunbuddy/profiles/{id}/...` | 白名单模型列表和生成协议转发 |

上游 HTTP 重定向关闭，避免转发凭据到重定向地址。上游错误返回固定分类，不透传可能回显密钥的正文。请求有大小与超时边界，取消传递给上游。

## 验证范围

专项用例位于 `backed.tests/ModelDiscoveryTests.cs`、`backed.tests/KunBuddySubscriptionTests.cs`、`client/apps/desktop/test/kunbuddy-subscription.test.mjs` 和 `front/tests/model-discovery-state.test.mjs`。使用临时 SQLite、合成账户、HTTP 替身和隔离客户端目录，不读取真实用户数据库或密钥。前端用例覆盖来源优先级、过期结果、顺序保存和失败后重试。

无需编译的纯逻辑用例可单独运行：`node --test front/tests/model-discovery-state.test.mjs`、`node --test client/apps/desktop/test/kunbuddy-subscription.test.mjs`。`kunbuddy-subscription-ipc.test.mjs` 依赖重建后的共享协议包，旧构建缺少新增频道时会明确失败，不能据此跳过最终集成验收。

构建与运行验证需按 CodeLimit 获得明确授权；仅静态检查或纯逻辑用例通过不能作为真实接口、登录或聊天成功的证据。交付时另存本轮变更集及实际验证结果，不复用早期移植变更集的指纹。

2026-10-21 已获本轮验证授权，完成后端 20 项、客户端纯逻辑 11 项、主窗口 IPC 1 项、网页状态逻辑 7 项验证；共享包及客户端构建、两端 TypeScript 类型检查通过。隔离 HTTP 和真实 Electron 验证也已通过，详情见 [本轮验证记录](kunbuddy-subscription-model-discovery.verification.md)。
