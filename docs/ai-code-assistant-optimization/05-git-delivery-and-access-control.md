# 任务 05：Git 交付与权限

## 目标

让代码交付遵循“先同步、再审查、后提交”的受控流程，减少未拉取代码即提交造成的失败与风险。

## 范围

- 在项目 Git 页面前置“拉取最新代码”与同步状态；
- 提交前检查当前分支、工作区修改、远端落后和冲突；
- 展示 AI 修改 diff 与变更摘要；
- Git Token 服务端安全保存，失效后提示重新授权；
- 权限分级：普通用户仅生成分析/Markdown，授权人员才可提交或推送。

## 非范围

- 不开放 AI 自动提交、自动推送或绕过人工确认；
- 不在会话、Prompt 或普通日志中显示 Token。

## 验收与测试

1. 远端落后或有冲突时，提交按钮给出明确阻断原因与拉取入口。
2. 无提交权限用户无法调用提交/推送接口。
3. 授权用户仍须查看差异并显式确认后才能提交。
4. Token 失效时仅提示重新授权，日志和界面不回显敏感值。
