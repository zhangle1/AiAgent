# 坤伴订阅原始会话同步

## 使用方式

KunBuddy 使用“坤伴订阅”登录 AiAgent 后，订阅会话自动保存到平台知识工作区“人员 → 我的工作区 → 会话”。该目录对应 `viking://user/<登录用户>/sessions/`，即使没有会话也显示。每个本机安装与会话的组合只对应一个逻辑 Markdown 文件；新消息追加到原文件，不为每轮聊天另建文件。平台目录中点击刷新即可查看新增记录、预览或下载原文。

启动、登录和手动重试时扫描已有订阅会话，补传完整历史；聊天进行中在消息确认落盘和轮次结束后同步后续记录。会话文件保留用户、助手、工具及可见系统事件，已有推理文本按原内容保存。隐藏模型系统提示、附件二进制和订阅凭据不进入导出。附件只记录名称与类型，引用会话的既有文本片段按原记录保存。

上传只做确定性的 Markdown 序列化、HTTP 传输和原始文件写入，不调用 LLM，不自动解析、生成摘要、提炼、建立索引或编译。手动上传到“会话”目录的文件也只保存原文。需要整理时，由用户主动选择文件运行“重新解析”或“编译资料 /compiler”；由该显式操作沿用已有任务和模型配置。平台的会话目录空状态与说明明确区分原文同步和后续处理。

订阅编辑弹窗显示本机待上传会话数量，并提供“重试会话同步”。断网或平台暂时不可用时保留待上传记录，后续重试；凭证失效时显示需要重新登录。普通 API Key、配对远程主机和原生导入会话不自动上传。升级前已有的订阅会话会补传；已有会话改绑到其他账号时不会自动将原账号的记录转交新账号。

## 生命周期接入

本地 Pi Agent 已通过 `agent.subscribe` 提供 `message_end`、`agent_end` 等事件，客户端将其投影到已有持久化链路。本轮没有让模型调用上传工具，也没有创建可执行的上传 Skill：

1. `PersistenceOutbox` 在 `session.appendMessage` 被 Rust host 确认并完成本地出箱持久化后，通知会话同步器。
2. 已有 `onTurnSettled` 在持久化轮次结算后补充通知，覆盖结束、取消和错误路径。
3. 同步器合并同一会话的通知，分页读取完整原始记录，仅上传新增或变更的消息分片。大消息按 Unicode 码点拆分，按 JSON 实际字节数组批，服务端不在分片间插入字符。
4. 退出时先停止事件生产、排空原有持久化队列，再在有限等待时间内尝试同步；未完成记录继续保留供下次启动恢复。

Rust 仍独占 SQLite。Electron 通过现有 host RPC 读取会话，不直接打开数据库。应用自有 `kunbuddy-session-sync.json` 只保存安装 ID、会话绑定、待上传状态及已确认分片哈希，不存密码、令牌、Markdown 正文或附件文件。损坏的同步状态不被静默覆盖。日志使用固定错误分类和会话标识，不记录上传正文或上游响应体。

## 服务端契约与存储

`POST /api/v1/kunbuddy/sessions/{sessionId}/markdown` 使用已有 `kunbuddy-client` 短期令牌。请求字段为 `account`、`client_id`、`title` 和 `entries: [{ id, markdown }]`；客户端账户断言必须与服务端认证账号一致，避免凭证切换竞态误投递。请求不接受目标人员、所有者 URI 或服务器路径。文件归属只由当前认证用户确定。

安装 ID 与会话 ID 生成稳定摘要，逻辑 URI 为个人 `sessions/<摘要>.md`；目录树显示可读标题及短摘要。原始资料使用独立内部存储 `kunbuddy-session-store` 和既有 `AiKnowledgeDocument`，不增加数据库实体或列。物理文件位于受控 raw 根目录的用户／会话摘要路径，客户端不能指定该路径。该内部存储不出现在公共知识库列表，禁止经旧知识库的按 ID 下载、内容、上下文树、搜索和索引入口访问；显式指定内部名称的通用聊天检索也被拒绝，防止绕过个人目录权限。读取和用户主动处理均经过有身份范围的资源接口。

服务端保存完整、不可变的 Markdown 与去重状态文件对，原子发布目录后再更新数据库中的原文指针。因此文件／数据库写入失败时，原先已发布记录仍可读；可能留下未引用的版本，不会显示为成功会话。不同用户、同名会话和不同安装相互隔离。同一分片的相同内容重试不会重复追加；消息修订追加修订片段，保留已收到的旧原文，旧请求重放不会回滚新记录。

当前单批最多 64 个分片、原始文本合计 2 MiB、单片 512 KiB，HTTP 请求上限 3 MiB；客户端采用 256 KiB Unicode 分片，并将 JSON 请求组批到约 2 MiB。单个原始会话文件上限为 128 MiB，超限明确失败并保留待处理状态，不静默截断。平台沿用普通文本预览的大小上限，较大原文可完整下载并按需手动处理。原始记录删除不因本地已确认状态而自动重建；后续新消息仍可建立该逻辑会话的新记录。

## 人员与管理员边界

普通账号仅能列出、读取、下载及写入自己的会话。内置 `superadmin` 具有现有 `admin` 角色，因此可看到所有注册人员的“会话”目录，并预览、下载其中原文。权限依据服务端数据库角色，不依据可伪造的前端用户名。

管理员额外读取范围只扩展到他人的 `sessions/` 及其目录祖先，不开放其记忆、Wiki、摘要等其他个人目录。管理员不能借此向他人的会话目录上传、建目录、重新解析或编译。管理员查看记录不会触发模型请求或任务。订阅令牌与网页登录会话的用途隔离保持不变。

## 验证入口

- 后端：`backed.tests/KunBuddySessionSyncTests.cs`，临时 SQLite 与文件目录，覆盖追加、去重、修订、并发、分片无损拼接、手动上传只存原文、双用户隔离、管理员原文读取及写入限制。
- 客户端：`client/apps/desktop/test/kunbuddy-session-sync.test.mjs`，覆盖序列化、Unicode 分片、JSON 字节组批、重试、重启、账号绑定、历史补传、分页和持久化通知顺序。
- IPC：`kunbuddy-subscription-ipc.test.mjs` 验证主窗口限制覆盖状态和重试入口。
- 本机隔离运行证据：实际 Electron 两轮聊天自动上传、实际动态 API、平台知识工作区目录和 Markdown 预览、模型调用计数与无自动任务计数。结果和源码指纹见 `kunbuddy-session-sync.changeset.json`，不沿用早期模型发现的审批指纹。

本轮修改与此前尚未提交的模型发现／订阅功能共存。新变更集记录当前组合源码及排除的无关代码库、Git 和部署脚本修改；仅本地校验，未提交或推送。真实账号、平台密钥和业务数据库未作为测试数据。
