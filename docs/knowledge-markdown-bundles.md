# PDF、Word、TXT 的 C# Markdown 目录产物

## 目标与使用

参考本地 [OpenViking 解析说明](E:/项目/know-why/OpenViking-PDF-Word-TXT转Markdown逻辑解析.md) 及其 MarkdownParser 源码，把格式提取与目录发布分开。实现完全位于 AiAgent C# 服务中，PDF、DOCX、TXT 的解析不依赖 Python，也不调用模型决定章节结构。原有 L0/L1 语义任务继续使用完整正文。

重新解析文件后，进入「解析正文」展开章节列表，点击「打开目录索引」。索引可逐级进入章节，也可返回上级目录；资料树中的「目录索引.md」对应只读 `_index.md`。原文、解析章节和图片均保留各自身份，删除与权限规则继续跟随原始资料。

## 产物结构

下面是大型分层文档的目录示意，实际文件名及数量由标题与解析阈值决定：

```text
<解析版本>/
├── document.md                 完整正文，图片链接指向 assets/
├── layout.json                 版本、来源区间、顺序、哈希、索引及图片清单
├── sections/
│   ├── _index.md               按原文顺序排列的一级入口
│   ├── 概述.md
│   └── 安装/
│       ├── _index.md           本目录入口与上级索引链接
│       ├── Linux.md
│       └── Windows.md
└── assets/
    ├── page-0001-001.png       PDF 区域裁图，重用相同内容的图片
    └── <内容哈希>.png           Word 内嵌图片等
```

通用转换输出还保留 `document.txt` 兼容现有调用方；知识库发布目录可能保留转换中间目录。索引与正文分片分开记录，索引不计入正文字符覆盖或章节数量。小文档只需要一个正文分片，也会有目录索引；关闭拆分会保留一个完整分片。不是每页或每个标题都强制建立文件。

## 统一处理

1. `DocumentConversionService` 验证受控输入／输出路径，按格式调用转换器，得到完整 Markdown 与资产。
2. `MarkdownDocumentPlanner` 依据标题层级、字符和 token 估值规划文件；超长叶章节按段落后备拆分，同名和 Windows 保留名作确定性处理。
3. `MarkdownBundleWriter` 校验所有来源区间连续完整，再生成章节、每级目录索引和哈希。图片路径按当前章节所在目录计算，索引链接按原文顺序生成。
4. 知识库使用同一个写入器，先完成受控 staging 内的正文、章节、索引、图片与清单，再重命名版本目录，由数据库行发布可见版本。
5. 资源服务依据清单投影来源可见的章节、索引和图片。网页阅读索引时，将已知清单中的相对链接转换为受控 Viking URI；原始下载文件仍保留可供目录阅读器使用的相对链接。

索引名 `_index.md` 是新布局的保留文件名，来源或标题同名时正文分片改名，避免覆盖。单份计划最多 10000 个正文分片；过小的阈值导致超限时明确失败。代码围栏和 Markdown 图片／链接引用不再从中间切开；单个不可分结构可超过目标阈值，完整表格行也保留原有例外。阈值用于组织文件，模型输入窗口仍由后续语义阶段独立管理。

## 各格式的优化

| 格式 | C# 处理与保留内容 |
| --- | --- |
| PDF | 沿用 PdfPig 的书签、文本、网格表格与坐标，以及 PDFium／SkiaSharp 裁图。无书签时，均匀抽样最多 32 页统计正文字号，避免只含大标题的封面被当作自己的正文。PNG 按整份文档的 SHA-256 去重，重复引用仍留在原位置。保留页码标记、裁图、矢量区域和无文本层页面的图片。 |
| DOCX | 保留样式继承与 outline 层级，段落、编号／嵌套列表、粗体、斜体、删除线、允许协议的超链接、脚注／尾注引用、表格及内嵌 PNG。内容控件内部的表格继续按表格处理；无声明表头时增加空表头，保留首行数据。文字中的 Markdown 特殊字符先转义，避免普通文字被误当作标题。 |
| TXT | BOM 识别 UTF-8、UTF-16 LE／BE、UTF-32 LE／BE，优先严格 UTF-8；无 BOM 且 UTF-8 失败时，严格尝试 GB18030（包含 GBK），要求有中文证据并保留推断警告。无法识别的输入明确失败，不用 Latin-1 无条件兜底。原文预览与转换使用相同解码器；原始字节不变。 |

TXT 原有 Markdown 标题、列表和表格语法会参与结构解析；普通「第一章」文本不会被擅自改写为标题。TXT 不包含嵌入式多媒体，本轮不会越过来源授权去读取邻近服务器文件或下载外链图片。Word 外部图片继续沿用警告策略，不抓取网络资源。

## 契约与兼容

转换请求 `DocumentParseRequest` 增加：

- `source_name`：可选原始文件名，避免受控临时文件名出现在分片中。
- `parsing`：沿用 `split_content`、字符和 token 双阈值及短章节合并阈值。
- `write_bundle`：默认 true，写出章节、索引和 `layout.json`；返回 `layout_path`、`index_path` 和 `section_count`。

知识库由自己的原子发布器负责目录生命周期，所以转换中间阶段设置 `write_bundle=false`，最终仍生成完整目录产物。聊天附件和项目文本预览显式跳过临时目录产物，继续保存原文件与兼容文本，避免写出稍后即被清理的章节或图片链接。

知识库清单升级为 `markdown-layout-2`，正文 `Files` 和图片 `Assets` 保持原结构，新增 `Navigation` 的路径与内容哈希。资源节点增加 `is_navigation`，原文读取结果增加 `parsed_index`；原 `parsed_outputs` 仍只包含正文分片，数量与覆盖契约保持。索引与章节一样校验来源、最新解析 ID、来源哈希、受控路径和内容哈希，不接受浏览器物理路径。

`markdown-layout-1` 的历史清单仍可读取，旧单文件正文兼容路径保持。历史资料不自动重跑解析或模型；重新解析后才获得索引与新布局。索引文件损坏时拒绝该索引读取，已发布完整正文仍可读。没有新增数据库字段。

## 限制与验证

扫描 PDF 仍未自动 OCR，保留页面图并提示；复杂跨栏、公式、无框线表格和浮动 Word 版面不保证视觉还原。Word 原始 `.doc` 继续通过已配置 LibreOffice 转成 DOCX，再进入 C# 转换器；不是新增纯托管二进制 DOC 解码器。本轮只发布已有 PNG 类型的文档图片，不增加音视频转写或整包 ZIP 下载接口。

测试使用隔离 SQLite、C# 生成的 PDF／DOCX 和合成编码文本。覆盖完整区间、目录链接、章节图片相对路径、封面字号、跨页图片去重、Word 样式／列表／脚注／表格、中文解码、不可分结构、取消、损坏索引、旧版本兼容、授权、删除与预览回归。浏览器使用真实页面和完全拦截的合成 API，覆盖索引入口、章节跳转、只读下载、390px 布局及原 PDF 预览。

部署需重新编译并重启后端，更新前端后刷新页面；对旧文档手动「重新解析」。未读取真实配置、数据库或用户原书，也未自动迁移原文件。
