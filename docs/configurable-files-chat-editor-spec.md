# 聊天配置文件编辑与代码库输出规范

> 状态：待评审（替代已撤回的“端口策略/自动服务关联”方案）

> 范围：聊天框、项目与代码库页、前端与 C# 后端代码库的**已授权配置文件**。

## 1. 目标

让用户在聊天中直接查看、编辑并保存项目配置，而不是把端口、API 关系和框架差异塞进运行设置。

- 一个项目可有多个代码库；每个代码库可选择多个配置文件。
- 前端和后端配置文件同等支持，例如 `package.json`、`.env*`、`vite.config.*`、`appsettings*.json`、`launchSettings.json`、Docker/Compose 文件。
- 聊天只可编辑在代码库页明确勾选过的文件；不能任意读写磁盘路径。
- 代码库页提供清晰的配置文件清单、编辑输出和变更记录；聊天负责对话式修改。
- 运行管理器保持现有“默认端口 + 自动寻找可用端口”行为，不负责推断或改写项目 API 配置。

## 2. 核心模型

现有代码库的 `configuration_files` 继续作为**授权白名单**，不在第一期新增端口、依赖或环境变量运行字段。

每个条目输出下列只读元数据：

| 字段 | 说明 |
| --- | --- |
| `repository_name` | 所属前端或后端代码库 |
| `path` | 相对代码库根目录的规范化路径 |
| `kind` | `frontend` / `backend` / `shared` / `unknown`，由文件名与代码库语言推断，可人工覆盖 |
| `format` | `json` / `jsonc` / `yaml` / `env` / `javascript` / `typescript` / `xml` / `text` |
| `sha256` | 当前版本；保存时用于并发保护 |
| `size` | 文件大小；超过限制只允许下载或局部查看 |
| `last_modified_at` | 代码库页输出用的最后修改时间 |

第一期的“配置文件”是文件清单，而不是把键值拆到数据库。这样 `appsettings.Production.json`、多个 `.env`、多个前端配置文件均可准确保留。

## 3. 代码库页：选择与输出

### 3.1 识别与选择

“项目与代码库 → 代码库配置”保留并强化“可编辑配置文件”区域：

1. 扫描候选文件，但默认不授权写入。
2. 用户可一次勾选多个文件，前端/后端没有数量限制。
3. 保存代码库后，勾选项成为聊天可操作的白名单。
4. 取消勾选不会删除物理文件，只会撤销聊天编辑权限。

候选规则覆盖但不限于：

- 前端：`package.json`、`.env`、`.env.*`、`vite.config.*`、`next.config.*`、`config/*.json`、代理配置。
- 后端：`appsettings*.json`、`Properties/launchSettings.json`、`web.config`、`*.csproj` 中的运行配置项。
- 共享：`docker-compose*.yml`、`Dockerfile`、`.editorconfig`、项目约定的 `config/` 文件。

扫描仅提供候选项；不因文件名自动获得写权限。

### 3.2 配置文件输出面板

代码库详情新增“配置文件输出”面板，按 `前端 / 后端 / 共享` 分组展示：

- 所属代码库、相对路径、格式、最后修改时间、文件版本摘要。
- 最近一次来自聊天的保存结果：成功、冲突、校验失败及简短原因。
- “在聊天中打开”按钮：将项目、代码库和文件路径带入当前聊天输入上下文。
- “复制配置上下文”按钮：只复制路径与摘要，不复制密钥内容。

该面板是输出与审计视图，不自动生成 `.env`、不覆盖 `package.json`，也不启动程序。

## 4. 聊天框交互

当用户已选择项目时，聊天输入框旁提供“配置文件”入口：

1. 弹出该项目所有已授权文件，可按代码库、前端/后端、文件名筛选。
2. 可多选并同时打开；每个文件独立标签页和独立草稿。
3. 用户可说“把前端 API 改为 …，后端连接串改为 …”；Agent 必须先列出将修改的文件和键，再写入。
4. 保存可选择“当前文件”或“保存全部已修改文件”；逐文件显示结果。
5. 保存后聊天返回简洁清单：改了什么、哪些文件成功、哪些冲突或需要用户处理。

聊天不根据文件内容自行启动服务，不自动重写端口，也不自动将前端指向某个后端。需要调整端口或 API 地址时，用户通过这些显式配置文件完成。

## 5. 读取、编辑与保存规则

### 5.1 安全边界

- 路径必须属于当前项目的已挂载代码库，且精确命中 `configuration_files`。
- 解析后路径必须仍在代码库根目录内，拒绝绝对路径、`..`、符号链接逃逸。
- 默认拒绝二进制文件、超过 1 MB 的文件以及凭证私钥文件。
- `.env`、连接串、Token、密码等敏感值在聊天预览与代码库输出中遮罩；用户明确打开并有权限时才返回原文。
- Agent 不能通过“编辑配置文件”入口写入未授权源码、脚本或任意命令。

### 5.2 并发与格式

- 读取返回 `sha256`；保存必须携带该值。
- 物理文件已被 Visual Studio、Git 或其他用户修改时，保存返回 `409 conflict`，不覆盖；聊天显示重新读取/比较选项。
- JSON/JSONC、YAML、XML 进行语法校验后保存；`.env` 校验 `KEY=VALUE` 基本格式。
- JavaScript/TypeScript 配置仅做文本编辑与基础大小/路径校验，不执行其中代码。
- 保存采用原文件编码；无法可靠识别时拒绝自动转换，提示用户确认。

## 6. API 与数据流

在已有“读取已配置文件 / 写入已配置文件”接口基础上补齐项目级聚合和结果输出：

```text
GET  /api/code-projects/{projectId}/configuration-files
GET  /api/code-repositories/{repositoryName}/configuration-files/{path}
PUT  /api/code-repositories/{repositoryName}/configuration-files/{path}
GET  /api/code-repositories/{repositoryName}/configuration-file-events
```

聚合接口只返回白名单与元数据。读取/保存接口始终按代码库和相对路径校验；保存请求包含：

```json
{
  "content": "...",
  "expected_sha256": "...",
  "source": "chat"
}
```

保存成功后写入轻量事件：代码库、路径、结果、时间、来源、前后 SHA；不记录完整敏感内容。

## 7. 分期实施

### Phase 1：收口与可见性

1. 撤回端口策略、启动适配器、自动前后端关联字段和设置项。
2. 保持 .NET 运行产物隔离，继续避免锁定 Visual Studio 的 `bin/Debug`。
3. 代码库页显示多文件授权清单和最近保存结果。

### Phase 2：聊天多文件编辑

1. 项目级文件选择器、多个编辑标签和草稿状态。
2. 复用现有 SHA 并发保存机制，逐文件保存并输出结果。
3. 增加 JSON/YAML/XML/.env 的静态格式校验与敏感信息遮罩。

### Phase 3：可追溯性

1. 代码库页增加配置文件事件列表与筛选。
2. 聊天提供“查看上次修改”“重新读取并比较”操作。
3. 需要时再增加 Git diff/提交建议；默认不自动提交。

## 8. 验收场景

1. 同一项目有一个前端代码库和一个 C# 后端代码库，分别勾选 3 个和 4 个配置文件；聊天文件选择器能一次看到全部 7 个，并按代码库分组。
2. 用户在聊天同时修改 `package.json`、`.env.development` 和 `appsettings.Development.json`；保存结果逐文件返回，任一失败不覆盖其他未保存文件。
3. 用户在 Visual Studio 中修改了 `appsettings.json` 后，聊天基于旧 SHA 保存，系统返回冲突且不覆盖。
4. 未勾选的源码文件、代码库外文件、私钥文件无法通过聊天读取或写入。
5. 代码库页能看到每个已授权文件及聊天保存的成功/失败输出，但不泄露 `.env` 和连接串的敏感值。
