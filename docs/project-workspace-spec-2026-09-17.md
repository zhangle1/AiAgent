# 项目工作空间规格

状态：待原型确认后实施  
日期：2026-09-17

## 目标

把“项目”升级为用户与 Agent 的统一上下文容器。用户进入项目后，可以同时使用 Git 代码仓、长期项目资料、AI 生成产物和项目知识；代码交付仍走 Git，普通资料与产物默认不进入 Git。

## 已确认决策

1. 项目是一级工作空间，也是聊天、资料、代码、产物和知识范围的共同边界。
2. 一个项目可关联多个 Git 仓库；代码修改、测试、diff 和提交保持现有 Git 流程。
3. 用户文件进入“项目资料”，按目录长期保存，可预览、下载、引用、移动和删除；默认不写入代码仓。
4. Agent 生成的 HTML、Markdown、Office、PDF 等进入“AI 产物”，可预览和下载；用户可显式转存为项目资料或导入指定代码仓。
5. 项目资料可按需知识化。聊天默认启用项目知识，但输入区持续显示实际上下文范围，允许本轮开关或细化。
6. Harness/本地 Codex 是执行通道，不是项目空间开关。没有 Harness 时仍可上传、检索、生成和下载；连接后才可访问授权的本地工作目录并执行改码、测试。

## 页面模型

项目详情页包含：

- 概览：最近会话、待处理产物、仓库状态、知识健康度和最近活动。
- 对话：项目默认上下文下的会话；输入框显示本轮使用的仓库、资料、知识库和附件。
- 项目资料：用户上传与从临时附件转存的非 Git 文件。
- AI 产物：Agent 生成文件的版本、预览、下载和转存动作。
- 代码仓库：关联仓库、分支、状态、diff、测试和受控提交入口。
- 项目知识：资料/代码派生的检索表示、同步状态和范围控制。
- 设置：成员权限、存储额度、安全策略和 Harness 连接状态。

## 核心流程

### 上传资料

用户在项目资料页或聊天附件菜单选择“保存到项目”。系统保存原始文件并返回逐文件结果；知识化是独立、可观察、可重试的后台任务。

### 项目聊天

新建会话时继承当前项目。系统默认提供项目知识，不把全部原文塞入提示词；代码访问限定在所选仓库，临时附件只在本轮使用，除非用户显式转存。

### 生成产物

Agent 生成文件后创建不可变版本，消息中显示产物卡片。用户可预览、下载、另存为项目资料或显式导入代码仓；导入代码仓必须展示目标路径和 diff。

### 修改代码

用户选择项目及目标仓库后启动执行。系统展示工具过程、变更文件、测试结果和 diff。只有具备提交权限的用户可批准 Git 提交；资料和产物不会被隐式提交。

## 权限与安全

- 所有资源继承项目访问权限，并记录创建者、来源、时间和审计事件。
- 服务端文件使用不透明 ID；下载、预览和引用均校验当前用户项目权限。
- 路径必须位于受控根目录；压缩包、预览 HTML 和 Office 转换沿用现有安全边界。
- 数据库连接只使用受控配置和只读优先策略，凭据不进入聊天、文件、日志或产物。
- 删除进入可恢复状态；Git 删除仍通过 diff 和审批呈现。

## 第一期范围

交付统一项目壳、项目资料、AI 产物、项目默认上下文、临时附件转存、现有多仓库入口整合和 Harness 状态提示。复用现有上传、预览、知识编译、聊天、Git 与权限能力。

暂不交付在线 Office 编辑、多人实时协作、任意本地目录全量同步、自动 Git 提交、数据库写操作和跨项目全局知识自动混用。

## 验收标准

- 用户可从一个项目页到达对话、资料、产物、仓库和知识，无需在多个中心重复选择项目。
- 项目资料上传后可预览、下载并用于项目聊天，且不会出现在 Git 状态中。
- Agent 生成的 HTML 至少可在浏览器内预览并下载原文件。
- 聊天输入区明确显示本轮上下文；关闭某来源后，本轮请求不再携带它。
- 未连接 Harness 时资料与产物能力正常；连接后才出现本地执行能力。
- 导入代码仓前展示目标仓库、路径和 diff；提交仍受现有权限与审批约束。
