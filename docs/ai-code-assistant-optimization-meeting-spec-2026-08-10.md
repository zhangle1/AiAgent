# AI 代码辅助工具优化 Spec（会议结论）

> 状态：待评审 / 不实施  
> 来源：CodeX / CodeDesk 使用体验、功能优化与测试推广会议  
> 目标：在安全受控前提下，将高频研发与排障场景的端到端效率提升至少 50%。

## 1. 背景与问题定义

当前工具已验证以下价值：

- 可在本地备份后完成局部修改，适合简单问题；
- 服务器端运行缓解了本地环境卡顿；
- 个性化、定制化代码问题的帮助效果优于标准业务问答。

但试用暴露出四类阻碍规模化使用的问题：

| 问题 | 表现 | 直接影响 |
| --- | --- | --- |
| 检索范围过大 | 复杂项目首次提问或模糊提问时全盘扫描 | 首次响应慢、Token 消耗大、定位不稳定 |
| 多模块同名混淆 | 不同端、不同项目存在相似业务功能 | 搜到无关代码，结论不可直接使用 |
| 多模型能力不一致 | DeepSeek 等非视觉模型不能直接理解报错截图 | 排障链路中断或长时间无效推理 |
| 代码交付流程不顺 | Token 重输、拉取入口深、未拉取即提交 | 提交失败、审核风险和使用挫败感 |

模板市场与跨项目引用不列为当前推广阻塞项。跨项目引用必须保留权限校验和受控上下文边界，但在完成核心检索与交付体验前不继续扩大功能范围。

## 2. 本轮目标与非目标

### 2.1 目标

1. 让 AI 在回答代码问题前优先获得项目结构和模块边界，降低全盘扫描比例。
2. 让用户可上传或引用 Markdown 业务资料、接口说明和日志摘要，作为受控上下文。
3. 为非视觉模型提供可选、可审计的截图 OCR 降级能力。
4. 缩短 Git 拉取、审查、提交的路径，并保留人工最终确认。
5. 建立分级权限、试点指标和复盘机制，验证 50% 效率目标。

### 2.2 非目标

- 不在本轮开放 AI 无人值守提交、强制推送或全员代码写入权限。
- 不自动解析 PDF、Word、Excel、PPT 等重型文档；首期仅支持 Markdown 上传/引用。
- 不把模板市场作为本轮核心改造对象。
- 不允许跨项目引用绕过项目授权、目录边界或仓库访问限制。
- 不将 OCR/Python 运行环境作为所有部署包的默认依赖。

## 3. 优先级与交付批次

| 优先级 | 能力 | 负责人建议 | 完成定义 |
| --- | --- | --- | --- |
| P0 | 项目 Agent Markdown 索引 | 开发负责人 | 已生成、可查看、可引用，且 AI 默认优先读取 |
| P0 | Git 拉取与提交前检查 | 开发负责人 | 拉取入口前置；提交前自动显示落后状态和差异 |
| P0 | Markdown 上传与聊天引用 | 开发负责人 | 仅允许授权项目和受控 `.md` / `.markdown` 文件 |
| P0 | OCR 能力开关与降级提示 | 开发负责人 | 非视觉模型可走 OCR；未配置时明确提示且不阻断文字聊天 |
| P1 | 模块/关键词检索引导 | 开发负责人 | 可按端、模块、仓库、关键词缩小范围并说明依据 |
| P1 | 日志与接口标识规范 | 各项目负责人 | 高频接口具备稳定业务标识，可被 AI 用于定位 |
| P1 | 夜间同步与索引刷新 | 运维 + 开发负责人 | 断网策略下可定时更新代码镜像与 Agent Markdown |
| P2 | 跨项目引用体验优化 | 开发负责人 | 仅在权限、上下文和引用价值验证后扩展 |
| P2 | 模板市场复评 | 产品 + 试点组 | 基于实际复用率决定保留、收缩或重构 |

## 4. 功能规格

### 4.1 项目 Agent Markdown 索引

每个已接入项目应维护一份由服务器生成的 Agent Markdown（建议命名 `AGENT.md` 或 `docs/ai-project-map.md`），用于让 AI 先理解代码边界，再决定是否搜索源码。

最低内容：

- 项目用途、运行端和主要技术栈；
- 受控目录树（忽略 `.git`、`node_modules`、编译产物、依赖缓存和密钥文件）；
- 入口文件、模块、接口、任务、打印/报表等高频业务入口；
- 模块与业务关键词映射，例如“派工 / 打印 / 调拨 / PDA / Web”；
- 代码版本、生成时间、提交号或同步时间；
- 维护提示：目录结构变更后需重新生成。

聊天编排规则：

1. 代码类问题先读取项目 Agent Markdown；
2. 用户提供端、模块或业务关键词时，将其作为搜索范围约束；
3. 无法从索引判断时，AI 必须说明将要搜索的仓库/目录，而不是默认全盘扫描；
4. 索引过期或不存在时，给出明确的刷新建议，不伪造项目结构。

### 4.2 夜间离线同步

在服务器夜间网络可用的窗口执行定时任务：

```text
拉取授权仓库镜像
  -> 记录提交号与拉取结果
  -> 生成或更新 Agent Markdown
  -> 更新代码索引状态
  -> 写入可审计任务日志
```

- 支持按项目启停、设置时间窗和失败重试；
- 断网、拉取失败或索引失败不得覆盖最后一次可用索引；
- 日间聊天默认只读取已同步的本地受控副本；
- 首期不要求开放互联网实时拉取。

### 4.3 Markdown 上传与引用

首期支持用户上传 Markdown 业务资料、接口说明、日志摘要或需求文档，并作为聊天上下文引用。

约束：

- 仅接受 `.md`、`.markdown`、UTF-8 文本；
- 设置单文件大小、字符数、单次引用数和总上下文长度上限；
- 上传文件归属项目和用户，按项目权限读取；
- 模型得到的是服务器读取、截断和标注后的内容，浏览器不能直接传入 Prompt；
- 文档正文按“不可信参考资料”边界注入，不可改变系统规则或获得工具授权；
- PDF/Word 等格式显示“暂未支持”，不隐式走高成本解析。

现有项目内 Markdown 搜索与引用设计见 [aiagent-project-markdown-reference-spec.md](./aiagent-project-markdown-reference-spec.md)。

### 4.4 截图 OCR 与模型路由

当用户选择不支持视觉输入的模型（例如部分 DeepSeek Profile）并上传截图时，界面必须明确显示当前能力状态：

| 条件 | 行为 |
| --- | --- |
| 原生视觉模型可用 | 传递受控原图；可选追加 OCR 文本 |
| 第三方模型且本地 OCR 已配置并启用 | 执行 OCR，将带边界的文本加入 Prompt |
| 第三方模型且 OCR 未配置/关闭 | 禁止或提示无法识图；仍允许发送纯文本聊天 |
| OCR 超时或失败 | 显示可重试原因，不阻断纯文本请求，不伪造识别结果 |

OCR 默认不随轻量部署包携带。需要 OCR 的环境显式使用 Python Worker 完整包并由管理员启用。模型、引擎、耗时、截断状态须写入审计元数据。详细安全边界见 [third-party-model-image-ocr-research.md](./third-party-model-image-ocr-research.md)。

### 4.5 精准检索与多模块消歧

聊天输入和提示词需要支持以下可组合的检索限定：

- 项目 / 仓库；
- 客户端或端类型：Web、PDA、服务端、桌面端等；
- 业务模块：派工、打印、调拨、入库等；
- 接口、类、文件、日志关键字；
- 当前代码版本或同步时间。

AI 的回答必须说明实际检索范围和命中依据。对于“调拨”等跨端同名词，未指定端时应先给出候选模块，请用户确认；禁止把另一项目或另一端的代码直接作为当前项目结论。

### 4.6 Git 交付体验与权限

Git 工作流调整为：

```text
选择项目
  -> 查看同步状态 / 一键拉取
  -> 查看本地修改和 AI 变更摘要
  -> 人工确认
  -> 创建提交
  -> 按权限推送
```

要求：

- 将“拉取最新代码”置于项目 Git 页面明显位置；
- 提交前检查工作区状态、当前分支、远端落后状态和冲突；
- Token 使用受保护的服务器端存储，失效时仅提示重新授权，不在聊天或日志中回显；
- AI 生成的变更必须可查看 diff，不能自动绕过确认；
- 默认角色只能生成分析、需求文档或 Markdown；
- 仅明确授权的资深测试/开发人员可执行提交或推送，且仍需人工确认。

## 5. 安全与审计边界

1. 项目、仓库、文档、跨项目引用和 Git 操作均以当前登录用户的授权为准。
2. 浏览器传入的路径、项目 ID、引用令牌和模型上下文只能作为候选；服务端必须重新验证。
3. 任何 AI 修改、提交、推送、OCR 处理、夜间同步均记录用户/任务、项目、时间、结果和失败原因。
4. 密钥、Token、数据库连接串和本地绝对路径不得出现在模型 Prompt、Markdown 索引、会话内容或普通日志中。
5. 跨项目上下文仅允许注入已验证的项目元数据或用户明确引用的受控文档；不授予读取/写入其他项目代码的隐式权限。

## 6. 测试与推广计划

### 6.1 上线前验证

- 用复杂老项目验证：首次提问、模糊问题、指定模块问题、跨端同名问题；
- 用报错截图验证：视觉模型、OCR 降级、OCR 未配置、超时四条路径；
- 用 Git 场景验证：已同步、落后、冲突、Token 失效、无提交权限；
- 用权限矩阵验证：普通用户、授权测试人员、管理员、无项目权限用户；
- 验证断网后的本地索引可用性与夜间同步失败恢复。

## 7. 指标与验收标准

“效率提升 50%”以端到端人力时间衡量，而不只比较模型 Token 或调用成本。每项试点任务记录人工基线、AI 辅助耗时、返工次数和最终结果。

| 指标 | 计算方式 | 首期目标 |
| --- | --- | --- |
| 高价值任务效率提升 | `(人工基线耗时 - AI 辅助耗时) / 人工基线耗时` | `>= 50%` |
| 首次可用定位时间 | 从发送问题到给出可验证文件/模块范围 | 复杂项目较当前显著下降，具体基线由试点首周采集 |
| 无关检索率 | 无关项目/端/模块命中数 ÷ 总命中数 | 持续下降，并纳入复盘 |
| AI 变更人工接受率 | 被人工确认合入的变更 ÷ AI 建议变更 | 试点阶段持续采集，不以绕过审核换取指标 |
| OCR 可用率 | 成功获得可用文本的 OCR 请求 ÷ OCR 请求 | 配置完整环境下建立基线后设定目标 |
| 安全事故 | 越权读取、越权提交、密钥泄露事件 | `0` |

## 8. 待确认决策

1. Agent Markdown 的固定文件名、生成入口和刷新频率。
2. 夜间同步可用的网络时间窗、仓库列表和失败告警渠道。
3. 首批具备提交/推送权限的人员名单与审批方式。
4. 试点任务的人工基线采集方法及“高价值任务”定义。
5. 视觉模型与 OCR 供应商的可用性、成本上限和网络合规策略。
