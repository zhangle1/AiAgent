# 聊天可视化第一版

本次实现收窄原 `doc/chat-visual-mode-design.md` 的范围，先验证聊天内生成图形的使用体验。

## 使用

普通聊天输入框顶部点击「可视化」或「图形」打开弹窗。卡片支持自动选择、架构、流程、时序、类图、ER、状态、思维导图、时间线、甘特和 Git 分支图；点击「使用此配置」确认，取消不改变当前配置。弹窗支持 Escape 关闭与键盘焦点约束。

先选择聊天项目，再在弹窗展开「勾选 Git 历史」：按仓库浏览本地当前分支历史，每页 50 条，可跨页、跨仓库勾选最多 20 条，单条移除或清空。选择项目或切换会话会清空选择；仅选记录而未输入问题时可直接发送。发送内容包含 SHA、父提交、作者、日期与摘要，不含代码差异，不证明对应功能已实现或验证。远端新记录需通过已有 Git 更新流程同步后才能看到。

输入问题，可结合现有项目、文档及附件入口选取资料，然后发送。图形使用现有 Mermaid 预览，点击放大；继续追问可生成完整新图。切回「文字」恢复原有提交行为。切换或新建会话默认文字模式。

## 接入边界

- 发送前一次性将问题与可视化要求组合为普通消息；组合后的全文可在聊天中看到并随历史保存。模式不是隐藏的系统指令。
- 原有聊天接口、模型选择、权限配置、停止、自动重试、断线处理均复用；没有额外模型调用或第二套任务状态。
- 自动重试使用已有请求快照；历史手工重试使用保存的消息，不根据当前工具栏重新组合。
- 输出为普通 Markdown 中的 Mermaid，旧图随旧消息保留，新回复生成新图。未建立独立产物、版本号或版本管理服务。
- 消息预览使用稳定的 pre 组件，避免周围消息重新渲染时卸载图形。渲染失败沿用原有错误提示和源码展示。
- 嵌入式原型等编辑器不显示此入口，也不包装其请求。未增加依赖或数据库字段。
- 新增 `GET /api/v1/code-repositories/projects/{projectId}/git/history?repository_name=...&skip=0`，沿用项目鉴权并校验仓库归属。服务端限制偏移量 0–10000，每页最多 50 条，使用已注册仓库路径及 Git ArgumentList，只读本地 HEAD，不获取凭据或执行 fetch。

提示要求仅分析、不改文件，但不会改变用户已有的代理执行权限；需要强制只读时仍须选择现有「只读分析」权限。图形内容和语法由所选模型生成，不保证每次都能正确渲染。

## 暂未实现

Git 双版本差异选择、其他会话消息选择、节点证据交互、Archify 渲染与 HTML 导出、独立产物归档。

## 验证

运行 `./node_modules/.bin/tsc --noEmit --incremental false`（在 front 目录）和 `node --test tests/chat-visualization.test.mjs tests/chat-file-links.test.mjs tests/document-diagram-preview.test.mjs`。
后端使用 `dotnet test backed.tests/AiAgent.Backend.Tests.csproj --filter FullyQualifiedName~GitHistoryTests`，在临时仓库验证空历史、分页、父提交与工作区不变。
人工验收：选择图形并取消/确认，跨仓库与翻页勾选，切换项目清空，发送及重试，图形放大与继续修改。测试不调用实际业务模型。
