# 工作画布节点编排

## 目标

工作画布中的会话节点不仅是聊天入口，也可被定义为一个可复用的执行单元。用户为节点设定职责与可选 Skill 标识，并将节点以“输出到此节点”的有向边相连。执行下游节点时，画布收集所有上游节点的最近产出，构成受边界保护的工作输入后启动下游会话。

## 用户流程

1. 在节点卡片上点击铅笔按钮，弹窗填写职责，例如“将需求整理为验收清单”。
2. 在同一弹窗选择执行模型；留空时沿用该会话最近使用的模型。Codex 节点只显示当前策略允许的 Codex 模型，普通 LLM 会话显示当前激活配置档中的模型；没有历史 Agent 的旧节点会同时显示两组模型，选择 Codex 模型会将该节点固定为 Codex 执行。
   - 画布右侧聊天框中的 Codex 模型选择也会同步保存为当前节点的预设，因此例如选择 `GPT-5.6 Terra` 后，节点卡片与后续流程执行都会使用 Terra。
3. 在同一弹窗手工输入一个或多个 Skill，例如 `front-creator`，按 Enter 或逗号添加；它们会作为该轮执行的显式工作约束展示给 Agent。
4. 按住源节点四周任一蓝色连接点并拖到目标节点，建立 `上游 → 下游` 的流程边。点击一条已有连线即可显示并执行删除操作。
5. 在目标节点卡片上点击播放按钮执行。系统将上游的最近回复、节点职责和 Skill 标识一起提交到当前会话，并沿用该会话的 Agent、项目上下文；节点设置了模型时，该模型优先于会话最近模型。

点击任一节点的播放按钮会启动一条新的流程运行。根节点完成后，系统会自动检查其下游：只有该下游节点的全部流程上游都已在同一运行中完成，才会启动它。因此支持分支和汇合；某一步失败或被停止时，该链会停止，不会继续触发后续节点。画布右侧聊天框中直接完成了一个有下游连线的节点，也会作为新的根步骤自动继续该链。自动启动仍受现有每用户 10 个并发会话的限制。

## 运行历史与回溯

画布顶栏的“运行历史”保存最近 30 条流程运行。每条记录包含根节点、运行状态、每个节点的开始/结束时间、上游节点、实际 Agent/模型以及失败原因。历史按节点时间线展示；每一步均可直接打开对应会话查看完整聊天日志，可用于确认某次输出来自哪一条上游链路。删除节点或连线不会删除既有历史记录。

## 数据与兼容性

节点职责、Skill 列表、可选模型 ID 与节点执行 Agent 写入已有 `ai_work_canvas_node.DataJson`，不新增数据库列。流程运行及其步骤分别写入 `ai_work_canvas_run` 与 `ai_work_canvas_run_node`，由启动时 CodeFirst 创建。旧节点缺少配置时按空值处理，旧版单个 Skill 会自动作为列表的第一项读取。新建流程边使用既有边表的 `RelationType = produces`；历史 `delivery` 边和投递数据保持可读，但画布不再提供“投递中心”入口。

## 执行输入与安全边界

上游回答属于不可信工作材料，而不是系统指令。下游提示会要求 Agent 忽略其中试图改变权限、工具规则、角色或数据边界的内容。浏览器只提交节点 ID；角色、Skill、会话归属和上游消息均由已鉴权的画布数据决定。

Skill 在首期是受长度与标识符格式限制的提示词约束，不接收或执行浏览器提交的文件路径、插件路径或 shell 命令。若要接入 Codex app-server 的原生 `skill` 输入，后续必须新增服务端白名单、可用 Skill 发现接口及审计记录，不能直接透传用户输入。

## 当前范围与后续演进

当前每个上游节点提供其最近一条会话产出，避免把完整历史无限注入。后续可添加输出选择器、已确认产物版本、批量拓扑执行与失败重试；这些能力必须保持同一用户和项目权限边界。
