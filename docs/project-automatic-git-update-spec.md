# 项目自动重置更新规格

## 目标

管理员可在“代码库”的项目卡片中，为一个项目启用定时“重置更新”。可设置间隔小时数，并查看上次尝试、上次完整成功和最近结果。项目范围仅是已登记且归属该项目的代码库。

## 安全条件

自动任务不会无条件丢弃本地修改。对每个 Git 代码库先读取工作区状态：

1. 无本地变更时，可继续执行。
2. 有本地变更时，只有**所有**变更文件的最后写入时间均早于当前时间 3 小时才可继续执行。
3. 删除文件、子模块、无法取得时间或路径解析异常视为不安全，跳过该仓库。
4. 有任一文件在近 3 小时内修改，跳过该仓库；不执行 `reset --hard`。
5. 远端刷新失败、无上游分支、非 Git 仓库也跳过。可执行的仓库按既有语义运行 `reset --hard HEAD` 后 `pull --ff-only`；未跟踪文件不删除。

项目的“上次完整成功”只有当本轮所有可管理 Git 仓库均成功更新时才写入。任何跳过或失败均保留上次完整成功时间，并记录简短最近结果。

## 调度与并发

后端每 5 分钟检查已启用项目；当从上次尝试起已达到管理员配置的间隔（1–168 小时）才开始一轮。启动即进行一次检查，因此过期任务不需要等到下一个整点。任务在单进程中串行，且复用项目与仓库 Git 操作锁，避免与聊天页的手工 Git 操作并发。

调度运行时仅使用代码库已经绑定的 Git 账号；没有绑定账号的仓库依赖服务器既有 Git 凭据，认证失败会安全跳过并报告。访问令牌仅进入 Git 子进程环境，绝不写入日志、数据库结果或 HTTP 响应。

## 管理与 API

仅管理员可以读取或保存自动更新配置：

- `GET /api/v1/code-repositories/projects/{projectId}/git/auto-update`
- `PUT /api/v1/code-repositories/projects/{projectId}/git/auto-update`

配置包括 `enabled` 和 `interval_hours`。项目列表同时返回运行状态字段：启用状态、间隔、上次尝试时间、上次完整成功时间、最近结果。普通用户即使能访问项目，也不能读取或变更此计划。

## UI

项目卡片仅对管理员展示“自动重置更新”设置。设置窗显示风险说明、启用开关、间隔选择与时间/最近结果；保存只修改计划，不会立即重置代码。窄屏对话框可滚动，控件全宽。项目无 Git 仓库时仍可保存但调度会记录无可处理仓库，不执行写操作。

## 验收

1. 管理员启用间隔后，到了周期会按项目检查并批量更新。
2. 任一仓库存在近 3 小时变更、删除项或无法取时间时，该仓库不重置；最近结果能说明原因。
3. 所有变更均超过 3 小时且远端/上游正常时，按已有 fast-forward 更新逻辑执行。
4. 普通用户无法调用自动更新 API，也不显示设置入口。
5. 并发手动操作与定时任务不会同时对同一仓库执行 Git 命令；凭据不泄露。
