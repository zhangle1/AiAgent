## 二、主要工作与成果

### 1. 修复 HTTP 局域网下知识聊天无法发送

- 定位 `crypto.randomUUID is not a function`：知识聊天面板直接使用仅在部分浏览器环境可用的 API，异常发生在请求发出前，还可能留下阻止后续发送的活动状态。
- 消息 ID 改为兼容生成：可用时使用原生 UUID，不可用时使用时间戳与模块内递增序号。用户、助手及目录命令结果统一处理。
- 在登记活动请求和 React 状态更新器之外生成 ID，避免异常留下发送锁，以及状态更新重复执行时重新分配 ID。
- 浏览器测试禁用该 API 后复现原错误，修复后问答、目录命令、编译结果、停止与再次发送均通过。

### 2. 修复 L2 已保存后语义阶段的数据库连接问题

- 根据截图区分正文解析与语义生成：正文 L2 已成功保存，失败发生在后续 L0/L1 阶段，错误为 ExecuteReader 使用了已关闭的连接。
- 模型目录 `Load/Save/Apply` 改用每次操作独立的 `CopyNew()` 数据库客户端，读取和事务写入不再直接使用共享根客户端。
- 事务内的 Profile、Model 和设置快照写入使用同一个操作客户端，保持原有保存与脱敏规则。
- 增加根客户端不可用、独立客户端仍可工作的回归：修复前失败，修复后加载、保存、应用均通过。该测试验证连接隔离边界，不等同于真实 SQL Server 并发复测。

### 3. 增加编译产物目录与树状资源选择

- 编译弹窗可选择已有资料、项目或本人原始目录，默认仍保存到“人员 → 我的工作区 → 摘要”。
- 显式选择后，文件摘要和目录 L0/L1 保存到目标目录的 `_compiled/`，树上显示“编译产物”；产物文件 URI 包含来源文档 ID，避免同名原文件覆盖。
- 原文件和解析正文保留原位置；知识摘要页列出可见的关联产物，便于找到编译结果。
- 编译来源改为可过滤的资源树，支持跨可见目录选文件，最多 32 个；过滤不会清空已选内容，生成产物不能成为编译来源。
- 命令目标增加树状选择与文件筛选；添加资源弹窗也提供目录浏览，上传和建目录使用所选父目录，不依赖当前预览文件的位置。
- 校验跨用户目录与生成目录，个人原始资料禁止发布到公共目录。资料 / 项目沿用已有公共资源可见范围，不新增项目授权体系。

### 4. 增加可选择、生成和编辑的编译技能

- 预置 `llm-wiki/SKILL.md`，用于文件知识摘要、目录 L1 概览和 L0 简介，保留主要语言、实体、业务规则、参数、来源与不确定性。
- 内置技能以明确资源名嵌入后端程序集，部署时不依赖当前工作目录查找文件。
- 新增技能对话弹窗：选择已配置 API 模型，描述需求、多轮调整，检查或手动编辑名称、说明和指令，再保存并直接用于编译。
- 自定义技能按本人设置快照持久化，保存完整 Markdown；其他用户不能读取、修改或选用，内置技能可以另存为个人技能。
- 任务入队前按服务器身份解析技能 ID，客户端指令不能覆盖已保存技能；目标、技能指令、模型和预算一起冻结到任务 `ConfigurationJson`。
- 修改技能不影响已入队任务，任务中心重试保留原快照。技能仅是提示文本，不执行脚本或扩大工具权限。
- 目录缓存指纹包含已发布子文件摘要，后续文件完成后更新目录概览；当前任务不会用自己的技能替其他待处理文件生成摘要。

### 5. 改为自动预算，修复中文输出误判

- 精确复现“KnowAgent 模型输出超过预算”：原逻辑把中文输出的 UTF-8 字节数当作供应商 token 数，与 8192 比较，导致正常返回被误拒绝。
- 移除该输出字节比较和语义 Markdown 的固定 12000 字符拒绝条件；输出请求采用供应商默认策略，不再额外发送固定 8192 的 `max_tokens`。
- L0/L1 使用所选模型配置窗口，取消固定 32000 输入封顶、16000 分段与 256000 正文字符限制。超出窗口自动分段、归并，计入 JSON 转义开销并保留完整 Unicode 内容。
- 新编译任务调用次数默认 0（不限），可手动设置正整数；设置页也支持 0，移除原 96 次上限。已有显式设置和历史任务快照保留。
- 输出预留只用于分配输入空间，不作为生成文本硬上限；输入 token 用量仍是保守估算。
- 超时、取消、压缩不收敛和供应商真实 `finish_reason=length` 截断继续明确报错，不把未完成响应当作成功。
- 独立的证据型 Wiki 草稿协议仍保留原字符、证据分段及字段校验；此次大窗口分段调整针对 L0/L1 语义编译。
