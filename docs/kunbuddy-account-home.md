# KunBuddy 登录首页与会话恢复

## 用户流程

客户端启动后先检查坤伴登录。未登录显示首页，填写平台 URL、用户名和密码，成功后自动同步订阅模型、刷新本地模型列表并进入工作区。首页与“设置 → 模型 → 坤伴订阅”使用相同主进程登录服务，不重复维护凭据。已有订阅会在升级后通过平台模型目录检查恢复，无需删掉重建。

平台返回的有效期到达、凭据缺失或平台会话检查返回 401 时，自动返回首页并显示过期提示，保留本地会话、平台地址和用户名，密码保持为空。重新登录更新同一账号的订阅配置，不新增重复档案。退出账号后同样回到首页。

首页沿用现有主题、品牌和共享表单控件，桌面使用介绍／登录两列，窄屏改为单列；窗口拖动与最小化／关闭控件保持可用。登录失败在表单内显示，不跳入工作区。

## 登录状态边界

- `KunBuddyAccount` 运行在 Electron 主进程，通过 Rust RPC 读取订阅公开配置及加密凭据；新增 IPC `kunbuddy/account/status` 只接受主窗口。
- `kunbuddy-account.json` 只保存当前平台地址、账号、有效期与退出标记，不保存密码、令牌或聊天正文。有效期无效时不创建计时器。
- `GET /api/v1/kunbuddy/models` 作为平台会话检查，不调用生成模型。首次进入、窗口恢复焦点、可见性恢复、Agent 错误／结束以及每 30 秒检查，已知有效期另设到期检查。
- 只有平台登录检查的 401 判定凭据失效；通用上游模型错误不会直接触发过期跳转。已登录且未到期时，临时网络／服务错误保留工作区；冷启动无法确认登录时显示首页网络提示和重试入口。
- 登录与检查按主进程队列串行，渲染层合并检查并忽略旧结果。首页登录期间先更新模型设置和本地目录再显示工作区。
- 首页是客户端交互入口，平台 API 权限仍由服务端认证决定；本地 Rust RPC、插件权限和远程主机授权边界保持原有实现。

既有会话原文同步保持不调用 LLM、不自动解析／编译；本轮登录检查同样不发模型生成请求。

## 验证与交付

用户于 2026-10-22 明确授权本轮专项测试、构建和隔离界面验证。测试使用合成账号、临时数据与回环 HTTP 服务，不读取真实用户配置、密钥或数据库。本轮没有后端业务代码修改，复用既有 Rust host 二进制。

专项入口：`client/apps/desktop/test/kunbuddy-account.test.mjs`、订阅及同步回归、主窗口 IPC 检查。真实 Electron 端到端入口为 `client/scripts/e2e-kunbuddy-account-home.mjs`，要求显式提供隔离目录 `KUNBUDDY_ACCOUNT_E2E_DIR`。该驱动覆盖新安装首页、错误密码、登录同步、模型设置可见、重启恢复、服务端撤销、到期跳转、原订阅更新、本地会话保留、临时服务失败、退出及 420px 窄屏。

构建、类型检查、测试结果及截图指纹见 `kunbuddy-account-home.changeset.json`。生产平台连接和真实模型服务未作为本轮测试对象；运行证据不代表已经部署或提交。原有无关代码库、Git 和部署脚本修改保留。
