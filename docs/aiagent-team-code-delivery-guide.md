# AiAgent：让团队在受控代码库中借助 Codex CLI 完成改码与 Git 交付

AiAgent 是面向内网研发团队的 AI 工作台。它把项目目录、代码库、聊天、Codex CLI 和 Git 操作放在同一个受控流程中：业务人员可以用自然语言说明需求，开发人员可以在平台内查看改动、运行项目、核对 Diff，并将确认后的修改提交到既有 Git 仓库。

它的目标不是让 AI 绕开研发流程直接“写完上线”，而是缩短“提出需求 → 定位代码 → 修改 → 验证 → 提交 → 交付”的协作链路。

## 适合哪些团队

- 有多个内部项目、代码仓库和协作成员，需要统一登记和授权。
- 希望业务或实施人员能描述需求、参与确认，但不希望他们直接登录服务器或操作 Git 命令。
- 希望开发人员使用 Codex CLI 处理跨文件理解、修复和重构，同时保留标准 Git 交付方式。
- 需要把知识库、模型配置、会话记录、项目权限和用量统计集中到一个内网工作台。

## 核心价值：把 Codex CLI 放进可管理的研发闭环

### 1. 在选定项目中启动 Codex，而不是把整台服务器交给 AI

用户先在平台中选择已经授权的项目，再选择 **Codex 接管**。后端以该项目根目录作为 Codex CLI 的工作目录，启动：

~~~
codex app-server --stdio
~~~

随后把用户的问题、必要的上下文和已上传的截图传入 Codex。执行过程中的回答、命令轨迹和文件修改结果会实时回传到聊天界面，便于发起人和开发人员共同查看。

这使得 Codex 能够使用其擅长的代码检索、跨文件理解和修改能力，同时避免用户在浏览器里直接操作服务器终端。

### 2. 用 Git 把 AI 修改变成可审查、可交付的变更

平台登记的代码库可查看当前分支、远程领先/落后状态、工作区 Diff 和待提交文件。确认修改后，团队仍按熟悉的 Git 流程完成交付：

~~~
需求说明
  → Codex 在选定代码库中分析与修改
  → 团队查看文件变化与运行结果
  → Git Diff 审查
  → 填写提交说明
  → 提交并推送到远程仓库
~~~

因此，AI 的输出不会成为一段难以追踪的聊天记录；它会沉淀为 Git 中可比较、可回滚、可走 Pull Request 或发布流程的提交。

### 3. 让业务、实施和开发人员在同一处协作

- **业务/实施人员**：描述问题、提供页面截图、确认结果，不必理解服务器目录或 Git 命令。
- **开发人员**：选择受权项目，审查 Codex 的定位和改动，运行单个代码库或项目内全部运行配置，再决定是否提交。
- **管理员**：创建用户、分配可访问项目、查看历史会话和用量，控制谁可以使用哪些项目。

## 如何降低源码暴露面

AiAgent 的设计重点是缩小平台层的暴露面，而不是承诺“代码永不离开服务器”：

- 代码库仍保存在服务器受控目录中；浏览器不会直接获得服务器路径或目录浏览权限。
- 管理员为用户分配项目范围；项目选择、聊天请求和代码库操作都受同一套项目访问校验约束。
- 聊天中可编辑的配置文件需要在代码库中明确勾选；保存时会检查文件版本，避免覆盖他人刚刚修改的内容。
- 上传给 Codex 的图片先由后端校验格式、大小、数量和当前用户归属，再以受控附件路径传给本地 app-server；浏览器不能提交任意本机路径。
- Git 账号由平台统一管理，团队可通过分支、Diff、提交记录和远端仓库继续审查交付。

> 重要边界：当 Codex CLI 或其他模型服务读取代码并请求其上游模型时，相关内容是否会离开内网取决于所选模型提供方、账户、网络策略和企业协议。生产部署应只挂载允许被 AI 处理的代码项目，并结合企业账号、网络出口、密钥管理和审计策略评估合规性。

## 推荐的团队使用流程

### 第一步：管理员完成环境准备

1. 配置模型服务、知识库和 Git 账号。
2. 在服务器允许根目录中登记项目与代码库。
3. 为每位用户分配可访问项目。
4. 为需要 Codex 接管的服务器账户安装并登录 Codex CLI，确保该账户可以执行 **codex app-server --stdio**。

### 第二步：开发人员登记运行与发布入口

一个项目可包含多个前端或后端代码库。开发人员可为每个代码库登记：

- 解决方案、工程文件或前端 package.json；
- 可由聊天读取或编辑的配置文件；
- 前端/后端启动入口、测试脚本、端口和健康检查路径；
- 发布目标、构建配置、运行时和输出目录。

这样，平台在“项目程序运行”中只展示经确认的入口，避免 AI 或非技术用户猜测命令、端口和文件路径。

### 第三步：在聊天中处理需求

1. 选择项目和代码库。
2. 用自然语言描述问题；需要时附上页面截图。
3. 对复杂代码任务选择 Codex 接管。
4. 关注聊天中的分析、工具调用、文件修改和错误信息。
5. 运行受控的项目配置，结合页面、日志或测试结果确认改动。

### 第四步：通过 Git 交付

1. 打开 Git 管理页面，刷新代码库状态。
2. 查看工作区、待推送或待拉取的 Diff。
3. 确认没有混入本地配置、密钥、构建产物或无关文件。
4. 填写清晰的提交说明，提交并推送。
5. 后续仍可在远端仓库按现有分支、评审和发布制度继续流转。

## 当前能力概览

| 领域 | 团队可获得的能力 |
| --- | --- |
| 项目与代码库 | 服务器目录授权、项目分配、代码库登记、配置文件白名单、运行和打包入口 |
| Codex CLI | 以选定项目为工作目录接管聊天任务，流式回传执行过程、回答和文件修改状态 |
| Git 协作 | Git 账号、克隆、状态、分支、Diff、拉取、提交和推送 |
| 聊天与知识 | WebSocket 优先的实时对话、截图附件、知识库导入、索引、检索和问答 |
| 运行管理 | 单代码库或项目全部运行、端口隔离、进程状态和强制结束 |
| 管理与审计 | 用户与项目授权、历史会话、Token 用量统计和管理员视图 |

## 当前阶段与路线图

### Codex CLI 是复杂代码任务的优先通道

目前，Codex CLI 接管适合需要理解既有工程、定位多个文件、修改代码并配合 Git 交付的任务。平台负责项目授权、会话入口、执行状态和 Git 协作，Codex 负责代码工作本身。

### 自有 Agent Loop 仍在持续优化

AiAgent 的自有 Agent Loop 已能够完成常规对话、工具调度、知识库检索和流式反馈，但在复杂代码任务上仍需继续强化：

- 更稳定的任务规划、工具选择与失败恢复；
- 更精确的代码上下文检索和引用管理；
- 自动化验证、测试结果理解与修改后的闭环确认；
- 更完整的执行可观测性、成本控制和人工接管体验。

在这些能力成熟前，建议将高风险或跨模块的代码改动交给 Codex CLI，并保留开发人员审查和 Git 交付环节。

### 下一阶段：完善团队记忆

路线图的重点是增加并完善记忆能力，让平台能在用户和项目范围内保留经过筛选的长期上下文，例如：

- 项目架构决策、约束、编码规范和常见问题；
- 用户偏好、历史任务结论和会话摘要；
- 可审计的原始观察记录与可复用的结构化记忆；
- 按项目、用户和权限范围检索，并在后续对话中注入有限、相关的上下文。

记忆不会替代 Git、知识库或人工判断。Git 仍负责可追溯的代码历史，知识库负责原始文档检索，记忆用于保存对后续协作有价值的结论、规则和上下文。

## 使用原则

1. **先授权，后接管**：只登记并授权允许 AI 访问的项目。
2. **先审查，后提交**：把 Codex 的修改视为待审查的工作区变更，而不是自动上线结果。
3. **Git 是交付事实来源**：以提交、分支和远端评审记录作为最终交付凭证。
4. **配置与密钥不进代码**：不在聊天、README、提交记录或截图中暴露密码、Token、API Key 和真实连接串。
5. **逐步扩大范围**：先从低风险项目和明确任务开始，积累流程、权限和审计经验后再扩展。

---

AiAgent 的价值不在于替代开发人员，而在于把 AI 的代码能力嵌入团队已经熟悉的项目权限、运行验证和 Git 交付制度中，让协作更快，同时保持工程变更可见、可控、可追溯。
