# 失效历史记录预览与清理

## 使用

知识工作区目录栏「文件处理」旁的清理图标打开「清理失效记录」。点击不可用文件时，预览区会显示原因，并提供「扫描并清理失效记录」入口。

1. 扫描并检查文件名、知识 URI 和失效原因。
2. 勾选要移除的记录，也可全选可清理项，每次最多 500 条。
3. 勾选确认，再点击「确认清理」。成功后目录刷新。
4. 扫描或清理失败时保留界面提示；资料或任务状态改变后需要重新扫描并重新确认。

清理采用数据库软删除，保存删除时间。源文件、解析文件、个人派生缓存、原始聊天、任务及审计记录均保留。被清理来源及依赖来源可见性的生成节点不再展示；后续可重新导入，或由维护人员核对后恢复软删除记录。此操作不是物理磁盘空间回收，不更改 RAG 活动索引。

切换 `KnowledgeStorage:RootPath` 不会自动迁移已有 `StoragePath`。旧路径越界时应先决定迁移资料还是移除失效记录；服务端继续拒绝读取旧根目录之外的正文。

## 状态与权限

`KnowledgeSourceFile.Inspect` 先验证绝对路径和当前知识库根边界，再检查文件及祖先的链接属性，不打开正文。目录树继续使用元数据；读取原始资源或显式扫描清理列表时检查原文件，状态随读取响应中的资源节点返回：

| source_status | 含义 | 清理 |
| --- | --- | --- |
| available | 受控路径内的原文件存在 | 不列入清理 |
| outside_root | 历史路径位于当前存储范围之外 | 可预览后移除记录 |
| missing | 文件或父目录缺失 | 可预览后移除记录 |
| invalid_path | 空路径、相对路径或无法规范化 | 可预览后移除记录 |
| unsafe_path | 路径包含符号链接或 junction | 可预览后移除记录，保留链接及目标 |
| unreadable | 权限或存储 I/O 错误导致检查失败 | 阻止清理，先恢复目录访问 |

缺失文件不再因 `FileInfo.Attributes == -1` 被误判为符号链接。页面读取不可用的原始资源返回包含节点状态的正常响应，不调用正文提取或模型，不返回真实磁盘路径。生成产物继续使用其原有读取校验。

清理必须有有效网页登录身份。普通用户限本人原始资料；管理员额外管理资料／项目下的共享来源。管理员查看他人会话的权限不包含清理权限。生成目录和 Wiki 不作为清理输入。

存在排队、执行、取消中任务，或文档仍处于处理状态时，清理项被禁用。执行接口再次检查权限、来源状态和活动任务，复核包含身份、存储根、记录内容和清理状态的 SHA-256 指纹，并在短事务内执行带版本条件的更新。任意项失败回滚整批。记录和文件没有自动硬删除，后台解析也沿用原有来源存活校验。

## HTTP 契约

| 方法 | 路径 | 数据 |
| --- | --- | --- |
| GET | `/api/v1/knowledge-resources/cleanup/preview` | 返回 `items`、`snapshot_sha256`、`includes_shared`；只读扫描 |
| POST | `/api/v1/knowledge-resources/cleanup` | 请求 `{document_ids, snapshot_sha256}`；返回 `{removed_count}` |

客户端不提交物理路径。失效项只包含文档 ID、文件名、逻辑 URI、原因和是否允许清理。

清理 POST 使用显式空模板 `[HttpPost("")]`，准确匹配控制器根地址。Furion 会为无模板的 `[HttpPost]` 追加动作名称，导致注册为 `/cleanup/cleanup`，前端调用 `/cleanup` 时返回 404。接口不可用时界面提示更新并重启后端，再重新扫描；失败后需要重新确认列表才能提交。

预览与清理请求因浏览器断开而取消时，服务在鉴权及清理边界内部处理并返回 HTTP 499，无错误正文；写入阶段取消会回滚整批。正常响应结构不变，未登录、客户端仍连接时的内部取消及真实异常继续上报。保留前端卸载取消请求的行为，不通过关闭调试器异常设置处理。详见 `knowledge-request-cancellation.md`。

## 验证

后端隔离 SQLite 和临时文件测试覆盖旧根目录、缺失文件、无效路径、本人／他人隔离、管理员共享范围、正常文件保护、活动任务、扫描后恢复文件／新增任务／记录变化、伪造 ID 和事务失败回滚。旧异常已在修复前通过实际资源读取调用复现。

前端 `front/tests/knowledge-cleanup.browser.mjs` 运行真实 React 页面并拦截全部 API 为合成响应，验证按钮入口、不可用提示、活动任务禁选、显式确认、失效快照、重新扫描、成功后树刷新、空态、失败态、Escape／焦点恢复和 390px 布局。测试依赖放在临时工具目录，不修改项目依赖。

`backed.tests/KnowledgeCleanupHttpTests.cs` 启动隔离 HTTP 服务，使用正式 Furion 路由注册与真实清理服务，通过浏览器使用的精确地址完成 GET 预览 → POST 清理 → 核对隔离数据库软删除。该测试在原无模板 POST 上复现 404，显式模板修复后通过。浏览器测试额外覆盖 HTTP 404 提示、重新扫描恢复和随后成功提交。

`KnowledgeCleanupCancellationTests` 通过正式清理控制器和服务验证 HTTP 499，以及鉴权等待、上下文清空和锁等待中的断开；已取消请求还检查不产生 `TaskCanceledException`。隔离 SQLite 测试在软删除执行后触发取消，验证提交前检查可回滚记录。

没有对真实数据库执行扫描或清理，也未删除用户旧文件。后端需重新编译启动；本地变更集仅用于审阅，未提交或推送。
