# KnowAgent 与个人知识产物

## 资源和产物归属

原始文件及 L2 解析正文仍在知识库的 raw / parsed 存储中。用户触发解析时，任务保存服务端解析的 `OwnerRoot` 与 `ParseOnly`；后台执行不依赖发起请求仍然存活。相同用户、文档的活动任务去重，不同用户分别生成，取消和重试校验归属。

共享资料 `viking://resources/docs/a.md` 的个人摘要映射为 `viking://user/<用户>/summaries/resources/docs/a.md`，项目资料保留 projects 分组，本人上传资料使用 personal 分组。仅纳入本人已提交任务的可见来源；父目录自底向上汇总到本人根目录，不进入其他用户或人员总目录。

语义文件保存到 `.user-workspaces/<用户根 URI 哈希>/semantics/<产物 URI 哈希>/`，沿用不可变版本与原子 manifest。来源哈希、解析正文哈希或可见来源集合变化会使缓存失效。摘要带宿主生成的来源链接，下载返回生成内容。原始 URI 的下载仍返回原文件。

Wiki 草稿在 `AiKnowledgeArtifact.OwnerRoot` 记录归属，数据库保留内容与逐段原文证据；Markdown 副本在 `.user-workspaces/<用户根 URI 哈希>/wiki/<内容哈希>.md`。文件先写临时文件再原子发布；数据库保存失败可能留下无引用副本，不会在目录中显示。个人 Wiki 通过目录树、知识页列表、正文接口和上下文树读取时均限制归属。原有知识库的提炼入口继续生成 Wiki；资源目录的「重新解析」继续生成 L2 与 L0/L1。

工作区 summaries / wiki 为生成目录，拒绝新上传和手工建目录。来源删除后，其生成节点不再出现在资源树；目录缓存不再声称最新。Wiki 仍为待核对草稿，不改变 RAG 活动索引。

## KnowAgent 边界

`KnowAgent/KnowAgent.cs` 负责统一执行预算与已有知识压缩；`ContextBudget.cs` 负责 Unicode 安全分段和完整提示的容量检查。`Core` 保留两阶段分析、逐段生成、证据精确匹配和语义归并算法。`KnowledgeModelAdapter` 仅连接既有 LLM API / Codex 通道，CLI 使用独立只读运行目录。

LLM API 使用模型目录提供的 context window；Codex 使用应用侧 65536 的保守窗口。输出预留为窗口的四分之一，最高 8192，另预留 4096 给系统指令和协议。以 UTF-8 字节数估算 token 上界，属于保守估算，非供应商 tokenizer 的精确计费。未知 API 模型沿用平台默认窗口。模型窗口太小或完整提示仍超限时，在调用前报错，不截断证据。

正文按预算分段并覆盖全部内容；最多 256000 字符，Wiki 最多 32 个证据分段。已有 Wiki 上下文过大时递归压缩，目录摘要分批归并；压缩不收敛、输出超限、调用预算耗尽或取消均显式终止。压缩与分析、生成、修正共用一次任务的调用上限，Wiki 原文证据仍须精确匹配，不以压缩文本代替证据。

生成调用进度和错误通过原任务队列展示。正文保存后发生语义失败，原始文件和解析正文仍可读取；已经完整发布的摘要在重试时可复用。任务模式持久化，重试沿用原模式。

## 历史兼容与验证

新实体列均可空，随现有 CodeFirst 初始化建立。历史无 OwnerRoot 的 Wiki 保持公共读取；不会推测历史发起者。旧任务保留在数据库，个人任务列表只显示明确属于本人的任务；旧资料可在资源树重新解析。旧公共语义缓存不复制到个人空间，重建不修改原文件。

没有 HTTP 身份的既有本地模式沿用 `current` 工作区；后台任务以入队快照为准。此改动沿用原资源可见性规则，不新增公司或项目授权体系。

验证使用临时 SQLite、临时文件及假模型，不访问真实资料和在线模型：Unicode 全文覆盖、输入及调用预算、个人语义落盘和失效、下载生成文件、跨用户任务拦截、Wiki 多入口隔离、语义失败后正文可读、缓存重试。前端执行 TypeScript 检查。真实 Codex / LLM 连通性需要部署后的配置环境验证。
