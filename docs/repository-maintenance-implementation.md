# 代码库养护实施与验收

日期：2026-09-09

## 使用入口

左侧“工作画布”下方新增“代码库养护”，地址 `/repository-maintenance`。

1. 选择已登记代码库的项目。本轮覆盖该项目下所有未删除仓库。
2. 选择“理解代码并给出建议”或“优化代码并编译验证”，填写目标、模型、执行时限及文件预算。
3. 保存后点击“立即执行”；或开启自动执行并设置 1–168 小时的间隔。
4. 编译通过的优化任务等待用户点击“批准并推送”，逐次批准后推送本轮分支。

设置修改后必须保存再执行。运行记录每 5 秒刷新，展示报告、编译和 Git 日志、变更集编号、目标分支，支持停止排队或运行中的任务。设置和执行都要求项目访问权限及代码提交权限。

## 执行链路

`queued → preparing → analyzing → building → ready → push_queued → pushing → delivered`

分析模式在生成报告后直接进入 `completed`；无改动的优化任务也进入 `completed`。异常、取消、进程失联分别进入 `failed`、`cancelled`、`interrupted`。

- 服务端每 5 秒检查到期计划，任务写入数据库；浏览器关闭后继续执行。
- 创建独立远程克隆，基于登记仓库当前分支创建 `maintenance/<runId>`。用户原工作区中的未提交内容不会进入副本。
- Codex 使用服务端专用工作目录。该目录参数带 `JsonIgnore`，浏览器不能通过聊天 JSON 指定。
- 分析使用只读模式，优化使用工作区可写模式；服务端负责后续编译和交付。
- `.csproj` 执行 `dotnet build`，包含 `Microsoft.NET.Test.Sdk` 的项目继续执行 `dotnet test --no-build`。
- 含 build 脚本及 `package-lock.json` 的 npm 项目执行 `npm ci`、`npm run build`。没有支持的编译目标则阻止交付。
- 最多修改 1–100 个文件，禁止配置密钥、运行数据及依赖目录；检查路径越界与符号链接。
- 编译前后比对快照，通过后创建 `AiCodeChangeSet` 及仓库明细。推送前再次比对快照、基线、分支与远程状态。
- 编译通过后保留待批准状态，由有提交权限用户逐次批准。只推送独立养护分支，不自动合并。兼容保留的 `auto_push` 字段必须为 false，旧版自动推送计划在执行前会被拒绝。
- 数据库事务将项目执行锁和排队记录一起提交，防止半写入。手动、定时和推送任务共享项目锁；取消排队任务时不会启动 Codex 或 Git。
- 运行中每 2 秒检查取消与权限；进程失联任务超出 130 分钟后标记中断，不重放可能已经完成的远程写入。

## API 与数据

统一前缀：`/api/v1/projects/{projectId}/maintenance`。

| 方法 | 相对路径 | 用途 |
| --- | --- | --- |
| GET | 空 | 读取计划 |
| PUT | 空 | 保存设置 |
| GET | `/runs` | 最近 50 次运行 |
| POST | `/runs` | 手动排队 |
| POST | `/runs/{runId}/cancel` | 请求停止 |
| POST | `/runs/{runId}/push` | 批准编译快照并排队推送 |

启动时创建 `ai_repository_maintenance_plan`、`ai_repository_maintenance_run` 表。副本位于服务端 DataPath 下的 `repository-maintenance/<runId>/<repositoryId>`。

## 回归重点

`backed.tests/RepositoryMaintenanceTests.cs` 覆盖设置更新、重复执行互斥、排队取消、推送占锁、权限、路径越界与保护文件；本地临时 bare Git 仓库验证快照变化阻止推送、成功推送只更新养护分支、源文件和基线分支不变。

验收中修复了公共 Git 执行器对 `-z` 输出调用 `Trim()` 的缺陷：首条未暂存记录以空格开头，去除后文件路径错位，导致快照漏掉真实文件内容。现在保留 NUL 协议的首尾字符，测试明确断言解析到的文件名及变更后的拦截结果。

## 当前边界

本次验证：后端编译、前端 `npm run build`、`npx tsc --noEmit`、`git diff --check` 通过；养护专项 16/16 通过。全量后端测试 36/38 通过，两个既有 `UsageStatisticsServiceTests` 在 SQLite 建表阶段报 `AUTOINCREMENT is only allowed on an INTEGER PRIMARY KEY`，不涉及养护执行链路，未改动该统计模块。

运行详情支持导出 Markdown，包含运行信息、报告和日志。前端明确展示 Token 预算尚未实现。旧版自动推送计划在调度时暂停，需重新保存关闭自动推送的设置；单个无效计划不会阻塞其他项目。

- 已实现按时间及修改文件数限制执行；尚未实现精确 token 配额、空闲检测或余额自动消耗。
- 后端每个实例串行执行养护任务。定时间隔是入队时计算下一次运行时间，不是固定时区 cron。
- 自动编译当前支持 .NET 与 npm；其他构建体系会明确失败。npm test 尚未自动执行。
- 独立副本保留用于审阅与故障调查，尚未提供自动清理；多仓库推送部分成功时不会回滚已推送仓库。
- 本地构建和测试不等同于生产 SQL Server、真实 Codex 账号及远端 Git 凭据联调；这些需要在部署环境选择测试项目验收。
