## 二、主要工作与成果

### 1. 改善知识工作区布局和文件处理可见性

对应提交：`0b03091 feat: 优化知识工作区布局与文件处理状态`

- 左侧目录、中间预览、右侧终端之间增加可拖动分隔条，支持键盘调整、双击恢复默认宽度，并保存宽度偏好；终端默认宽度扩大到 480px。
- 窄屏根据工作区容器宽度堆叠面板；预览保留单一滚动区域，使用细圆角滚动条，减少正文内外重复滚动。
- 目录标题处新增“文件处理”弹窗，展示文件名、大小、正文状态、最新处理任务、阶段与进度；失败任务可以展开查看原因。
- 提供搜索、预览和手动刷新，存在活动任务时自动轮询；关闭弹窗或发起新请求时取消旧请求，避免过期结果覆盖。
- 后端从当前用户可见资源树获取文件，并按文件查询最新 `wiki_compile` 任务，不依赖任务中心最近列表的数量窗口。
- 明确区分“正文已经解析”与“整个语义任务成功”，避免摘要生成失败时误报文件全部处理完成。

### 2. 梳理个人知识产物归属和生成预算

对应提交：`521d45d feat: 引入 KnowAgent 并隔离个人知识工作区产物`

- 原文件与解析正文（L2）保留在资源层，个人摘要与 Wiki 写入 `viking://user/<user>/summaries/` 和 `wiki/`，来源目录结构保留在产物映射中。
- 任务入队时记录用户归属及解析模式，后台执行使用快照；去重、查询、取消和重试均校验用户范围。
- 语义文件按用户保存，使用不可变版本和原子 manifest 发布；Wiki 保留来源证据与内容哈希，防止半成品被当作最新产物。
- 生成目录为只读产物入口，不接受手动上传和建目录；删除来源文件后隐藏对应产物。历史无归属记录保留兼容规则，不猜测用户归属。
- 引入 KnowAgent 统一生成与上下文压缩，按模型窗口预留输出及指令预算，压缩和生成共享调用次数上限。
- 预算不足、超时或压缩无法收敛时明确失败；语义失败仍允许读取已保存正文。

### 3. 完善 KnowAgent 流式对话与目录编译

对应提交：`35168db feat: 完善 KnowAgent 流式对话与目录编译配置`

- 知识工作区接入真实 SSE 流式输出，提供配置模型选择、聊天气泡、Markdown 展示、停止、新会话和工具执行明细。
- 原生工具循环复用现有 AgentRuntime 与 LLM 客户端，仅开放所选目录内的 `ls/read/search/status`；每次执行重新校验可见目录和 URI 范围。
- 模型 ID 必须来自配置目录；不支持原生工具调用的模型采用普通流式对话与手动命令入口，并明确展示能力差异。
- 完整拼接工具调用增量并配对工具结果，限制步骤、工具次数及模型总调用次数；上下文压缩保留当前问题，整组处理历史工具调用与结果。
- 区分模型完成标记与普通连接结束，避免连接截断后误报成功；上下文用量与压缩指标明确标为估算值。
- 新增目录编译配置弹窗，可选择 1–32 个来源文件、API 模型或 Codex/CLI 配置、推理级别、调用上限和超时。
- 每批编译参数保存到任务 `ConfigurationJson`，重试沿用原快照；已有不同配置的活动任务明确返回冲突，不静默覆盖全局设置。
- 编译仍经知识任务队列，按正文解析再语义生成的顺序执行，错误和取消继续进入任务中心。

### 4. 增加聊天资料库并修复文档引用

对应提交：`bf96db8 feat: 增加聊天资料库并整理侧栏入口`、`e767bb2 fix: 修复仓库根目录文档链接识别`

- 聊天新增“资料库”，汇总本人历史上传与当前授权项目的文档，支持搜索、来源筛选、预览、原文件下载、关联聊天及刷新。
- 项目文件关联复用文档引用；本人历史附件取回原文件后重新上传，继续遵守模型能力、文件类型和附件数量限制。

- 文档发现沿用白名单及现有项目扫描边界，不扫描任意服务器目录；文件修改时间仅用于排序，不作为“AI 生成”的归属证据。
- 调整侧栏菜单，隐藏新增菜单和空面板中的任务、终端入口，保留项目运行日志入口。
- 根目录文档与子目录共用扫描、预览及下载流程；修复 `/D:/...` 类型 Windows 路径引用的规范化，并保留项目、仓库归属校验。
- 下载保留原始文件字节，错误明确显示；不使用同名文件回退无效绝对路径。

### 5. 修复运行状态与 Git 状态的独立显示

对应提交：`0a15320 fix: 独立处理运行状态与 Git 状态检查失败`

- 运行状态和 Git 状态分别处理成功与失败，一侧请求失败不会覆盖另一侧已成功的数据。
- 防止旧请求响应覆盖新选择，Git 查询失败时清除旧状态并显示对应错误。
- 只有实际仓库状态完整且无远程刷新错误时，才显示无需拉取或推送，避免将查询失败误报为已同步。
