# 团队知识 Git

入口：知识工作区左侧目录可直接勾选文件／目录，点击「推送所选」；右上角「Git 提交推送」和原文预览栏「提交推送」均在当前页打开弹窗，也可在「设置 → 知识工作区 → 团队知识 Git」操作。目录整选包含子项，取消其中一个文件时父目录显示部分选中；原文栏入口只预选当前文件。已配置的远程在弹窗中默认折叠，展示当前目标、文件检查、确认和推送结果。管理员保存团队唯一的 HTTPS 远程与分支，凭据复用本人已激活的 Git 账号，不存入远程地址或 appsettings。

## 配置与目录

服务器 appsettings 或环境变量 `KnowledgeStorage__RootPath` 可指定固定绝对路径：

```json
{ "KnowledgeStorage": { "RootPath": "D:\\KnowledgeCenter" } }
```

- `storage/knowledge_bases/`：原始知识持久化存储。
- `workspaces/team-knowledge/`：团队唯一 Git 工作区。
- `team-git.json`：远程和分支配置，不含凭据，不进入团队仓库。

空值保留旧 `DataPath/knowledge_bases` 存储行为，团队工作区放在 `DataPath/knowledge-workspaces/workspaces/team-knowledge`。页面只读展示实际路径，修改 appsettings 后重启。

切换目录不自动迁移数据。应先停写、备份并复制原存储，核对数据库记录中的绝对 `StoragePath`、解析正文路径等映射以及数据保护密钥，确认原件和解析内容可读取后再切换。只保留知识文件目录不能代替数据库备份。

## 使用

1. 在 Git 账号设置中激活有目标仓库权限的账号。
2. 保存 HTTPS 远程地址和分支（默认 main）。远程可以有既有历史；本地知识副本是默认同步来源。
3. 在目录勾选要更新的资料／项目文件或目录，或选择「发布本人会话」。每次最多 500 个共享入口、100 个会话；其他已导出的副本保留当前本地版本。没有页面选择时，顶部入口沿用全量共享资料刷新。打开弹窗不自动导出或推送。
4. 默认勾选「本地优先，强制同步远端」；确认后用本地分支覆盖远端目标分支，包括远端领先、历史分叉或独立历史。也可取消勾选改为普通推送，此时遇到远端领先／分叉即停止。
5. 点击「刷新资料并检查远端」。先完整生成暂存副本，再替换受管目录；普通异常会回滚替换。刷新不会触发解析或模型调用。修改选择、配置或推送方式后原检查与确认失效，须重新检查。
6. 检查完整文件列表（含工作区已有待提交／待推送内容）、输入提交说明，确认提交并推送。页面展示实际 Git 命令输出及提交 ID；失败不显示成功，保留本地提交可检查后重试。

仓库保留 `resources/` 与 `projects/<项目>/<目录>/` 的知识资源结构。新增已登记代码项目节点使用 `viking://projects/project-<ID>/`，显示 DisplayName（空值回退 Name）；目录树包含当前登录身份有权访问的未删除项目，空项目也显示，改名保持 URI 及已有子文件位置。这个保留命名范围内的资料和生成节点随项目权限一起筛选。旧知识目录／organization.project 文本分类保持，不按同名自动绑定代码项目，未归属项目的既有知识继续在资料中。源 URI、导出路径、显示名称、类型和文件 SHA256 保存在 `manifest.json`；目录条目也保留，空项目的名称可在清单中核对。合法中文目录直接保留，保留名称编码，大小写冲突报错。

默认仅导出共享资料与项目树中的原件、已发布解析章节和可读取的公共产物。明确选择的本人会话原始 Markdown 另存为 `sessions/<用户>/<稳定会话文件>.md`，保留完整原文并记录来源 URI、显示标题和哈希；仓库成员可阅读这些副本。即使管理员可以预览他人会话，发布接口仍拒绝他人会话、个人记忆、摘要、Wiki 和解析生成节点。

普通资料刷新从既有 manifest 校验并保留已发布会话副本，不自动重新读取后续私人消息；所有者再次选择后才更新副本。副本或清单损坏、来源失效、复制失败均阻止发布，保留上一完整工作区。取消勾选表示本次不更新，不会撤回 Git 历史中已发布的内容。数据库、凭据、向量索引和缓存不导出。空目录可在服务器副本中查看，Git 本身不保存空目录。已有公共产物过期／缺失会使本次刷新失败，保留上一副本。

推送使用知识专用 `PushTeamAsync`，在同一 Git 操作锁内重新检查、提交及推送，不改变代码仓库的通用推送规则。默认本地优先采用 `--force-with-lease=refs/heads/<分支>:<检查到的远端SHA>`，只更新已配置 origin 的当前目标分支。内容、远端地址、分支、远端 SHA 和强推模式均进入确认指纹；检查后远端发生变化会使旧确认失效，提交过程中远端更新也由 lease 拒绝覆盖。重新检查确认后可继续以本地为准同步。

不自动拉取、合并或重置本地文件；凭据或网络错误继续阻止推送。推送失败时保留本地提交，刷新后可再次推送，不重复生成相同提交。当前不在聊天中挂载该工作区或新增 KnowAgent 模式切换。

## HTTP 契约

全部为管理员接口，由服务层验证身份；无客户端任意磁盘路径参数。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/knowledge/team-git` | 实际存储、工作区路径、配置、Git 状态和本人会话候选 `session_options` |
| PUT | `/api/v1/knowledge/team-git` | `{remote_url, branch}` 保存／初始化 |
| POST | `/api/v1/knowledge/team-git/refresh` | 可选 `{resource_uris, session_uris: [], force: true}`；resource_uris 缺省为全部共享资料、空数组为不更新共享资料，目录递归选取，未选已导出副本保留。仅额外发布明确选择的本人会话；兼容无请求体。返回文件列表、检查项与 snapshot_sha256 |
| POST | `/api/v1/knowledge/team-git/push` | `{message, snapshot, force: true}` 复核后提交推送；force 默认 true，false 为普通推送 |

资源树节点的 `can_publish` 由服务端身份和资源范围计算，只向管理员开放共享资源及本人原始会话的勾选；人员根目录、他人会话和个人产物不能批量勾选发布。写接口独立复核范围，不以浏览器标记作为授权依据。

工作区采用单实例操作锁。应用进程异常退出期间可能留下临时目录；多后端进程共享同一目录前需要增加跨进程锁和崩溃恢复。服务器工作区由应用维护，避免由外部进程同时修改。
