# 团队知识 Git

入口：知识工作区右上角「Git」下拉面板，桌面在右上展开、手机使用底部面板，沿用聊天页工具面板交互。左侧目录仅浏览；展开面板自动刷新全部共享资料、项目及本人会话的服务器副本，以 Git 实际状态展示待提交文件数量和可展开文件明细。只在点击「强制推送」时提交并推送。配置保留在「设置 → 知识工作区 → 团队知识 Git」；管理员保存团队唯一的 HTTPS 远程与分支，凭据复用本人已激活的 Git 账号，不存入远程地址或 appsettings。

## 配置与目录

服务器 appsettings 或环境变量 `KnowledgeStorage__RootPath` 可指定固定绝对路径：

```json
{ "KnowledgeStorage": { "RootPath": "D:\\KnowledgeCenter" } }
```

- `storage/knowledge_bases/`：原始知识持久化存储。
- `workspaces/team-knowledge/`：团队唯一 Git 工作区。
- `team-git.json`：远程和分支配置，不含凭据，不进入团队仓库。

空值保留旧 `DataPath/knowledge_bases` 存储行为，团队工作区放在 `DataPath/knowledge-workspaces/workspaces/team-knowledge`。页面只读展示实际路径，修改 appsettings 后重启。

切换目录不自动迁移数据。应先停写、备份并复制原存储，核对数据库记录中的绝对 `StoragePath`、解析正文路径等映射以及数据保护密钥，确认原件和解析内容可读取后再切换。只保留知识文件目录不能代替数据库备份。

## 使用

1. 在 Git 账号设置中激活有目标仓库权限的账号。
2. 在同步设置保存 HTTPS 远程地址和分支（默认 main）。远程可以有既有历史，以服务器知识内容为准同步。
3. 打开「Git」下拉面板，自动调用刷新接口，省略 `resource_uris`、传入空 `session_uris` 与 `include_own_sessions: true`，由后端按当前登录身份刷新全部共享资料、项目及本人会话，再显示真实待提交数量。查看变更文件可展开新增、修改、删除、重命名等路径；porcelain `-z` 的重命名源路径计入同一个文件。打开面板不创建提交、不推送；刷新图标可重新检测。关闭后再次展开会重新检测，旧数量在检测期间清空。
4. 点击「强制推送」：`KnowledgeGitSync` 重新检测并获得新快照，再调用推送接口；两次均固定 `force=true`，提交说明自动填入“同步服务器知识资料”。配置页复用同一操作。推送成功按返回状态更新数量，日志按需展开。没有未提交文件但仍有待推送提交或远端差异时，保持可推送；完全同步则显示无需推送，可点击刷新再次检测。
5. 本人原始会话自动加入检测，不需要逐项点击发布。自动范围在服务器按当前用户解析，包含当前可访问的全部本人 Markdown 会话，不受显式 URI 请求的 100 项上限截断；其他人会话、记忆、摘要、Wiki 与解析生成节点排除。目录中的会话数是来源数量，待提交数是 Git 实际变化文件数，包含 manifest；两个新会话通常表现为两份 Markdown 和一份清单变化，已同步且未变化时显示 0。
6. 处理中展示阶段，阻止重复执行及关闭；检测／检查失败不调用推送，推送失败保留服务器提交。失败重试重新刷新快照，远端变更仍由快照及 lease 阻止覆盖。未配置仓库或配置未保存时禁用操作；读取配置失败可在面板内重新加载。

“服务器内容”是后端生成的受管 Git 副本，不是浏览器电脑上的文件。自动刷新先完整生成暂存副本再替换受管目录，异常回滚；不会触发解析或模型调用。推送仍包含该工作区已有待提交／待推送内容。

仓库保留 `resources/` 与 `projects/<项目>/<目录>/` 的知识资源结构。新增已登记代码项目节点使用 `viking://projects/project-<ID>/`，显示 DisplayName（空值回退 Name）；目录树包含当前登录身份有权访问的未删除项目，空项目也显示，改名保持 URI 及已有子文件位置。这个保留命名范围内的资料和生成节点随项目权限一起筛选。旧知识目录／organization.project 文本分类保持，不按同名自动绑定代码项目，未归属项目的既有知识继续在资料中。源 URI、导出路径、显示名称、类型和文件 SHA256 保存在 `manifest.json`；目录条目也保留，空项目的名称可在清单中核对。合法中文目录直接保留，保留名称编码，大小写冲突报错。

网页导出共享资料与项目树中的原件、已发布解析章节和可读取的公共产物，以及自动纳入的本人原始会话 Markdown。会话另存为 `sessions/<用户>/<项目名>-<项目ID>/<稳定会话文件>.md`，保留完整原文并记录来源 URI、显示标题和哈希；仓库成员可阅读这些副本。即使管理员可以预览他人会话，发布接口仍拒绝他人会话、个人记忆、摘要、Wiki 和解析生成节点。

平台会话按所属项目分目录：例如 `sessions/superadmin/MES标准库-11/<摘要>.md`；没有已确认平台项目关联的手动上传或客户端会话放入 `sessions/<用户>/未分配项目/`。项目关联从当前所有者的 AiChatSession.CodeProjectId 批量读取，使用同一 SessionIdentity 规则匹配平台导出的稳定 URI，不从原文内容、标题或浏览器传参猜测项目。目录显示项目名并附 ID，同名项目保持分离；名称中的路径字符替换为下划线，长度按 Unicode 字符限制。项目改名后下次同步更新目录名，原始 URI 与会话摘要文件名保持。

manifest 的会话条目追加可空 project_id、project_name 快照。旧平铺路径经来源 URI、旧／新格式路径及哈希校验后迁入项目目录；未选副本只搬运已发布字节，不读取私人后续内容。其他所有者仅沿用已发布项目快照，旧无项目快照放入“未分配项目”，不查询其私人会话关联。重复同步稳定；迁移、复制或哈希失败保留上一个完整工作区。原始知识存储、前端目录 URI 和聊天历史保持不变。

网页自动检测时，当前用户会话的新增、内容变化与已删除记录同步到副本；其他所有者已发布的会话副本仍从既有 manifest 校验保留。旧客户端省略 include_own_sessions 时继续保留未明确选中的会话副本，选择后才更新。副本或清单损坏、来源不可读或复制失败仍阻止发布，保留上一完整工作区。数据库、凭据、向量索引和缓存不导出。空目录可在服务器副本中查看，Git 本身不保存空目录。已有公共产物过期／缺失会使本次刷新失败，保留上一副本。

推送使用知识专用 `PushTeamAsync`，在同一 Git 操作锁内重新检查、提交及推送，不改变代码仓库的通用推送规则。界面固定使用 `--force-with-lease=refs/heads/<分支>:<检查到的远端SHA>`，只更新已配置 origin 的当前目标分支。内容、远端地址、分支、远端 SHA 和强推模式均进入指纹；刷新后远端变化会使旧快照失效，提交期间远端更新也由 lease 拒绝覆盖。点击重试会自动重新刷新再推送。

不自动拉取、合并或重置本地文件；凭据或网络错误继续阻止推送。推送失败时保留本地提交，刷新后可再次推送，不重复生成相同提交。当前不在聊天中挂载该工作区或新增 KnowAgent 模式切换。

## HTTP 契约

全部为管理员接口，由服务层验证身份；无客户端任意磁盘路径参数。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/knowledge/team-git` | 实际存储、工作区路径、配置、Git 状态和本人会话候选 `session_options` |
| PUT | `/api/v1/knowledge/team-git` | `{remote_url, branch}` 保存／初始化 |
| POST | `/api/v1/knowledge/team-git/refresh` | 可选 `{resource_uris, session_uris: [], include_own_sessions?: false, force: true}`；resource_uris 缺省为全部共享资料、空数组为不更新共享资料，目录递归选取，未选已导出副本保留。include_own_sessions=true 由后端按当前身份自动更新全部本人原始会话；默认 false 保持旧显式选择语义，兼容无请求体。返回文件列表、检查项与 snapshot_sha256 |
| POST | `/api/v1/knowledge/team-git/push` | `{message, snapshot, force: true}` 复核后提交推送；force 默认 true，false 为普通推送 |

上述 HTTP 契约保持兼容，界面不再提供 `force=false` 切换，也没有新增绕过快照校验的接口。前端自动串联既有刷新和推送请求。

资源树节点的 `can_publish` 仍由服务端身份和资源范围计算，保留原契约；目录不再渲染推送复选框。人员根目录、他人会话和个人产物不能自动发布，写接口独立复核范围，不以浏览器标记作为授权依据。原局部选择 API 保持兼容，当前页面统一自动检测全部共享资料、项目及本人会话。

工作区采用单实例操作锁。应用进程异常退出期间可能留下临时目录；多后端进程共享同一目录前需要增加跨进程锁和崩溃恢复。服务器工作区由应用维护，避免由外部进程同时修改。
