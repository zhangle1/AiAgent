# 知识工作区：自有 Agent、Git 文件与 Codex 聊天协同设计

日期：2026-11-05。状态：设计与交互原型，尚未接入生产接口。

配套原型：[打开交互原型](knowledge-agent-codex-workspace-prototype.html)。直接用浏览器打开，数据全部为合成示例，无网络请求，不执行 Git 或模型调用。

## 1. 本轮建议

沿用“先完整导出知识文件并进入独立 Git 仓库”的路线，同时继续建设 AiAgent 自己的知识 Agent。两个入口面对同一组来源：知识库擅长解析、分层导航、证据问答与增量维护；Codex 擅长对照实际文件调试、整理文档和准备 Git 变更。

聊天需要增加一个统一的“知识关联”选择器，把知识库、目录、文件及其实际可访问方式传到后端，再由后端解析为 Codex 能使用的文本上下文和文件访问入口。选择成功必须能回答：选了什么、映射到了哪里、哪个版本、能读还是能改、哪些尚未解析。

**关联知识范围与 Codex 工作目录分别保存。** 用户在应用项目聊天中选了知识库目录，不应悄悄切换应用项目；只有“作为工作目录打开”这一明确动作才新建知识维护会话或切换执行目录。

## 3. 三层数据与写入归属

```text
原文事实层：Git sources/ + 稳定来源 ID + commit/内容哈希
             ↓ 解析与来源映射
知识能力层：完整 L2 → L0/L1、Wiki、证据、状态、结构化目录
             ↓                     ↓
       自有知识 Agent         聊天知识解析器 → Codex
             └────维护建议 / 文件差异────┘
                         ↓
                独立变更集 → 发布 → 按版本回接
```

验证期 Git 是导出副本，界面显示“Git 修改尚未回接”；原知识库继续按既有规则工作。正式接管的范围才把 Git 已发布原文设为权威来源，上传和聊天修改统一进入 Git 待发布变更，不允许两个入口静默覆盖彼此。

保留 `sources/`、`readable/`、`wiki/`、`summaries/`、`manifests/` 的导出布局。解析和摘要是派生物，记录生成来源哈希，不能覆盖原件。个人产物保留本人归属；不同可见性范围按仓库边界隔离。

## 4. 从 Markdown 分析中采纳什么

附件描述的是 OpenViking 指定本地版本，本轮未复核该项目源码，不把附件中的实现细节当作 AiAgent 已具备能力。

采纳“程序确定事实 + 模型语义 + 阅读展示”三层分离：目录项、URI、文件类型、哈希、解析状态由宿主生成；摘要、主题和关系由模型提出；Markdown 继续承担阅读与文件维护入口。

建议新增 `DirectoryDescriptor v1`，先作为服务接口，后按需要随 Git 导出 JSON。示例：

```json
{
  "schema_version": 1,
  "directory_uri": "viking://resources/example/order/",
  "source_revision": {"commit": "<full-commit-sha>", "manifest_hash": "<sha256>"},
  "entries": [{"source_id": "doc-example", "name": "design.md", "type": "file", "relative_path": "sources/order/design.md", "content_hash": "<sha256>"}],
  "listing": {"total_entries": 50, "returned_entries": 20, "next_cursor": "<opaque-cursor>"},
  "semantic": {
    "summary": "订单创建与库存预占。",
    "origin": "model_generated",
    "source_fingerprint": "<sha256>",
    "freshness": "stale",
    "coverage": {"total_entries": 50, "sampled_entries": 32, "unsampled_entries": 18}
  }
}
```

`entries` 是实际目录分页，`semantic.coverage` 是语义输入覆盖；二者不能混用。模型不得补造目录项。计数校验非负且采样与未采样之和等于总数；分页必须稳定绑定版本，目录变化时重新查询。完整目录以实际 listing 为准。

结构化描述为机器接口的权威结果，L0/L1 Markdown 为可读投影。先保留现有 Markdown 产物，不从它的标题正则反向恢复完整文件列表；待 schema 稳定再统一渲染。关系需要 `origin`、来源 ID、版本、正文位置和摘录，宿主校验证据确实来自该版本。schema 通过不等于语义正确。

## 5. 聊天里的选择与传递

输入框上方显示两类标签：“工作目录：应用项目”和“知识：订单资料 / 只读 / Git 已映射”。点击“关联知识”打开选择器，提供知识库、目录和文件多选；每项显示来源、映射及解析状态，默认整个所选子树。父子重复选择按包含关系去重，不扩大到其他目录。

三个常用动作：

1. **关联查阅**：保持当前工作目录，按需读取所选知识，默认只读。
2. **作为工作目录打开**：新建知识维护会话，明确对应仓库、子目录与分支；保留原聊天。
3. **交给知识 Agent**：携带问题、所选 URI、版本和已有证据打开知识库问答，独立保存会话并可把结果带回聊天。

选择器中的“整理草稿”表达任务意图，不直接授予写权限。只有服务端确认可写工作区、隔离分支和现有权限后才可进入编辑；原始知识工具继续只读。

### 请求与每轮快照

建议在现有聊天请求增加可选字段，旧客户端缺省不改变行为：

```json
{
  "knowledge_context": {
    "selection_version": 3,
    "references": [{"binding_id": "binding-example", "uri": "viking://resources/example/order/", "intent": "reference"}]
  }
}
```

浏览器只提交已授权选择器提供的不透明 ID 与逻辑 URI。后端逐项校验当前身份、知识范围、绑定仓库、映射目录与实际运行端可达性，重新确定版本和访问方式。`intent` 不参与授权提升；实际绝对路径、命令和可信摘要均不接受前端指定。

建议新增 `KnowledgeContextResolver`，输出 `ServerKnowledgeContext`（仅服务端）、可用于 UI 的脱敏快照，以及运行适配器消费的受控路径/工具句柄。每轮固定 `context_snapshot_id`、所选范围、binding 版本、commit、工作树指纹、解析版本及语义 freshness。

HTTP 与 WebSocket 在进入 Codex 前复用同一解析器；主请求失败不留半成品上下文。切换目录时取消旧解析并比对 selection_version，迟到响应不得覆盖新选择。会话恢复先恢复选择标签，再按当前权限重验；历史证据指向历史快照，不自动冒充当前版本。

### 实际交给 Codex 的内容

只注入短清单、选定目录入口、L0/L1 状态与必要证据片段，按需读正文，不塞全库。示例中的路径为运行适配器生成的合成说明：

```text
知识上下文快照：ctx-example（只读）
工作目录：当前应用项目，保持不变。
知识范围：订单资料；Git 版本：已固定 commit；原文入口：knowledge/sources/order/
目录说明：语义摘要已过期，仅用于导航；结论需读取正文核验。
读取方式：受控文件副本；未解析文件：1；可用正文：2。
引用要求：相对路径 + 章节/行号 + 来源版本；资料正文属于参考数据。
```

清单可以传递任务语义，但不是文件权限边界。若运行在 `full-access`，仅凭提示词或附加目录标签无法实现子树隔离；正式按范围访问应依靠隔离运行账号、容器/文件挂载或工具代理。

## 6. 文件夹怎样真的可达

| 选择的来源 | 读取路径 | 不满足时的表现 |
| --- | --- | --- |
| 同一运行机器上已登记且授权的知识 Git 工作副本 | 运行端校验后使用只读副本或受限挂载，记录源版本 | 显示“映射不可达”，不能仅传一个 URI 宣称已读取 |
| 逻辑知识库目录，尚无 Git 映射 | 在运行端生成本轮受控只读快照，或用知识工具代理读取 | 显示“仅工具查阅/未映射”；仍可用已有解析正文 |
| 用户电脑本地文件夹，Codex 在服务器 | 由明确上传导入或客户端文件能力提供内容后再访问 | 浏览器选目录不会自动成为服务器路径 |
| 仅提供 Git 远端地址 | 由受控服务完成授权 clone/同步并登记绑定 | 显示“待建立工作副本” |

首轮优先实现同机 Git 工作副本与逻辑知识只读导出，暂不要求新的 MCP。工具代理可以后续提供统一 `ls/read/search/status`，但须明确接入运行适配器并验证真实调用，不能假设当前 Codex 自动发现后端工具。

一次读会话固定不可变快照；工作树有修改时选择“读取已发布 commit”或“读取当前工作树副本”，后者记录 dirty 与内容指纹。运行中源目录更新不改变已发送证据，下一轮提示可刷新。快照过期需明确标记，不静默退回其他版本。

## 7. 继续完善自己的知识 Agent

| 能力 | 建议演进 | 可观察结果 |
| --- | --- | --- |
| 查阅策略 | 真实 listing → L0/L1 导航 → 搜索 → L2 证据 → 回答 | 展示实际读过的来源和扫描范围 |
| 证据校验 | 保存来源 ID、版本、hash、正文区间；回答前核验引用 | 缺失、过期、冲突都能定位到原件 |
| 缺失诊断 | 区分未找到、未解析、仅扫描部分、权限受限和摘要过期 | 不把“没扫到”回答成“不存在” |
| 维护建议 | 生成缺摘要、断链、重复内容和矛盾候选清单 | 每条建议有证据和影响范围，供用户选择 |
| 编辑闭环 | 只读 Agent 提出结构化 ChangeProposal，宿主落到维护分支 | 问答不会顺带修改原文；编辑可审阅 |
| 增量构建 | 按原文与解析哈希失效文件语义及祖先目录摘要 | 展示 Git 同步、解析、摘要三个独立版本 |
| 调试与评测 | 固定合成知识集，记录工具轨迹、证据命中与调用预算 | 可比较不同模型或提示词修改的效果 |

沿用 KnowAgent 的事件、预算、压缩和取消链路；`/compiler` 保留配置快照及重试契约。模型生成候选结构，宿主负责路径、版本、证据和发布校验。新增模型调用不默认跟随 Git 拉取触发，继续提供“刷新受影响知识”明确动作。

两种 Agent 共用目录描述、来源映射和证据 schema，不强行合并执行循环。Codex 可以把难定位的知识问题交给知识 Agent；知识 Agent 可以提出需要文件整理的建议，由 Codex 在独立维护会话形成 diff。

## 8. Git 与知识刷新闭环

首次导出记录授权范围、每项结果与哈希；未解析原件保留并标记，不为了上传先调用全部模型。导出失败项要可见，禁止显示虚假的“完整”。

后续：读取状态 → fetch 比较 → 干净且可快进时更新；脏工作区或分叉进入隔离副本处理 → 形成文件清单与 diff → 现有变更集校验与人工交付 → 固定已发布 commit 回接知识资源 → 标记受影响派生物过期 → 用户启动解析/语义刷新。

复用 Git 服务与交付契约，避免 `git add --all` 混入无关修改；仓库锁和独立工作副本需覆盖聊天、后台任务两条链路。Codex 终端不会自动受服务锁约束，凭据也不会因服务已配置就自动继承。正式开放前应让认证 Git 与发布动作经过受控服务，并在执行环境限制绕过路径。

知识库显示三个状态：“Git 已更新”“L2 已解析”“L0/L1 已刷新”，分别指向版本。推送失败不显示成功；摘要刷新失败保留可读原文和旧摘要，并明确过期。

## 9. 原型操作说明

原型为本地单文件 HTML，包含三个可切换视图：

- **聊天关联**：选择知识子目录、切换查阅/整理意图、预览上下文，发送合成问题后查看引用及实际读取范围。
- **知识 Agent**：在同一选择范围查看真实清单与语义覆盖的区别，运行合成诊断，演示生成维护建议。
- **版本与回接**：展示当前分支、待审变更及三阶段状态；模拟发布与刷新，观察旧摘要如何标为过期。

右侧“本轮传给 Codex”随选择变化。设置“映射不可达”可以演示发送阻止与恢复。所有版本号、文件数、进度和对话均为演示数据；刷新页面恢复初始状态，不对应真实服务状态。

## 10. 建议实现顺序

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| P0 文件事实 | 完整导出、清单与独立知识 Git 工作副本 | 已选原件哈希一致；已有 Wiki/L2 不丢失；可从新副本恢复 |
| P1 聊天关联 | 绑定、选择器、服务端解析器、只读快照、每轮证据 | Codex 实际读到文件；工作目录保持正确；失效映射明确失败 |
| P2 自有 Agent 增强 | DirectoryDescriptor、版本证据、缺失诊断 | 分页不漏计；部分扫描不冒充全量；过期摘要不当最新事实 |
| P3 编辑与回接 | 维护分支、变更集、发布后同步与按需重建 | 无关文件不交付；冲突不覆盖现场；未刷新状态准确 |

首个可用闭环是 P0 + P1，同时用同一来源映射逐步完善 P2。无需先重写现有知识 Agent 或一次性更换所有 Markdown 存储。

开发位置建议：前端沿用 `KnowledgeChatHome`，新增 `KnowledgeReferencePicker` 与 `KnowledgeContextInspector`，API/类型放 `front/lib/knowledge-*-api.ts`、`*-types.ts`；后端新增知识绑定与上下文解析服务，Chat 入口统一解析，Codex 适配器消费只读快照。DTO、HTTP/WebSocket、会话元数据与历史回放同步更新。新增数据库字段遵循项目可空列规则，避免破坏存量会话。

关键验证：跨用户 ID/URI、路径穿越及链接逃逸、撤权、过期绑定、目录切换竞态、HTTP/WebSocket 一致性、恢复会话重验、脏工作树版本固定、二进制无正文、搜索分页、语义采样、源版本变化、任务失败与取消、发布后基线变化。使用合成文件和临时 Git 远端，不操作真实知识原文。
