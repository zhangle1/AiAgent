# 代码库运行时理解流程

## 设计目标

代码库不应要求用户先建立全量索引才能回答“项目做什么”。系统采用“按需读取优先、持久化索引加速”的两层策略。

## Agent 调度

现有 `AgentLoop` 不需要增加新的固定节点。它已经按 `TOOL -> observation -> FINISH` 调度工具；代码理解能力通过工具注册进入同一条 Loop。

1. 用户选择代码库并提问。
2. LLM 根据系统提示选择工具。
3. `code_repository_overview` 用于项目概览：读取根目录、README 和常见清单文件，不依赖索引。
4. `code_search` / `find_symbol` 优先查询持久化索引；没有命中时进行受限的只读实时扫描。
5. 工具把文件路径和片段作为引用交回 Loop，LLM 根据证据生成最终回答。

## 实时扫描边界

- 仅读取已登记代码库根目录下的文件。
- 跳过 `.git`、`node_modules`、`bin`、`obj`、`.next`、`dist` 等目录。
- 只读取常见源码与清单扩展名。
- 单文件大小和实时扫描文件数都有上限，避免一次提问卡住整个应用。
- 不执行构建、安装依赖、脚本或修改源文件。

## 全量索引的定位

“建立代码索引”会把可搜索源码与基础符号保存到 `ai_code_repository_file`。它用于更快的异常定位、跨文件查询和未来的调用链分析，但不是项目概览的前置条件。

## 参考 codex 的原则

参考 `E:\项目\know-why\codex` 的工作方式，本模块采用最小必要读取：先确定工作区边界，再读取结构与关键清单，只有证据不足时才扩大到相关源码文件。这样比全仓库预先灌入上下文更可控，也更适合诊断问题。
