# 聊天上传库与管理员上传管理规格

> 状态：已实施，待运行时验收  
> 范围：设置页“我的上传”、管理员“上传管理”、聊天右侧上传文件索引，以及聊天附件抽取文本的可追溯保存。

## 1. 目标与边界

聊天附件不再只是一次性输入：用户可在设置页查看自己上传过的图片、PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX、Markdown、TXT、CSV 及其可用的提取文本；管理员可按用户、格式、文件名和类型审计所有用户上传。

聊天中查看文档提取内容统一改为右侧“上传文件”索引打开，不再在聊天区弹出独立预览。聊天消息仅保存不透明附件/提取文件 ID，索引和预览接口按当前用户或管理员权限解析实际文件。

## 2. 存储与生命周期

统一复用 `ChatAttachments:RootPath`：未配置时为 `DataPath/chat_attachments`。

```text
ChatAttachments:RootPath
├─ <图片临时文件>                  # 兼容既有图片上传
├─ history/<用户哈希>/<会话>/       # 既有图片及 manifest
└─ files/
   ├─ <文档临时文件>
   └─ history/<用户哈希>/<会话>/
      ├─ <文档原件> + manifest
      └─ extracted/<提取文本>.txt + manifest
```

- 原件、图片与提取文本都由上传库索引；索引使用 manifest 中的用户、会话、文件名、MIME、大小、创建时间、类别和来源附件 ID，不将绝对路径写入数据库或 API。
- 仅临时、未发送的附件遵守既有保留时长清理；发送成功后的原件与提取文本与会话历史绑定。
- 提取文本仅对可解析格式生成。旧 OLE Office、解析失败或禁止格式不会伪造提取文件。

## 3. 权限与安全

- 普通用户只能查询、打开本人上传文件；请求中的用户 ID、目录、路径与 manifest 均不可信，必须由服务端归属校验。
- 管理员可查询所有用户，但不经由普通用户接口绕过权限；管理员列表单独返回上传者账号。
- 列表、预览和下载均不返回绝对路径、哈希目录、密钥或聊天上下文全文。
- 文档抽取内容始终是不可信数据；在聊天中传给 Codex 时仍保留既有 `<attachment_text>` 安全边界。
- 列表默认最多 200 条，可按文件名、类别、用户和会话筛选；内容读取有文本长度上限，图片仅流式读取已验证的受控文件。

## 4. API 与模型

### 普通用户

- `GET /api/v1/chat/uploads/mine`：我的上传列表，支持 `keyword`、`kind`、`session_id`、`limit`。
- `GET /api/v1/chat/uploads/{id}/content`：读取本人可访问的原件或提取文本；图片以安全文件流返回。

### 管理员

- `GET /api/v1/admin/uploads`：全部上传列表，支持 `user_id`、`keyword`、`kind`、`session_id`、`limit`。
- `GET /api/v1/admin/uploads/{id}/content`：按管理员权限读取指定上传内容。

统一列表项 `ChatUploadFileDto` 至少含：`id`、`file_name`、`content_type`、`size_bytes`、`kind`（`image` / `document` / `extracted_text`）、`extraction_status`、`created_at`、`session_id`、`source_attachment_id`；管理员响应额外含上传者账号。所有 ID 为不透明 ID。

## 5. 前端交互

1. 新增 `/settings/uploads`“我的上传”：搜索、类型筛选、上传时间/会话信息、图片缩略图、文本/提取文件预览与安全下载。
2. 新增 `/settings/admin/uploads`“上传管理”：复用列表组件，增加上传者筛选和所有用户可见标识。
3. 设置首页与管理员首页各增加入口卡片；管理员入口受既有管理员鉴权保护。
4. 聊天右侧检查器新增“上传文件”标签。文档附件的“文本提取”双击/打开动作切换到该标签并定位其提取文本；普通文件可在该索引继续预览。
5. 聊天消息本身只显示附件引用；提取文本不再在聊天内弹层显示。

## 6. 验收用例

1. 发送带 PNG、DOCX、XLSX、PPTX、TXT 的聊天后，“我的上传”均可找到原件；图片能预览。
2. 可解析文档生成提取文本条目，内容与实际送给 Codex 的受限文本一致（仅包裹标记不同）。
3. 普通用户不能通过 ID 查询他人上传；管理员可按用户和类别筛选。
4. 聊天中打开“文本提取”将右侧检查器切到上传文件索引，定位提取文件，不再显示聊天弹窗。
5. `.doc/.xls/.ppt` 显示原件但无提取文本，且继续提示转换。
6. 消息 metadata、列表接口与日志不出现绝对路径或附件全文；`git diff --check` 和编码检查通过。

## 7. 已知限制

- 扫描 PDF、Office 内嵌图片、图表、公式及旧 OLE Office 的视觉/结构语义仍不保证可提取。
- 本期上传库为聊天附件存档与审计，不替代知识库、项目 Markdown 文档库或 Git 代码库。
