# AI 打包与预览的成功流程复用

打包和预览配置弹窗默认勾选“优先复用已验证流程”。发送聊天后，AI 先检查匹配的成功流程，配置和环境一致时沿用已验证步骤；没有记录、校验不通过或执行失败时重新分析。取消勾选只影响本次请求，成功后仍保存新流程。

## 保存内容

目标仓库中的 `artifacts/aiagent-workflows/<scope_key>/<唯一版本>/` 保存 `recipe.json`，打包另存 `package.ps1` 或 `package.sh`。预览使用本次请求的 manifest 仓库保存配方。目录加入该仓库 Git 忽略，不进入交付 ZIP。

- `scope`：项目、操作类型、仓库及入口、补充要求、自动选择模式、预览访问 origin。入口去重排序、仓库排序；对提示词提供的 scope JSON UTF-8 内容计算 SHA-256 得到 `scope_key`。
- `environment`：OS、架构、运行时、包管理器版本。
- `inputs`：入口、锁文件、构建/代理配置、依赖工程与脚本的仓库相对路径及 SHA-256。
- `steps`：工作目录、程序及参数；不保存聊天记录或秘密。
- `outputs`、`verification`、`verified_at`：产物、实际验证证据及时间。
- 打包的 `script`：真正执行通过的脚本及其指纹。
- 预览的 `targets`、`request_id`：允许的启动模板，以及证明本次成功的请求 ID。

先写临时文件，成功后原子发布独立版本。失败、取消、超时不生成成功记录，不覆盖旧成功版本。流程写入失败必须在回复中说明，不能只报告“已固化”。

## 复用规则

AI 重新核对文件内容、相关配置的新增/删除、环境和脚本，不只依赖 Git HEAD。入口、要求或 origin 变化会匹配另一组流程；配置或脚本发生变化时重新分析。普通源码修改可继续使用构建方法，但每次必须构建当前源码并生成新的 ZIP，不能返回旧产物冒充新包。

预览模板写入本次新请求的 manifest，由现有后台验证仓库归属、路径、环境白名单并启动进程。只有本次结果的项目和请求 ID 匹配、状态为 running 且全部服务就绪，AI 才保存成功配方。旧请求、旧 PID 和旧结果不可重放；端口冲突不能通过盲杀进程或静默换端口解决。

## 实现边界

这是对现有聊天执行链路的增强。`front/lib/chat-workflow.ts` 生成统一执行协议，打包和预览提示词调用该模块，弹窗传入本次复用开关。实际文件读写、指纹计算、构建脚本生成与校验仍由拥有项目工具权限的聊天 AI 完成。后台的进程托管、权限控制和就绪检查保持原有契约。

当前没有新增流程数据库、免模型执行器、流程管理页面或服务端自动缓存命中判断。仅打开弹窗不会写流程或执行脚本。已有成功聊天不会自动追溯生成配方；需要完成一次新版请求。流程存在本机仓库的忽略目录，换服务器不会自动同步。

预期节省的是重复探测和试错时间，构建、依赖安装与就绪检查仍取决于项目。本次开发验证覆盖提示词契约、选择范围隔离、复用开关、原有链接及浏览器交互；没有调用真实模型构建用户项目，未测量端到端提速。
