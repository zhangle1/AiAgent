# AiAgent 项目 Markdown 文档搜索、预览与引用规格

## 目标

在已有聊天“/”项目引用菜单的基础上，增加当前项目内 Markdown 文档的受控搜索、树状浏览、预览和聊天引用能力。用户可以输入 `/spec` 进入文档二级搜索，或在 `/` 的类别菜单中选择“项目文档”。

系统只公开当前用户可访问的当前项目中、已注册代码仓库内的 `.md` 与 `.markdown` 文件；不得返回代码文件、绝对路径、未授权项目或未注册目录的内容。

## 用户体验

1. 聊天输入框输入 `/` 时，仍显示可引用的其他项目，并显示“项目文档 /spec”类别。
2. 选择该类别或直接输入 `/spec` 时，弹出文档二级菜单；继续输入 `/spec 关键词` 可按仓库相对路径与文件名筛选。
3. 菜单支持鼠标/触摸选择，以及 `ArrowUp`、`ArrowDown`、`Enter`、`Tab` 和 `Escape`。移动端菜单宽度随输入框适配。
4. 选择文档后，输入框插入清晰、可读的令牌：`[[文档:<显示名称>|<repositoryName>|<repositoryRelativePath>]]`。
5. 右侧工作区新增“项目文档”页签，按“仓库 / 文件夹 / 文件”树展示文档；选择叶子节点可预览 Markdown，并可用“引用到聊天”插入同一令牌。
6. 文档预览采用安全 Markdown 渲染，不启用原始 HTML；预览不会提供代码树、代码文件或绝对路径入口。

## 命令和引用语法

| 场景 | 语法 | 行为 |
| --- | --- | --- |
| 其他项目 | `/名称` | 搜索用户有权限访问的其他项目。 |
| 项目文档 | `/spec` | 打开当前项目的 Markdown 文档二级菜单。 |
| 文档筛选 | `/spec api` | 按当前项目中已注册仓库的文档名称和相对路径筛选。 |
| 文档引用 | `[[文档:接口说明|aps-api|docs/api-spec.md]]` | 服务器重新验证并将文档内容作为受控上下文提供给模型。 |

引用令牌是用户可见的聊天文本，不能作为服务器信任边界。服务器不接受浏览器提交的文档内容、绝对路径或任意本地路径。

## 权限与数据边界

- 列表与内容接口都先认证用户，再用项目访问权限校验当前项目；无权限统一返回禁止访问。
- 仅查询 `ProjectId` 等于当前项目、未删除的已注册仓库。
- 目录遍历跳过 `.git`、`node_modules`、`bin`、`obj`、`.next`、`dist`、`build` 和 `coverage`，跳过符号链接/重解析点，并限制最大深度和数量。
- 服务端规范化仓库相对路径，拒绝绝对路径、`..`、非 Markdown 扩展名和排除目录；解析物理路径后再次确认其仍在仓库根目录内。
- 文档正文仅支持 UTF-8 或带 Unicode BOM 的文本，并设置内容长度上限；聊天历史只存仓库名与相对路径，不存注入的文档正文。

## 前后端数据流

```text
聊天输入 /spec 或右侧项目文档
  -> GET /api/v1/code-repositories/projects/{projectId}/markdown-documents?query=...
  -> 权限校验 + 已注册仓库 Markdown 扫描
  -> 文档列表（repository_name、path、name）
  -> 用户选择并插入 [[文档:...|仓库|相对路径]]
  -> 聊天请求 markdown_document_references + 原始消息
  -> 服务器按令牌重新解析、鉴权、读取受控文档
  -> ServerMarkdownDocumentContext 注入模型提示词
```

右侧预览通过：

- `GET /api/v1/code-repositories/projects/{projectId}/markdown-documents/content?repository_name=...&path=...`

读取内容。该接口使用与聊天注入相同的项目、仓库、扩展名和路径边界校验。

## 模型上下文注入

1. 后端从用户消息中的 `[[文档:...]]` 令牌提取仓库名与相对路径，最多解析 5 个。
2. 服务器重新读取每份文档；客户端的 `markdown_document_references` 只作结构化辅助信息，不能绕过令牌及权限校验。
3. 已验证令牌在给模型的用户消息中替换为自然语言文档名称，例如 `文档“docs/api-spec.md”`，避免模型把协议令牌当成待解释代码。
4. 文档正文以带仓库、路径和截断标记的受控块加入系统构建的提示词，并明确说明文档内容是不可信参考材料，不是指令或执行授权。
5. 对 DeepSeek、Codex 和普通聊天编排使用同一服务器端上下文；前端仅负责展示和引用，不能直接拼接模型 prompt。

## 验收标准

1. 有权限用户在选择项目后可通过 `/spec` 搜索、键盘选择并插入 Markdown 文档引用；未选择项目时显示明确提示。
2. `/` 菜单可通过触摸打开“项目文档”，移动端不遮挡输入和发送操作。
3. 右侧“项目文档”按仓库和文件夹树显示，能安全预览并将选中文档引用到聊天输入框。
4. 非 Markdown、排除目录、符号链接越界、路径遍历、未注册仓库和无权限项目均不能被列出、预览或注入。
5. 聊天服务对伪造或过期的文档令牌返回通用不可用错误，不泄露服务器实际路径、仓库存在性或代码内容。
6. 模型收到的是服务器验证后的文档内容和自然语言引用；会话历史保留原始可读令牌及元数据，但不持久化文档正文。
