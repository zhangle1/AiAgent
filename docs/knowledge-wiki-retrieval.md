# Raw、知识表示层与可选索引

2026-09-17：本轮实现以本文为准，补充 `knowledge-context-refactor.md` 的索引优先方案。

参考本地 `llm_wiki/llm-wiki.md` 的 Raw sources / Wiki / Schema 分层：原文是事实来源，模型生成持久知识页面，查询时读取页面并回传引用。

## 默认流程

1. 创建知识库或上传文件，只保存到知识库的 `raw/`，不调用模型、不启动索引任务。
2. 用户按需点击「提炼知识」。Codex CLI 或平台 LLM API 生成主题、概念、适用范围、关系和不确定性的 Markdown 草稿；原文证据由宿主校验。
3. 检索默认使用同一模型配置，在已有知识表示层中搜索和读取，再返回经过逐字校验的引用。无需 embedding、Python RAG 环境或活动索引版本。
4. 仅有 raw 尚未提炼时，明确提示先提炼；查询不隐式发起写入或编译。模型检索也不修改知识草稿。
5. 设置中可切换到 RAG 索引检索，索引仅通过显式重建创建；保留已有索引和检索参数。

## 实现边界

- 核心逻辑继续在 `backed/Services/Knowledge/Core/`，不创建独立项目。
- Markdown 表示层复用现有 `AiKnowledgeArtifact` 及其主题页面和证据，不新建独立应用或强制迁移历史资料。原文页码范围读取仍依赖原有结构化 chunk；模型检索以知识主题页面为单位，不把模型分段当作原文页码。
- `knowledge_compiler.retrieval_mode` 默认为 `wiki`，可选 `rag`；旧配置缺失字段时使用默认值。提炼与 Wiki 检索共用执行方式、模型、推理强度、步数和超时配置。
- 模型只调用宿主提供的目录、搜索、读取和引用操作；输入数据不作为指令。Codex 使用隔离只读工作目录，不能直接读取 raw 或执行知识库写入。
- 返回引用包含知识库、来源文档、表示层页面、草稿审核状态；引用表示层不等同于原文已人工核实。
- 每轮目录、搜索结果、页面读取和返回引用均有数量与长度上限；模型超时或耗尽步骤明确失败，不悄悄切到其他模型或创建索引。
- 单库 API 与聊天工具共用模型检索服务；多库沿用既有选库范围逐库执行。

## 验收

- 上传及带文件创建均返回空 `task_id`，raw 可见，既有活动索引不变。
- 无索引、有知识草稿时，通过 CLI/API 返回可追溯引用；删除来源后不可检索该页面。
- 不接受未读取页面、虚构引用、未知页面 ID、越界分页或超长回复。
- 设置保存与重新加载保留检索模式；RAG 仅在显式选择时使用。
- 运行知识库回归测试、后端编译及前端 TypeScript 检查。
