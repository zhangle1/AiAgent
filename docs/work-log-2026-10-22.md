## 完成工作

### 1. 坤伴登录首页与登录恢复

- 未登录时默认显示平台 URL、用户名、密码登录页，登录成功后进入工作区并同步坤伴订阅模型。
- 首页与设置中的订阅入口共用登录链路，重新登录更新同一订阅，保留原有本地会话。
- 重启后恢复有效登录；服务端撤销或本地有效期届满后返回首页，保留地址和账号提示，密码不回填。
- 临时网络故障单独提示，不直接认定登录过期；补充桌面与窄屏布局验证。

### 2. 修复后端构建失败

- 定位运行时 `backed/data` 文件被 Web SDK 默认纳入项目内容的问题，动态文件变化导致构建复制阶段出现 `MSB3030`。
- 在项目默认项中排除 `data` 子树，避免运行数据进入构建及发布内容，保留必要静态资源。
- 修复后实际后端构建通过，0 错误，保留 17 条原有警告；新构建输出不包含运行数据目录。

### 3. 后台安装包发布管理

- 增加「设置 → 管理 → 坤伴客户端发布」，支持上传 Windows EXE、macOS DMG 或应用 ZIP，配置版本、平台、架构及更新说明。
- 增加上传进度、版本列表、刷新、下载和撤回；同平台、架构、版本不可覆盖，按数字版本排序。
- 服务端校验格式、大小和 SHA-256，通过不可变版本目录与原子目录文件发布，无需新增数据库表。
- 管理操作限定网页管理员；客户端版本及下载接口使用独立客户端登录会话，验证两类令牌不能混用。

### 4. 客户端版本检测与更新操作

- 从当前登录平台检查新版本，提供下载进度、更新说明和「打开安装包并退出」按钮；安装前再次检查发布状态和文件哈希。
- 切换平台 URL 或账号时取消旧请求，清空旧版本、下载状态和安装权限，从新平台重新检测；退出或登录过期同样失效。
- 下载使用固定同源接口并禁止重定向，不采用服务器返回的任意下载链接；更新操作限定主窗口 IPC。
- 增加统一版本脚本，同步工作区包版本、Cargo 版本及共享运行时版本，并补充 Windows / Mac 打包和双版本升级测试步骤。

### 5. 修复大安装包上传限制

- 实际 Next.js 联调发现默认 rewrite 在 10 MiB 处截断请求，会影响真实安装包上传。
- 为安装包上传增加专用 Node 流式转发，保留后端鉴权和包校验，不提高全部 API 的内存克隆上限。
- 经真实网页验证，16 MiB Windows 文件及 Mac DMG 可上传成功；部署说明补充反向代理大小和超时配置。
