# 知识工作区：固定根目录、Git 同步与项目目录

本轮是原型设计，未修改实际服务、appsettings 或知识数据，未连接远端。配套原型：[打开交互原型](knowledge-git-directory-prototype.html)。

## 1. 建议先实现什么

保留现有三栏工作台，顶部增加「Git 同步与设置」「服务器目录」。左侧保留资料、项目、人员；项目下面按具体项目展开其知识文件夹。Codex 后续直接读取所选的服务器查阅目录，当前项目代码仍是聊天工作目录。

首版采用一个团队知识 Git 工作区，里面按项目列目录；不要求每个项目都配置远程。远程链接、分支、Git 账号在弹窗配置，根目录由管理员在 appsettings 指定，页面只读显示。个人空间维持独立授权，不能把全部人员资料一起推入团队仓库。

“本地”指运行 AiAgent 后端的服务器磁盘；若浏览器在另一台电脑，不能直接把浏览器电脑的文件路径当成服务器目录。

## 3. 固定服务器根目录

建议新增配置，以下名称尚未实现：

```json
{
  "KnowledgeStorage": {
    "RootPath": "D:\\KnowledgeCenter"
  }
}
```

```text
D:\KnowledgeCenter\
  storage\knowledge_bases\           现有知识持久化存储
  workspaces\team-knowledge\         团队 Git 工作区
    resources\
    projects\project-101\
      需求文档\
      接口设计\
      会议纪要\
    projects\project-102\
    manifests\                        来源 ID、版本和内容哈希
  workspaces\users\<稳定用户ID>\       独立个人工作区
```

绝对根目录不依赖应用安装位置或当前工作目录；应用换版本后继续使用同一目录。未配置保留原行为，已配置但不可用应明确报错，不能悄悄落回空目录。各存储服务统一使用路径解析器，排查解析正文、语义产物、个人空间等是否存在独立路径推导。

切换根目录不是自动迁移：先核对现有持久化绝对／相对路径、停写复制并校验文件及哈希，调整数据库文件路径映射，验证原件、章节、摘要和个人资料读取后再切换。数据库和账号存储的迁移单独处理；固定知识目录并不等于搬迁整个应用后数据必然完整恢复。不改写真实 appsettings，不把它提交 Git。

## 4. Git 配置与推送

弹窗分为「远程配置」「变更与推送」：

1. 展示服务器工作区，只读；输入远程链接、选择已有 Git 账号和目标分支。
2. 检查连接及权限，保存仓库绑定。远程链接不包含密码或 Token；凭据沿用受保护账号服务，不能保存在 appsettings。
3. 首次初始化独立工作区 Git，检查已有 `.git` 与 origin，一旦不一致必须明确处理，不静默覆盖。
4. 按可见资源导出原件及已有可读正文、摘要和来源清单。刷新失败不发布半成品；首版延续此前确定的导出查阅副本方案，避免两套写入入口互相覆盖。
5. 展示变更文件、差异和目标分支，输入提交说明，生成可复核的变更快照；有提交权限的人工用户批准后执行，执行前复核指纹。
6. 推送返回脱敏命令输出、提交 ID 和成功时间。无变更但有待推送提交时支持只推送；提交成功、推送失败时保留本地提交供重试，不能重复制造提交。

工作区锁覆盖导出、提交和推送，防止刷新期间文件变化。远端领先或分叉时阻止直接推送，保留本地修改并提示单独处理同步；首版先提供检查远端，不引入自动拉取、自动合并、强推或重置更新。Git 托管地址沿用代码库可用协议与网络访问限制，命令使用参数列表。

仓库只跟踪导出清单允许的资料；数据库、凭据、向量索引、缓存与运行数据不加入 Git。不同读取权限的个人数据必须分仓／分工作区，子目录无法隔离仓库历史读取权限。

## 5. 项目目录

左树展示「项目 → 订单系统／财务平台／设备运维 → 需求／设计／会议等真实文件夹」。原型名称均为示例。展示当前身份有权访问的项目，使用稳定项目 ID 作为磁盘目录标识，项目改名仅改变显示名称。

建议明确绑定代码项目 ID 与知识项目根 URI，复用项目列表作为选择来源；现有 organization.project 文本只作为迁移候选，不能按同名自动建立授权。未绑定旧资料留在「未关联项目」并由有权限者确认归属。已有代码项目即使没有知识文件也可展示空态并提供添加目录入口。

首版文件夹与资源关联仍通过知识中心既有写入入口维护。物理导出路径保留稳定来源映射；不绕开知识资源记录直接扫描全部磁盘发布。目录浏览、导出和文件读取都同时验证项目权限、来源权限与根边界（包括链接／junction），不接受浏览器任意绝对路径。

## 6. 给聊天预留的轻量链路

聊天左下角知识库默认不选，树勾选确认后只发送 scope ID。后端按当前身份解析成 Codex 运行端可读的目录，按实际运行环境接入附加只读查阅范围；不能仅把服务器路径写进提示词就算完成。查阅团队 Git 工作区当前内容，记录导出版本、HEAD 基线和脏状态，引用实际读取的文件。不会在聊天发送时自动 pull 或 push。

页面分别展示「源资料是否待刷新」「工作区是否有变更」「远端是否检查／已同步」。Git 已同步不代表源资料已导出，HEAD 也不能代表未提交文件版本。后续 KnowAgent 接口读取模式复用同一 scope ID，不改变目录选择交互。

## 7. 实施拆分与验收

先做固定根目录及路径兼容，再做项目绑定与树展示，随后实现授权导出和知识 Git 适配器，最后连接聊天。新增后端请求同步补齐 DTO、前端 API 封装和 TypeScript 类型；新增实体字段先允许空值。业务与进程操作放 Service。

验证使用隔离临时目录、合成知识和本地临时 Git 远端：应用目录改变后仍能读取同一根目录；旧路径回退兼容；双用户／项目隔离；项目改名映射稳定；文件全量与哈希一致；推送失败重试、远端领先、路径越界、并发刷新、个人资料排除。正式实现前再补齐接口契约与专题开发文档。

## 8. 原型操作

可展开项目、切换文件夹，打开服务器目录配置示例。点击 Git 设置，输入示例 HTTPS 远程地址后保存，进入变更页模拟远端检查、冲突阻止和人工确认推送。所有操作仅影响当前页面内存，刷新恢复初始状态。
