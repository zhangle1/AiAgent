# 代码库中心重构设计

## 结论

代码库不应复刻文档知识库的“上传后全量向量索引”模式。代码天然有目录、文件、符号和引用关系；默认能力应是受控的实时读取与搜索，持久化索引只用于加速大仓库与跨文件分析。

## 页面信息架构

```text
代码库中心
├─ 搜索引擎
│  ├─ Live Grep（默认）：按需、只读、快速文本搜索
│  ├─ Symbol Index（可选）：类、方法、路由、导入关系缓存
│  └─ Call Graph（后续）：调用链与依赖图
└─ 已登记代码库
   └─ 代码库详情
      ├─ 文件
      ├─ 实时搜索
      ├─ 结构概览
      ├─ 索引缓存
      └─ 设置
```

## 文件页

- 左侧是懒加载目录树，只请求当前展开目录，行为接近 VS Code。
- 右侧是多标签文件预览；打开多个文件不会互相覆盖。
- 文件内容通过受控 API 按路径读取，支持行号、语言识别、文本搜索和定位到行。
- 前端不能直接读取磁盘；后端必须验证每个路径仍位于已登记代码库根目录内。

## 聊天时的自主读取策略

Loop 不新增固定节点，仍由工具调用驱动；新增工具而不是把全仓库送给模型。

1. 概览问题：读取根目录、README、构建清单、入口配置。
2. 错误问题：先用错误类型、文件名、组件名做 Live Grep，再读取少量命中上下文。
3. 符号问题：优先符号缓存；无缓存时实时搜索定义模式。
4. 调用链问题：从目标符号开始，逐层搜索导入/引用，达到预算即向用户说明证据范围。
5. 只有重复查询、跨文件诊断或大型仓库才使用持久化索引缓存。

## 实时任务

“建立代码索引”是后台任务，采用与知识库一致的进度模型：

- `queued -> scanning -> extracting -> saving -> ready/failed`
- 推送字段：当前文件、已扫描数、可索引数、已保存符号数、跳过数、错误摘要、百分比。
- UI 显示进度条和诊断抽屉，失败保留可读错误而不是直接抛出未处理异常。

## 后端接口边界

```text
GET  /api/v1/code-repositories/{name}/tree?path=
GET  /api/v1/code-repositories/{name}/file?path=
GET  /api/v1/code-repositories/{name}/search?q=
POST /api/v1/code-repositories/{name}/index
WS   /api/v1/code-repositories/{name}/progress
```

所有接口均复用代码库根目录白名单和相对路径校验；不允许任意绝对路径读文件，也不执行代码库中的命令。
