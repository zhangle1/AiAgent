C# 负责安全、任务、版本和业务编排；Python 负责受控解析、OCR、切块与检索。先使知识可引用、可追溯、可重建，再提升召回质量。

推荐分层

层负责边界
C# / .NET 9权限、上传验真、路径白名单、任务、版本、审计、聊天编排不在 Controller 解析文件或拼命令
Python Worker文档解析、OCR、Markdown、切块、Embedding、向量检索不信任浏览器路径，不提供 HTTP API
数据/索引文档、版本、chunk、job、向量索引只向前端暴露安全引用

目标数据流

受控上传 → 验真 / 指纹 → Markdown + manifest → Chunk + metadata
→ embedding / 向量索引 → 激活 IndexVersion
→ 结构化 + 关键词 + 向量检索 → Evidence → 带引用回答

阶段路线

P0 · 基线与安全（1 周）

统一 JSON 协议、错误码、取消和 request_id；保存 SHA-256 与配置快照；建立脱敏回归集。

验收：任务状态完整，失败可诊断，重复任务可复用。

P1 · 解析标准化与引用（2 周）

统一输出 document.md + manifest.json；仅低文本覆盖率页 OCR；chunk 保留页码、章节与来源定位。

验收：能预览解析结果；页码范围总结和语义问答均有引用。

P2 · Embedding 与混合检索（2 周）

配置化 Embedding；向量、关键词、结构化检索以 RRF 合并；权限在 C# 层过滤。

验收：Recall@5、引用及页码范围正确率可量化提升。

P3 · 生产可靠性（2–3 周）

持久化队列、重试、并发上限、观测、版本回滚和中间产物清理；UI 展示质量、任务、版本和引用。

验收：任一答案可追溯，故障可诊断且不影响激活版本。

最近两周行动

  1. 冻结 worker 协议、错误码与 manifest 格式。
  2. 实现 C# ParsingOrchestrator，持久化解析任务和质量。
  3. RAG worker 改为只消费中间产物，并导出稳定 chunk ID。
  4. 统一检索 Evidence 和引用 DTO。
  5. 前端增加解析状态、预览、版本、引用。
  6. 用脱敏回归集验证，再进入混合检索。
项目基础已具备：异步索引任务、索引版本、chunk 物化、语义/页码检索，以及独立的 RAG、解析、OCR Python worker。接下来关键是将它们收敛到同一中间产物与可观测任务链路。
