# 无限画布：独立会话之间的按需信息投递

> 状态：概念修正版 / 可交互原型
> 原型：[session-flow-prototype.html](./session-flow-prototype.html)

## 1. 设计结论

画布不是流程图，每个会话也不是等待调度的任务节点。每张会话卡片代表一个真实、完整、长期存在的聊天空间，它有自己的历史、输入框、运行状态、Skill、职责和权限，可以随时独立工作。

人工连线仅表示：用户允许从会话 A 向会话 B 投递一份选定的信息。它不表示依赖、顺序、阻塞关系或自动运行。

```text
会话 A 独立工作并形成结果
        ↓ 用户选择要交付的内容
      投递草稿（可预览、删减、补充）
        ↓ 沿人工连线发送
会话 B 收到一条“待检查投递”
        ↓ 用户决定
忽略 / 仅存为参考 / 带入输入框 / 带入并开始新一轮
```

核心原则：**会话独立，连线轻量，投递显式，执行另行确认。**

## 2. 概念边界

| 对象 | 是什么 | 不是什么 |
| --- | --- | --- |
| 会话卡片 | 完整聊天空间的画布入口 | DAG 节点、一次性任务 |
| 人工连线 | 可投递方向和默认收件人 | 依赖、运行顺序、触发器 |
| 投递 | 用户挑选并发送的信息副本 | 全量聊天历史共享 |
| 收件箱 | 目标会话内的待检查内容 | 自动注入 Prompt 的队列 |
| Skill / 职责 | 会话自身的长期工作设定 | 连线策略或全局角色 |

连线可以被删除而不影响两端会话；任意会话失败、暂停或归档，也不应改变其他会话的运行状态。

## 3. 会话卡片

卡片强调“正在聊什么”和“我可以继续聊”，弱化输入端口、输出端口与流程状态。

卡片展示：

- 会话标题、最近一条消息和更新时间；
- 当前是否正在回复，仅描述本会话自身状态；
- 绑定的角色和最多两个 Skill 标签；
- 待检查投递数量；
- “打开会话”和“投递”快捷操作。

卡片不展示“输入未齐”“等待上游”“阻塞下游”“运行槽位”等编排术语。

## 4. 人工连线

### 4.1 建立关系

用户从一张会话卡片拖线到另一张，确认方向和关系名称，例如“方案交给实现”。保存后只产生一个快捷投递通道。

默认配置只有：

- 来源会话；
- 目标会话；
- 关系名称；
- 默认携带内容类型（结论、消息片段、文件引用）；
- 是否允许发送方建议接收后启动新一轮。

首期不提供“完成后自动触发”“失败时阻塞”“等待全部上游”等配置。

### 4.2 视觉语义

连线使用细虚线和纸飞机图标，表达“邮路”而非“管道”。线上的标签只展示“可投递”“1 份待检查”或最近送达时间，不播放持续流动动画。

## 5. 创建投递

用户可以从消息菜单、会话卡片或连线发起投递：

1. 选择一条或多条消息、AI 最终答复、结论摘要及文件引用；
2. 系统生成投递草稿，用户可删减、改写摘要和补充给接收方的说明；
3. 选择目标会话；已有连线目标优先展示，但也可新建关系；
4. 可勾选“建议接收后开始新一轮”，这只是建议，不会自动执行；
5. 用户确认发送，目标会话待检查计数增加。

投递只复制显式选中的内容，不复制完整历史、系统指令、工具原始输出、物理文件路径或密钥。

## 6. 接收与检查

目标会话收到投递后保持原状态，不打断正在进行的回复。会话内显示收件卡片，用户可以：

- **仅收下**：保存为该会话的参考资料，不发消息；
- **带入输入框**：组合为可编辑草稿，等待用户继续输入；
- **带入并开始新一轮**：明确确认后创建目标会话的新用户消息；
- **编辑后接收**：先删减敏感或无关内容；
- **忽略**：不进入上下文，保留最小审计记录。

接收方使用哪个 Skill、是否执行、何时执行，都由目标会话自身决定。发送方无权远程运行目标会话。

## 7. Skill、职责与约束

这些配置挂在会话上，在会话检查器中独立编辑：

| 配置 | 示例 | 作用 |
| --- | --- | --- |
| 角色 | 前端工程师 | 解释会话长期定位 |
| 职责 | 实现并验证授权范围内的前端改动 | 规定该会话主要负责什么 |
| Skills | Next.js、测试驱动 | 为后续轮次提供能力说明 |
| 约束 | 不修改后端；不读取密钥 | 约束可采取的行动 |
| 完成定义 | 测试通过并给出变更摘要 | 辅助判断本轮是否完成 |

收到的投递始终是外部参考信息，不能覆盖会话的系统安全策略、职责、Skill 指令和工具权限。若投递建议与会话约束冲突，接收界面应明确提示，由用户处理。

## 8. 推荐数据模型

```text
CanvasSessionProfile
  session_id, role, responsibilities, constraints,
  completion_definition, version

CanvasSessionSkill
  session_id, skill_key, requested_version, resolved_version,
  config_json, enabled

CanvasDeliveryLink
  id, source_session_id, target_session_id, label,
  default_content_types, allow_run_suggestion

CanvasDelivery
  id, link_id, source_session_id, target_session_id,
  sender_note, selected_content_json, artifact_refs_json,
  run_suggested, status, created_by, created_at

CanvasDeliveryReceipt
  delivery_id, decision, edited_content_json,
  target_message_id, decided_by, decided_at
```

投递状态保持简单：

```text
draft → sent → reviewing → accepted
                         ↘ ignored
```

`accepted` 只代表内容被接收；是否产生 `target_message_id` 取决于用户选择“仅收下”还是“开始新一轮”。

## 9. API 草案

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET/PUT` | `/api/v1/canvas/sessions/{id}/profile` | 会话职责与约束 |
| `GET/PUT` | `/api/v1/canvas/sessions/{id}/skills` | 会话 Skill 绑定 |
| `POST/DELETE` | `/api/v1/canvas/delivery-links` | 建立或删除人工投递关系 |
| `POST` | `/api/v1/canvas/deliveries/preview` | 生成脱敏投递草稿 |
| `POST` | `/api/v1/canvas/deliveries` | 明确发送投递 |
| `GET` | `/api/v1/chat/sessions/{id}/inbox` | 查询待检查投递 |
| `POST` | `/api/v1/canvas/deliveries/{id}/accept` | 仅收下或生成输入草稿 |
| `POST` | `/api/v1/canvas/deliveries/{id}/start-run` | 确认后创建新消息并执行 |
| `POST` | `/api/v1/canvas/deliveries/{id}/ignore` | 忽略投递 |

服务端必须验证两端会话归属、资源引用权限和内容大小；发送方的 `run_suggested` 不能绕过接收方确认。

## 10. 分期建议

### 第一阶段

- 人工建立单向连线；
- 手动选择内容并投递；
- 目标会话检查、编辑、接收或忽略；
- 会话级 Skill、职责与约束展示和编辑；
- 完整记录投递来源与接收决定。

### 第二阶段

- 一次投递给多个独立会话；
- 常用投递模板和内容摘要；
- 冲突、重复、过期内容提示；
- 从投递结果一键回复原会话。

### 暂不进入

- DAG 自动调度；
- 上游完成后无确认地启动下游；
- 会话间共享全部历史；
- 发送方强制指定接收方 Skill 或工具；
- 因某个会话失败而阻塞其他会话。

## 11. 验收标准

1. 不看说明时，用户也不会把连线理解为执行顺序；
2. 删除连线、暂停一端或忽略投递均不影响另一端独立工作；
3. 任何投递在进入目标 Prompt 前都可见、可编辑、可拒绝；
4. 未经接收方确认，投递不会触发目标会话执行；
5. Skill、职责和约束明显属于会话，而非流程节点；
6. 可以追溯“谁把哪些内容投给哪个会话，以及对方如何处理”。
