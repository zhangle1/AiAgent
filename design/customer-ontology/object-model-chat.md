# 项目本体模型：从代码追到业务记录

**设计稿 · 待评审**　[打开离线交互原型](./object-model-chat.prototype.html)

用户在 MES 项目里问「为什么工单 WO-1024 还不能发料」。理想的回答应能指到代码中的发料条件，交代工单需要多少、ERP 订单处于什么状态、库存接口返回多少，以及哪条证据足以解释这次拦截。配置人员负责把企业系统映射为业务对象。聊天用户只需选择「生产履约」模型，不必知道表名或填写数据库密码。

## 在原型里试一遍

| 场景 | 怎么点 | 应当看到什么 |
| --- | --- | --- |
| 追一张工单 | 点左侧示例问题 → 保持三个对象勾选 → 应用到聊天 → 发送 | 模拟 MES 需求 12 件、ERP 订单已审核、库存接口可用 8 件。缺 4 件的判断同时引用工单与库存记录 |
| 缩小范围 | 聊天输入区点模型按钮 → 取消「可用库存」→ 应用 → 再问 WO-1024 | 仍可取得工单和销售订单，回答说明判断缺料还缺哪项证据 |
| 排查连接故障 | 数据连接 → ERP 库存接口 → 配置与测试 → 模拟「执行器离线」→ 测试连接 → 保存 → 再问 | 其他来源仍有结果。故障来源显示未取到记录。把结果改回通过，测试并保存后即可重试 |
| 自己定义 | 新建模型 → 数据连接 → 新建连接，填演示 URL、账号和密码或令牌 → 测试并保存 → 业务对象 → 定义对象 → 勾选字段 → 聊天挂载 | 新模型可单独使用。只有映射且勾选的字段出现在预览和模拟结果里 |
| 项目或版本变化 | 挂载后编辑对象，再查看输入区；或把页首项目切成「未选择项目」 | 既有挂载固定到原版本，可显式重新应用。离开项目清空会话挂载，面板给出项目选择入口 |

原型双击 HTML 即可运行，无需启动产品。页面内的代码规则、数据、网络状态和连接测试均为模拟；表和字段来自三个固定样例，关系按示例键匹配。刷新还原初始状态。可直接输入 WO-1024、SO-2048 或 MAT-17 验证不同的查询起点。

## 产品入口与配置顺序

保留截图中的右侧「本体模型」页签，与聊天并排。未选项目时直接给出项目选择入口；已有会话切换项目沿用现有新聊天确认流程。桌面端在右侧编辑，窄屏下使用同一组面板。关闭配置面板不会解除已应用的聊天挂载。

1. **数据连接**。先选「数据库」或「接口组件」，再选择具体驱动或组件。数据库表单接受没有凭据的 URL，也可沿用主机、端口、库名分项输入；解析后回显目标库供核对。账号与密码独立填写。ERP 可以是订单数据库，也可以是库存 HTTP 服务。接口表单改为基础 URL、认证方式、令牌和已登记的操作。数据库与 HTTP 配置各自验证。
2. **测试连接**。由实际将要查询的执行器发起。依次展示可达性、认证、元数据或指定操作的只读探测，记录时间、环境以及失败步骤。保存草稿允许暂时离线；只有最近一次通过的匹配配置才能执行数据读取。更改地址、账号、凭据、环境或操作范围后，旧验证失效。读表目录成功仍需单独校验对象的读取权限。
3. **业务对象**。命名对象，选连接，从已授权的表、视图或接口操作选择来源，指定查询键，映射业务字段、类型、单位和显示权限。保留代码实体或方法的可选线索。关系编辑器明确选择两端对象、连接键、方向和基数，预览一条示例并由配置人确认。原型只演示已知模板的映射。生产版不得把同名字段自动发布为关系。
4. **聊天挂载**。输入区增加「本体模型」，就地选择一份模型及其中部分对象，预览实际进入下一轮的内容。应用后显示模型名和对象数，允许随时移除。查看、编辑模型与应用到聊天是两个独立动作。首期每个会话同时挂载一份模型，一份可跨多个来源，避免混淆不同模型里的同名对象。

## 对象、连接与关系如何分工

| 概念 | 关键内容 | 生产履约示例 |
| --- | --- | --- |
| 连接 | 所有者、项目、环境、执行器、驱动、目标、凭据引用、配置版本、验证结果 | MES 只读数据库、ERP 订单数据库、ERP 库存 HTTP 组件 |
| 对象 | 稳定 ID、业务名、查询键、允许的查询、字段映射、来源引用、代码线索 | 生产工单，按工单号读取销售单号、物料号和需求量 |
| 对象关系 | 两端对象和字段、方向、基数、适用条件 | 工单.销售单号 → 销售订单.销售单号；工单.物料号 → 库存.物料号 |
| 本体模型 | 同一项目中一组有业务意义的对象和关系，有独立版本 | 生产履约 v1；同一订单连接也可供「销售订单核对」模型复用 |
| 聊天挂载 | 模型与版本、选中的对象、可用关系、各连接版本、授权范围 | 本轮只选工单和销售订单，库存对象及指向它的关系都省略 |

三个样例的数据粒度分别为一张工单、一张销售单和一种物料在**单一示例仓**的可用库存。正式映射通常还需组织、仓库、计量单位、批次或行号。键不全时先补问；多仓库存未经换算或指定范围不能直接与工单需求比较。跨库关系分两次限量查询，不要求 MES 与 ERP 可以互相联库。

## 查代码时如何自动查数

**发送时。** 前端在原有聊天请求中附加可空的模型引用、版本与对象 ID。服务端按登录身份、项目和会话重新解析，生成有界的对象说明、字段语义、关系、查询能力以及可选的代码定位线索。消息正文保留用户原话。把模型 ID、对象与连接版本固定到本轮，重试沿用同一快照。未选模型继续走现有聊天链路。

**推理时。** Agent 先用原有代码检索定位发料校验逻辑。若问题仅涉及代码，至此即可回答。若需要实际工单数据，通过宿主提供的只读工具调用，例如下表。模型不能仅凭上下文文本取得连接。服务端校验每次调用，用已登记模板和类型化参数查询，执行器从凭据存储取密。

| 动作（拟议） | 输入示例 | 返回给聊天的内容 |
| --- | --- | --- |
| 描述对象 | 生产工单 | 已授权字段、类型、查询键、可沿用的关系 |
| 查询对象 | 生产工单，工单号 = WO-1024 | 销售单号 SO-2048、物料 MAT-17、需求 12 件 |
| 沿关系读取 | 本轮取得的销售单号或物料号、关系 ID | 订单已审核；库存接口返回可用 8 件。两次查询分别记录来源 |

**回答时。** 分别标明代码依据和本次读取的数据，显示对象、环境、读取时间、行数和可追溯的运行 ID。ERP 状态只是相关背景，本例的拦截条件来自数量比较。无匹配记录、权限拒绝、超时、桥接离线要分别标示；已成功来源的记录仍可引用。真实系统会随时间变化，重新查询产生新证据并标时间。普通重放使用已有结果。

## 与现有代码衔接

当前右侧入口由 `front/components/chat/KnowledgeChatHome.tsx` 和 `ChatInspectorPanel.tsx` 调度，`front/components/ontology/OntologyWorkbench.tsx` 可编辑单连接与流程图，并把脱敏上下文插入草稿。`backed/Services/Ontology/OntologyStore.cs` 已按用户和项目存储加密配置、校验版本和流程 DAG。现有流程表达执行依赖，另建对象关系结构表达业务关联，允许业务关系回指；运行时查询限制深度并去重。

| 改动位置 | 建议增量 |
| --- | --- |
| 项目本体存储 | 保留旧模型 ID、单连接、图和 v1 API。首次编辑新版时在同一事务或原子迁移内创建稳定连接引用并转移加密凭据；可重复执行。旧图保留，旧模型初始无业务对象，待用户显式映射。旧版连接编辑与新版引用共用版本校验，避免两份密码分叉 |
| 本体 API | 在现有项目前缀下新增连接管理、测试、受限元数据目录、模型对象与关系保存、挂载解析。保存携带预期版本，冲突返回 409 并保留用户草稿。连接读取只返回凭据已设置标志 |
| 聊天与执行器 | 新增独立工具适配器，通过服务端签发的本轮句柄描述或查询对象。HTTP 与 WebSocket 使用相同解析器。Codex 通过受支持的宿主工具桥接，保留原生线程、停止和恢复。执行器不可用时明确显示「仅对象说明」 |
| 安全与可见性 | 沿用本人 + 项目边界，连接与查询分别授权。数据库侧使用只读账号、参数化模板、字段/行级限制、超时和行数上限。接口组件只开放登记的只读操作，绑定受管理地址和凭据；禁用任意路径转发及跨目标重定向。按环境登记允许的内网目标。原始凭据、连接串和令牌不进模型、浏览器持久化、日志或回答 |

## 首期实施与验收顺序

1. **跑通一种数据库。** 优先用 SQL Server 的测试库实现连接验证、元数据读取、字段映射和按主键读一条工单；同一驱动先覆盖一个 MES 库和一个 ERP 库。原型的 PostgreSQL 模板用于验证多驱动表单，真实驱动在对应阶段接入。断开执行器或撤销读取权限后应得到独立的错误状态。
2. **让聊天拿到第一条真实证据。** 验收未挂载、只挂一个对象、挂载两对象、编辑后重试、项目切换及权限撤销。用测试代码和可控数据验证来源、字段过滤、部分失败、取消与审计。首期自动查询限定为有键值的只读查找。
3. **加入首个 ERP 接口组件。** 选择一个实际 ERP 厂商的只读操作，实现其认证、参数与响应映射；先在测试环境走通「工单 → 订单 → 库存」。接口限流、键缺失或多个匹配时给出明确结果。多组织授权、批量分析和写操作另行设计。
