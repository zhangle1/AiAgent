# 本地能力工作台：验证后，一次填入 AI 上下文

交互原型：[agent-workbench.html](agent-workbench.html)。本版取代旧版以交付风险编排为中心的交互。总体本体领域设计保留在 solution.md；prototype.html 为早期设计，不作为本版验收依据。

## 核心需求

用户已经在本地掌握数据库、ERP 接口和工具，希望配置一次，直观看到是否能用，再把正确的客户、项目、环境、工具与数据范围方便地提供给 AiAgent、Codex CLI 或其他 Agent。第一阶段的重点是“本地能力资产 + 验证证据 + Prompt 上下文包”。本体模型作为探测结果的长期沉淀。

保留聊天与可视化节点链：本地工具 → 数据连接 → 探测范围 → AI 上下文。节点用于查看配置、验证层次及复用入口。窄项目资料面板里布局自动折行，避免画布被固定宽度挤出视区。

## Codex CLI 兼容边界

见 [Codex 兼容要求](codex-compatibility.md)，实施时必须保持原有 CLI 能力。

## 用户流程与原型操作

1. 选择客户、项目和 dev/test/prod。配置数据库类型、主机、端口、数据库、账号及凭据引用。
2. 点击“模拟分层测试”，分别显示工具、网络、认证、数据库访问、元数据读取。支持工具缺失、网络失败、认证失败、元数据权限不足场景；失败后的层次标为未执行。
3. 选择表或视图及探测目标，勾选验证摘要和结构快照，选择本地 CLI 或远程 Agent 桥接。
4. 生成 Prompt 预览。检查客户、环境、执行位置、连接引用、工具操作、范围、只读限制及证据时间。
5. 一键填入聊天草稿，用户再发送；或复制 Prompt、下载 Markdown 上下文文件，在 CLI 中显式附加。重复填入替换已有上下文，避免无限叠加。
6. 正式版由 Agent 返回表、字段、关系候选和来源，审查差异后保存模型版本。发现与执行结果可反向回到聊天。

本页使用合成数据，不访问真实数据库、不调用模型、不保存凭据。刷新重置。下载仅导出上下文文本。所有测试通过也只代表模拟场景通过。

## 实施顺序和验收

第一步完成连接配置、本地凭据库、一种数据库驱动的真实分层测试与证据存储。第二步接上下文选择器到现有聊天“+ → 本体模型 / 本地能力”，发送时保存上下文快照并传给既有 Agent。第三步接本地 CLI 适配器与远程桥接，同一 connection_ref 解析策略。第四步让探测结果产生模型提案并审查保存。

正式验收：同一连接经页面验证后可被聊天和 CLI 引用；测试区分工具缺失、网络、认证、元数据权限；连接或环境改变后旧证据不能继续执行；未安装适配器明确提示；失败与取消不伪造成功；跨客户、跨用户引用拒绝；Prompt 与日志无密码；只读账号无法执行写操作；导出上下文与聊天快照来源一致。

本段描述早期模拟原型；首轮已实现范围以 phase-1.md 为准。真实驱动与 CLI 适配器仍待后续实现。
