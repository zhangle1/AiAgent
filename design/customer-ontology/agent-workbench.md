# 本地能力工作台：验证后，一次填入 AI 上下文

交互原型：[agent-workbench.html](agent-workbench.html)。本版取代旧版以交付风险编排为中心的交互。总体本体领域设计保留在 solution.md；prototype.html 为早期设计，不作为本版验收依据。

## 核心需求

用户已经在本地掌握数据库、ERP 接口和工具，希望配置一次，直观看到是否能用，再把正确的客户、项目、环境、工具与数据范围方便地提供给 AiAgent、Codex CLI 或其他 Agent。第一阶段的重点是“本地能力资产 + 验证证据 + Prompt 上下文包”。本体模型作为探测结果的长期沉淀。

保留聊天与可视化节点链：本地工具 → 数据连接 → 探测范围 → AI 上下文。节点用于查看配置、验证层次及复用入口。窄项目资料面板里布局自动折行，避免画布被固定宽度挤出视区。

## 用户流程与原型操作

1. 选择客户、项目和 dev/test/prod。配置数据库类型、主机、端口、数据库、账号及凭据引用。
2. 点击“模拟分层测试”，分别显示工具、网络、认证、数据库访问、元数据读取。支持工具缺失、网络失败、认证失败、元数据权限不足场景；失败后的层次标为未执行。
3. 选择表或视图及探测目标，勾选验证摘要和结构快照，选择本地 CLI 或远程 Agent 桥接。
4. 生成 Prompt 预览。检查客户、环境、执行位置、连接引用、工具操作、范围、只读限制及证据时间。
5. 一键填入聊天草稿，用户再发送；或复制 Prompt、下载 Markdown 上下文文件，在 CLI 中显式附加。重复填入替换已有上下文，避免无限叠加。
6. 正式版由 Agent 返回表、字段、关系候选和来源，审查差异后保存模型版本。发现与执行结果可反向回到聊天。

本页使用合成数据，不访问真实数据库、不调用模型、不保存凭据。刷新重置。下载仅导出上下文文本。所有测试通过也只代表模拟场景通过。

## 上下文包

上下文必须包含客户 / 项目 ID、环境、连接版本、执行器位置、connection_ref、工具及版本、操作白名单、探测范围、任务目标及运行限制。可选附带脱敏的验证摘要与元数据快照；证据保存 checked_at、配置指纹、run_id、来源、有效期与所验证的能力。结构快照附带来源连接和采集时间。

密码、Token、原始连接串、凭据库地址不进入 Prompt、Markdown 导出、聊天历史或模型文件。主机和账号也按字段策略脱敏；原型中的地址与账号为合成示例。正式版用户配置密码时仅写入本地凭据库，平台保存不透明引用。Agent 使用 connection_ref 调用服务，执行器即时解析凭据。

连接验证通过、元数据可读、业务查询可读和 Agent 可调用分别记录。TCP 成功不能代表认证或权限成功。证据过期、配置变化、工具升级、权限撤销、切换环境时使引用失效；旧运行快照仍可追溯。导出的文件是不可撤回的历史文本，执行时仍须服务端重新授权。

## 本地与远程执行

本地 CLI：通过工具适配器 / 插件获取当前用户授权的能力清单、上下文和连接引用，调用本机执行器。先检查工具存在，再执行固定预制操作。导入 Markdown 只是填充信息，不会安装插件或自动赋予数据库访问能力。

远程 AiAgent：通过认证的本地执行器桥接，向指定执行器发送类型化调用，不将客户端 localhost 解释为服务器地址。执行器离线、桥接未授权或能力缺失时返回明确状态。禁止模型自行拼接 shell 或从 Prompt 读取密码直连。

建议统一服务协议（待实施，并非现有 API）：

| 操作 | 输入 | 输出 |
| --- | --- | --- |
| capabilities.list | 客户、项目、环境 | 已授权工具与连接摘要 |
| connections.test | connection_ref、预期配置版本 | 分层状态、诊断码、run_id、证据时间 |
| context.resolve | 引用、版本、范围、勾选项 | 脱敏 Prompt 与结构化快照、指纹 |
| tools.invoke | 工具 ID、连接引用、类型化参数 | 结果、来源、run_id、审计记录 |
| model.propose | 元数据证据、目标模型版本 | 字段及关系差异草稿 |

所有操作由当前登录身份验证客户 / 项目访问权。调用工具时重查引用版本、范围和权限，不信任 Prompt 声称的授权。数据库对象名采用允许列表及驱动安全引用，参数化查询；超时、结果上限、取消和只读数据库账号由执行层落实。prod 默认只读，DDL/DML 不进入首期工具。

## 数据模型与预制工具

- Capability：工具 ID、类型、版本、执行器、输入输出 schema、允许操作。
- ConnectionProfile：客户 / 项目 / 环境、驱动、非敏感配置、不透明 credential_ref、版本。
- ValidationRun：连接及工具版本、配置指纹、分层状态、脱敏错误、时间、运行位置。
- ContextBundle：所选引用、固定版本、范围、任务、可选证据与快照、渲染文本和内容哈希。
- ModelProposal：目标模型版本、来源证据、对象 / 字段 / 关系补丁、审查状态。

首批预制工具：test_connection、list_tables、describe_table。后续接 ERP HTTP 接口测试、接口 schema 探测、限量只读查询。每种工具使用专用配置 schema 和独立校验器，不把数据库账号表单直接套在所有工具上。

## 实施顺序和验收

第一步完成连接配置、本地凭据库、一种数据库驱动的真实分层测试与证据存储。第二步接上下文选择器到现有聊天“+ → 本体模型 / 本地能力”，发送时保存上下文快照并传给既有 Agent。第三步接本地 CLI 适配器与远程桥接，同一 connection_ref 解析策略。第四步让探测结果产生模型提案并审查保存。

正式验收：同一连接经页面验证后可被聊天和 CLI 引用；测试区分工具缺失、网络、认证、元数据权限；连接或环境改变后旧证据不能继续执行；未安装适配器明确提示；失败与取消不伪造成功；跨客户、跨用户引用拒绝；Prompt 与日志无密码；只读账号无法执行写操作；导出上下文与聊天快照来源一致。

当前交付仅更新交互原型与方案，真实驱动、凭据服务、聊天注入接口和 CLI 适配器尚待实施。
