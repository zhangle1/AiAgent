# AiAgent 任务面板设计

## 目标

任务面板位于左侧“聊天”下方，以项目为组织单位，聚合用户自己创建的任务与已配置 Gitee 账户可读取的 Open Issue。每张任务卡的一键处理会打开对应项目的新聊天会话，并把任务内容写入浏览器本地的单次交接数据；聊天页读取后预填输入框，不把令牌、浏览器路径或未验证外部内容当作系统指令。

## 信息架构

```text
任务面板
├── 项目筛选（全部 / 单项目）
├── 新建任务（项目、标题、说明）
├── 同步 Gitee（仅当前项目）
└── 任务卡
    ├── 来源：本地 / Gitee
    ├── 状态、负责人、原始链接
    └── 处理 → /chat?project={id}&template_handoff={nonce}
```

## 安全与数据边界

- Gitee 访问令牌复用 `ai_git_account` 中数据保护加密的令牌；从不返回给浏览器或写入任务表。
- 同步调用 Gitee 的用户 Issue 接口，只保存任务展示与交接所需字段。
- 外部 Issue 的正文被视为不可信任务材料。进入聊天时仅作为用户消息内容，不改变工具权限、模型配置或 Codex sandbox。
- 任务归属到创建者与代码项目；后端再次验证项目存在。

## 已实现 API

| 操作 | API |
| --- | --- |
| 列表 | `GET /api/v1/project-tasks` |
| 新建 | `POST /api/v1/project-tasks` |
| 同步 | `POST /api/v1/project-tasks/sync/gitee?projectId={id}` |

当前同步策略为：用已启用的 Gitee 账户同步其开放 Issue 到用户选定项目，使用 Gitee Issue ID 去重更新。后续可基于仓库远端地址增加“只同步该项目仓库”的精确过滤。
